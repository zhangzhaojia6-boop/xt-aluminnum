## 2. 一句话架构

系统是“鑫泰铝业 数据中枢”，不是 MES 系统本身。它的职责是把外部 MES、人工填报、能耗、日报、异常、权限、AI 汇报等数据接到一起，然后在管理端和手机端展示。

整体链路可以理解为：

浏览器页面 → 前端 Vue 应用 → 后端 FastAPI 接口 → 本地业务数据库 → 外部 MES SQL Server 只读同步 → 报表、看板、AI、钉钉。

## 3. 产品边界

系统正式名称是：

`鑫泰铝业 数据中枢`

必须注意：

- 本系统不能叫 MES。
- MES 只能作为外部生产系统、数据源、同步适配器来描述。
- 前端页面不能直接连接 MES 数据库，必须通过后端接口读取整理后的业务数据。
- MES 数据应作为生产、卷材、工艺、在制、包装产量等主数据。
- 人工填报应作为补录、纠偏、异常说明、内勤专项和 MES 缺字段补充。

## 4. 后端主结构

主要接口模块包括：

## 8. 业务时间口径

生产业务日：

- 开始时间：早上 `07:30`。
- 结束时间：次日早上 `07:30`。
- 如果当前时间早于 `07:30`，系统会把业务日算到前一天。

内勤或一日汇总类口径：

- 开始时间：早上 `09:30`。
- 如果当前时间早于 `09:30`，系统会把业务日算到前一天。
- 迟报参考节点是 `10:00`。

这个口径很关键。日报、今日、生产分析、MES 在制料、调度大屏如果没有统一使用这个口径，就会出现“同一天数字对不上”的问题。

## 10. 数据库分组理解

本地业务数据库大致分为这些数据区：

- MES 投影数据：随行卡、卷材快照、工序记录、库存、物料、在制、同步日志。
- 人工填报数据：班次填报、手机端报表、工单录入、字段补录。
- 能耗数据：机台能耗、每日对比、未来物联网同步数据。
- 基础资料：车间、班组、机台、用户、角色、别名。
- 报表数据：日报、生产分析、异常、导出。
- 智能体数据：AI 摘要、钉钉通知、主动汇报、治理留档。

## 11. MES 数据链路

当前目标链路是 SQL Server 只读直连。

链路理解：

外部 MES SQL Server → 只读适配器 → 同步服务 → 本地 `mes_*` 投影表 → 后端接口 → 前端页面。

重要原则：

- 外部 MES 数据库只读，不写入。
- 前端不直接查外部 MES。
- 后端同步后，管理端读取本地投影表。
- MES 同步健康状态会进入 `/readyz`。

当前线上 `/readyz` 已显示：

- 数据库正常。
- 管道正常。
- MES 同步正常。
- MES 状态新鲜。
- 适配器是 `sqlserver`。

## 12. 能耗链路

当前能耗由本地能耗数据和填报数据支撑。

已知边界：

- 机台能耗表是重要成本报表来源。
- 未来物联网能耗数据库会作为独立外部数据源接入。
- 吨耗计算需要统一使用业务日和统一产量分母。
- 能耗页必须区分“已采集能耗”和“暂缺数据”，不能把缺失误显示成真实 0。

## 13. 日报和看板核心口径

日报与看板需要同时区分三类数据：

- MES 主数据：生产、工艺、卷材、在制、包装产量。
- 人工填报数据：补录、异常、内勤专项、无一体机车间补充。
- 算法数据：成品率、废料、吨耗、统计指标。

前端应避免把这三类混在一起，否则用户会误以为数字来自同一个来源。
