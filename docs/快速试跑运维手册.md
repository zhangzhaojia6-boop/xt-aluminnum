# 快速试跑运维手册

## 一键试跑

正式试跑前先在云主机执行：

```bash
./scripts/deploy_trial.sh
./scripts/check_trial_stack.sh
TRIAL_BASE_URL=https://你的域名 ./scripts/deploy_trial.sh
```

默认检查 `https://localhost`。如需只看动作不执行：

```bash
./scripts/deploy_trial.sh --dry-run
./scripts/check_trial_stack.sh --dry-run
./scripts/backup_db.sh --dry-run
./scripts/restore_db.sh --dry-run backups/你的备份文件.dump
```

## 检查基础文件与运行环境

试跑前必须确认：compose 文件存在、`.env` 已准备、docker/compose/daemon 可用。

- `curl` 可用。
- `docker` 命令存在。
- `docker-compose.yml` 存在。
- `docker-compose.prod.yml` 存在。
- `docker compose` 可用。
- `docker daemon` 正在运行。
- `db / backend / nginx` 均已启动。
- `APP_ENV` 使用生产或试跑配置。
- `.env` 里不能保留 `CHANGE_ME`。
- `SECRET_KEY` 长度需 >= 32。
- `INIT_ADMIN_PASSWORD` 长度需 >= 12。
- `ssl/cert.pem` 与 `ssl/key.pem` 已准备。
- `READY_RETRIES` 与 `READY_INTERVAL_SECONDS` 按现场网络调整。
- `/` 首页可访问，返回页面中应包含 `id="app"`。
- `/entry` 可访问。
- `/manage/factory` 可访问。
- `/api/v1/auth/login` 入口可达；只检查不为 404、000 或 5xx，5xx 视为服务异常，不校验登录结果。
- 单次请求超时 `15` 秒。

## 外部连接就绪检查

```bash
cd backend
python scripts/check_statistics_module_ready.py --env-template
python scripts/check_statistics_module_ready.py --json --check-live-aggregation --check-app-connection-live
docker compose exec -T backend python scripts/check_statistics_module_ready.py
```

不要把包含密钥的 `.env` 提交到 Git。
不要把上述真实值写入文档或提交到 GitHub。

外部连接试跑变量：

- `MES_ADAPTER=mvc`
- `DINGTALK_ENABLED=true`
- `APP_CONNECTION_PUSH_MODE=enabled`

## 备份与恢复

```bash
./scripts/backup_db.sh
./scripts/restore_db.sh backups/你的备份文件.dump
```

- 支持自定义备份路径，并自动创建对应目录。
- 备份产物为空时直接失败。
- 备份文件不存在或 `db` 未运行时直接失败。
- 备份完成后会立即做一次备份格式可读性校验。
- 恢复前检查备份文件不存在/为空。
- 恢复前做备份格式可读性校验。
- 自动清理容器内临时备份文件。
- 自动清理容器内临时恢复文件。
- 恢复目标库不能与生产库同名。
- 恢复目标库不能使用 `postgres/template0/template1`。

## 一键上线闸门

```bash
./scripts/go_live_gate.sh
./scripts/go_live_gate.sh --skip-ai --skip-role-smoke --require-external
```

通过时输出 `hard_gate_passed=true`。若失败会自动输出关键容器状态与后端/nginx日志片段。若 `/readyz` 未通过，会输出最后一次 readyz 响应。容器状态和后端/nginx 日志由 `deploy_trial.sh` 包裹失败时输出。
