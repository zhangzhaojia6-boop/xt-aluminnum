# 快速试跑运维手册

## 试跑入口

- 部署：`./scripts/deploy_trial.sh`
- 健康检查：`./scripts/check_trial_stack.sh`
- 默认检查 `https://localhost`
- 指定域名：`TRIAL_BASE_URL=https://你的域名 ./scripts/deploy_trial.sh`
- 备份：`./scripts/backup_db.sh`
- 一键上线闸门：`./scripts/go_live_gate.sh`

## 运行前检查

检查基础文件与运行环境：

- `curl` 可用。
- `docker` 命令存在。
- `docker compose` 可用，且 docker daemon 正常。
- `docker-compose.yml`、`docker-compose.prod.yml` 存在。
- `.env` 已准备。
- compose 文件存在、`.env` 已准备、docker/compose/daemon 可用。
- `APP_ENV` 不能保留测试值。
- `SECRET_KEY` 长度需 >= 32，不能是 `CHANGE_ME`。
- `INIT_ADMIN_PASSWORD` 长度需 >= 12，不能是 `CHANGE_ME`。
- `ssl/cert.pem` 和 `ssl/key.pem` 已准备。
- `READY_RETRIES`、`READY_INTERVAL_SECONDS` 可按现场网络情况调整。
- `db / backend / nginx` 必须运行。

## 健康检查

- `/` 首页可访问，页面里应有 `id="app"`。
- `/entry` 可访问。
- `/manage/factory` 可访问。
- `/api/v1/auth/login` 入口可达。
- 登录接口只验证入口，不校验登录结果。
- 返回码不为 404、000 或 5xx；5xx 代表服务异常。
- 单次请求超时 `15` 秒。
- `hard_gate_passed=true` 才能继续试跑。
- 若失败会自动输出关键容器状态与后端/nginx日志片段。
- 若 `/readyz` 未通过，会输出最后一次 readyz 响应。
- 容器状态和后端/nginx 日志由 `deploy_trial.sh` 包裹失败时输出。

## 备份与恢复

- 备份文件不存在或 `db` 未运行时，先停止恢复动作。
- 支持自定义备份路径，脚本会自动创建对应目录。
- 备份产物为空、备份文件不存在/为空都视为失败。
- 备份格式可读性校验必须通过。
- 备份完成后会立即做一次备份格式可读性校验。
- 自动清理容器内临时备份文件。
- 自动清理容器内临时恢复文件。
- 恢复目标库不能与生产库同名。
- 系统保留库为 `postgres/template0/template1`。

## Dry Run

- `./scripts/deploy_trial.sh --dry-run`
- `./scripts/check_trial_stack.sh --dry-run`
- `./scripts/backup_db.sh --dry-run`
- `./scripts/restore_db.sh --dry-run backups/你的备份文件.dump`

## 外部联通与密钥

- `docker compose exec -T backend python scripts/check_statistics_module_ready.py`
- `python scripts/check_statistics_module_ready.py --env-template`
- `python scripts/check_statistics_module_ready.py --json --check-live-aggregation --check-app-connection-live`
- `MES_ADAPTER=mvc`
- `DINGTALK_ENABLED=true`
- `APP_CONNECTION_PUSH_MODE=enabled`
- `--skip-ai`
- `--skip-role-smoke`
- `--require-external`
- 不要把包含密钥的 `.env` 提交到 Git。
- 不要把上述真实值写入文档或提交到 GitHub。
