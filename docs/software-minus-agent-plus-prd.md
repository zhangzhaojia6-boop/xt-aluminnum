# PRD：Hermes 真实证据闭环与数据中枢减量增强

日期：2026-06-27

状态：封档基线 / 下一阶段 PRD

适用项目：`鑫泰铝业 数据中枢`

## 1. 背景

数据中枢已经有很多能力，但现在最需要的不是继续加页面。

下一阶段要解决一个更具体的问题：

```text
用户用自然语言问生产、能耗、库存、异常问题时，
Hermes 必须能查真实来源、给出可信答案、留下可追溯证据。
```

如果做不到这一点，智能体只是“会说”。

做到这一点，智能体才开始“会办事”。

## 2. 目标

### 2.1 产品目标

让 `数据中枢` 从“功能很多”收口成“关键链路可信”。

### 2.2 智能体目标

让 Hermes 从“闭环骨架能跑”升级为“基于 NousResearch Hermes 增强后的真实证据智能体”。

### 2.3 减量目标

冻结和合并不再服务主链路的入口、页面、服务和文档，不直接删除生产证据。

## 3. 用户

| 用户 | 他们要什么 |
|---|---|
| 经营管理者 | 快速知道今天有没有异常，数字从哪里来，能不能信。 |
| 生产负责人 | 查车间产量、入库、在制、能耗、异常原因。 |
| 专项责任人 | 补充钉钉证据、确认口径、处理缺失。 |
| 系统管理员 | 看到 Hermes 运行状态、证据链、失败原因和灰度结果。 |
| 后续开发智能体 | 读少量入口文档就知道该改哪里、不该改哪里。 |

## 4. 范围

### 4.1 本期必须做

1. 建立 20 个自然语言 smoke 问题。
2. 每个问题映射到指标、日期、车间或业务对象。
3. 每个指标对齐 [Hermes 事实来源地图](./hermes/fact-source-map.md)。
4. Hermes 能按来源优先级查证据。
5. 回答必须包含结论、来源、状态和 `trace_id`。
6. 缺数据时生成清楚的下一步动作。
7. 管理端能看到回答背后的来源状态。
8. 减法清单进入观察，不直接删除生产链路。

### 4.2 本期不做

1. 不新建完整新后台。
2. 不新建第二套日报系统。
3. 不把 RAG 当实时数字来源。
4. 不扩到所有经营分析问题。
5. 不做不可回滚的数据删除。
6. 不把没有真实证据的回答写成“已验证”。

### 4.3 软件形态

本期软件形态不是继续扩成很多系统。

软件端收口成：

```text
数据底座 + 大仪表盘 + 必要管理页面
```

大仪表盘优先放在 `/manage` 主线里，负责把关键指标、来源状态、异常冲突、Hermes trace 放到一起。

这 20 个问题用来验收 Hermes 是否真的能查证据。

| 编号 | 用户会怎么问 | 主要指标 |

| 8 | 今天成品率是多少？分子分母是什么？ | `daily_yield_rate` |
| 9 | 今天成本折算元/吨是多少？ | `cost_per_ton` |
| 10 | 今天在制料是多少？ | `wip_total` |

| 12 | 本月累计产量是多少？ | `monthly_total_output` |

| 20 | 今天日报能不能自动生成？还缺什么？ | 日报字段完整性 |

## 6. 回答格式要求

Hermes 的关键回答至少包含：

| 字段 | 含义 |
|---|---|
| 结论 | 用一句话回答用户问题。 |
| 数值 | 如果能查到，给出数字和单位。 |
| 时间范围 | 比如今天、昨天、本月、指定日期。 |
| 来源 | 说明本次实际采用的来源：钉钉群文件 / 群聊天、外接只读数据库、数据中枢投影、DailyFactBundle / 报表 / 历史记录，或 RAG 解释材料。 |
| 状态 | `confirmed`、`candidate`、`missing`、`conflict` 之一。 |
| `trace_id` | 用来回查本次回答、工具调用和证据。 |
| 下一步 | 缺数据或冲突时，告诉谁补、补什么、为什么。 |

小白版：

```text
不是只回答“今天产量 100 吨”。
而是回答“今天产量 100 吨，来自哪个来源，为什么可信，哪里可以回查”。
```

## 7. 功能需求

### 7.1 自然语言理解

Hermes 要把用户问题拆成：

- 指标。
- 日期。
- 车间。
- 业务对象。
- 是否需要比较、解释、追责或生成任务。

### 7.2 来源计划

每次回答前，Hermes 要先形成来源计划。

来源计划要对齐 [Hermes 事实来源地图](./hermes/fact-source-map.md)。

示例：

```text
问题：今天成品入库多少？
来源计划：
1. 先查授权钉钉群文件和群聊天内容
2. 再查成品入库业务域的 WMS/MES 外接只读来源
3. 再查数据中枢本地投影
4. 缺口再看 DailyFactBundle / 历史日报 / 人工填报
5. 只需要解释口径时才查 RAG 材料
6. 如果缺失，生成补证据任务
```

Hermes 回答 root_owner 真实问题时，事实优先级为：

1. 钉钉群文件和群聊天内容。
2. 外接只读数据库在自己业务域内的事实。
3. 数据中枢本地投影。
4. DailyFactBundle / 历史日报。
5. 人工填报。
6. RAG 解释材料。

如果钉钉群内容与 MES 或其他外接库冲突，回答优先采用钉钉群内容，并把冲突写入 trace。

### 7.3 真实取数

能查真实来源时，必须查真实来源。

允许返回空，但不能假装有值。

涉及 MES 数据库的数据，必须走只读读取链路：

```text
MES 数据库
  -> MES/WMS 只读 adapter
  -> 数据中枢投影或 DailyFactBundle
  -> Hermes 来源计划
  -> 回答、状态、trace
```

验收时要证明链路通畅，而不是只证明模型能说话。

空值要说明：

- 哪个来源没有数据。
- 缺日期、缺车间、缺权限还是缺同步。
- 下一步应该由谁处理。

### 7.4 冲突判断

多个来源不一致时，不要强行合并成一个数。

Hermes 要返回：

- 哪些来源冲突。
- 差异是多少。
- 当前采用哪个来源。
- 为什么采用它。
- 另一个来源需要谁复核。

### 7.5 管理端展示

管理端不需要新建大页面。

优先在已有页面增强：

- `/manage/today`：显示关键指标来源状态。
- `/manage/live`：显示实时数据卡点。
- `/manage/alerts`：显示缺失、冲突、待确认。
- `/manage/ai-control`：显示 Hermes 运行、trace、灰度和任务。

## 8. 减量需求

### 8.1 路由减量

继续保护主路由：

- `/entry/*`
- `/manage/*`

旧路由只做兼容跳转或冻结观察，不新增业务逻辑。

### 8.2 服务减量

报表加工层、历史 dashboard builder、重复 overview builder 等，先进入观察。

观察条件：

- 有无生产调用。
- 有无 Hermes 依赖。
- 有无报表依赖。
- 有无审计或回溯价值。

通过观察后再合并。

### 8.3 文档减量

README 和 [文档入口](./README.md) 作为主入口。

历史文档保留，不再作为第一阅读路径。

## 9. 验收标准

### 9.1 必须通过

| 验收项 | 通过标准 |
|---|---|
| 20 个 smoke 问题 | 每个问题都有来源计划、状态和 trace。 |
| 真实来源 | 能查真实来源的指标必须返回真实值。 |
| 空值处理 | 查不到时说清缺什么，不编数字。 |
| 冲突处理 | 多来源冲突时明确采用和不采用理由。 |
| 管理端可见 | 管理端能看到来源状态或跳到 trace。 |
| MES 读取链路 | 涉及 MES 的问题能证明数据库只读读取、投影、来源追踪链路通畅。 |
| 测试 | Hermes 相关单测和 smoke 测试通过。 |
| 减法 | 新增或更新冻结、合并、观察记录。 |

### 9.2 不能算通过

- 只有单元测试，没有真实 smoke 证据。
- 回答没有来源。
- 回答没有 `trace_id`。
- RAG 命中就直接当事实。
- 页面展示了数字，但查不到来源。
- 删除了生产证据、审计日志或 Hermes 依赖链。

## 11. 风险

| 风险 | 处理 |
|---|---|
| 真实数据源不稳定 | 明确返回缺失状态，不编答案。 |
| 指标口径混淆 | 以事实来源地图为准，回答里写分子分母。 |
| 旧代码还有隐藏依赖 | 先冻结观察，不直接删除。 |
| 管理端越做越复杂 | 只在已有页面增强，不新开门户。 |
| 智能体回答过度自信 | 强制来源、状态、trace 和下一步动作。 |

## 12. 完成定义

本 PRD 完成时，应该能做到：

```text
现场人员问 20 个关键问题。
Hermes 能查来源、给答案、说状态、留 trace。
管理端能看到证据链。
旧入口和重复服务继续收口。
```
