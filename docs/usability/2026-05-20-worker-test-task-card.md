# 数据中枢 工人现场使用测试任务卡

**版本日期：** 2026-05-20
**适用对象：** 试点车间一线操作工人
**测试形式：** 真机操作（钉钉 H5 + 工厂手机）
**预计耗时：** 单人 15-20 分钟
**配套观察人：** 1 位项目侧观察员，记录但不引导

---

## 测试前准备（观察员负责）

| 项目 | 操作 |
|---|---|
| 工人手机 | 工厂用手机打开钉钉 |
| 应用入口 | 工作台 → 数据中枢（或直接扫机台二维码） |
| 测试账号 | 用工人当天实际登录的账号，**不要**用专用测试账号 |
| 测试时段 | 当班正常生产中，不挑闲时 |
| 是否引导 | **不引导**，工人卡住时观察员只能说"按你平时的习惯做" |

---

## 任务一：到岗扫码登录

**给工人的话：**

> "你今天到岗了，请用平时的方法进入数据中枢。"

**观察员要看的事：**

- [ ] 工人是不是直接扫机台上贴的二维码？还是用账号密码登录？
- [ ] 第一次扫码到看到首页，**用了多少秒**？
- [ ] 进入页面后能不能立刻看到"自己今天在哪台机"？
- [ ] 有没有任何让工人困惑的步骤？

**记录卡：**

| 观察项 | 实际情况 |
|---|---|
| 进入方式 | □ 扫机台码 □ 账号密码 □ 其他：____ |
| 进入耗时 | ____ 秒 |
| 当前机列显示 | □ 一目了然 □ 需要找一下 □ 看不到 |
| 有无困惑 | □ 顺畅 □ 卡了一下：____ |

## 任务二：填一卷料

**给工人的话：**

> "刚下了一卷，请把这卷的数据录进去。"

**给一张真实的流转卡或扫码引导工人扫这一卷的二维码。**

**观察员要看的事：**

- [ ] 工人扫码后**屏幕上自动带出**了哪些字段？
- [ ] 工人需要**自己填**哪些字段？（重量、人数、能耗等）
- [ ] 工人能不能找到所有他要填的字段？
- [ ] 哪个字段填得最慢？为什么？

**记录卡：**

| 观察项 | 实际情况 |
|---|---|
| 扫码识别耗时 | ____ 秒（或失败：____） |
| 扫码后自动带出字段数 | ____ 个 |
| 工人手填字段数 | ____ 个 |
| 完成单卷耗时 | ____ 秒 |
| 提交结果 | □ 一次成功 □ 报错：____ |

## 任务三：处理一次"扫错"

**给工人的话：**

> "如果你不小心扫到了别的机器在做的卷，会怎么样？"

**让工人扫一张不属于他登录机列的流转卡。**

**观察员要看的事：**

- [ ] 系统有没有提示"机列与扫描结果不匹配"？
- [ ] 这个提示工人能不能看懂？
- [ ] 提示出现后，工人**自己怎么处理**？（继续填？重新扫？找班长？）

**记录卡：**

| 观察项 | 实际情况 |
|---|---|
| 是否有提示 | □ 有 □ 无 |
| 工人理解提示意思 | □ 立刻懂 □ 想了一下 □ 不懂 |
| 工人后续动作 | ____ |

## 任务四：班次填报（轮到他这班的整体数据）

**给工人的话：**

> "今天这一班结束前，把整体班次报表填一下。"

**观察员要看的事：**

- [ ] 工人能不能找到"班次填报"入口？
- [ ] 出勤人数、能耗这些字段填起来顺不顺？
- [ ] 哪几个字段他不知道填什么？

**记录卡：**

| 卡顿字段 | ____（写字段名） |
| 是否需要问别人 | □ 完全独立 □ 问了同事 □ 找了班长 |

## 任务五：网络弱时的体验（机房或地下室）

**让工人到信号差的位置（网络弱），扫一卷、填一卷、提交。**

**观察员要看的事：**

- [ ] 信号弱时还能不能扫码？
- [ ] 提交时如果失败，系统怎么告诉他的？

## 不要做的事（观察员注意）

1. ❌ **不要**告诉工人"应该怎么操作"——让他卡住，记录下来
2. ❌ **不要**夸"这个功能很方便对吧"——会污染反馈
3. ❌ **不要**只观察一个工人——至少 3 人，不同班次、不同熟练度
4. ❌ **不要**在工人在岗忙碌时硬塞测试——挑接班前后或换料间隙
5. ❌ **不要**把测试卡给工人填——观察员记录，工人只回答口头问题

## 测试结束后（项目侧）

把所有记录卡汇总到 `docs/audits/2026-05-{N}-worker-usability-field-audit.md`，含：

- 每位工人的耗时、问题数
- P0/P1 问题清单
- 三个最常见的卡点
- 工人原话引用（显示真实痛点）
- 改进优先级排序

汇总后 24 小时内给项目侧回信，决定是否进入下一轮。
