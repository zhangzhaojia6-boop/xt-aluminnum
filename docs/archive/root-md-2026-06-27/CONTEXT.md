# 鑫泰铝业 数据中枢

This context defines the business language used by the data hub and Hermes factory brain work.

## Language

**数据中枢**:
鑫泰铝业用于汇集、校验、审计和分发生产经营数据的系统。它不是 MES，MES 是外部生产数据来源。
_Avoid_: MES 系统, 报表系统

**日报事实包**:
某个业务日用于生成日报的一组可信事实集合，包括字段值、单位、来源、缺失、冲突和数据新鲜度。它只表达事实状态，不负责生成日报文案、发送消息或自动修正数据。
_Avoid_: 日报正文, 事实包文案, 报表模板

**业务日**:
生产经营数据归属的日期，是日报事实包的主键。不同角色看到的是同一业务日事实包的不同视角，不应重新计算出另一套数字。
_Avoid_: 自然日, 请求日期, 页面日期

**视角**:
同一业务日事实包面向不同接收人的裁剪方式，例如 root_owner 完整日报、老板摘要、车间主任视角或能耗负责人视角。视角不拥有独立事实，只决定看哪些事实和如何表达。
_Avoid_: 版本事实, 角色数据源

**Hermes 工厂大脑**:
面向制造现场的智能体，负责基于事实证据理解业务、判断风险、组织输出、推动动作和沉淀学习。
_Avoid_: 统计员, 报表助手

**全厂业务工厂大脑**:
Hermes 的长期目标形态，覆盖生产、库存、发货、合同、质量、能耗、成本、设备、人员、异常、工艺和经营分析等全厂业务。日报只是第一类验收场景，不代表 Hermes 的能力边界。
_Avoid_: 日报机器人, 统计助手, 单一报表 Agent

**Hermes 全厂业务工厂大脑升级**:
Hermes 从日报统计助手升级为全厂业务工厂大脑的正式架构方向，覆盖自然语言任务指令、工厂大脑长期规则、钉钉四条件采样、RAG 分层检索、LangChain/LangGraph 原生编排、Codex 验证转正和 Codex 施工层能力。
_Avoid_: 高级指令补丁, 日报助手优化

**Day-1 日报验收场景**:
旧的 Hermes Day-1 Super Brain MVP 不再是 Hermes 的能力边界，而是全厂业务工厂大脑升级中的第一个可验收场景。它用于验证 Hermes 能否围绕某个业务日查证事实、生成日报、解释冲突、沉淀学习和回复 root_owner。
_Avoid_: Hermes 总架构, 只做日报

**Hermes 主动性等级**:
Hermes 默认运行在 L4 主动性：主动补证据、主动发现风险、主动发起低风险动作，例如归档钉钉文件、生成待核对清单、生成日报草稿和建议长期规则。L5 主动性允许调用 Codex 重施工、修数据链路、部署生产或执行高影响动作，只能由 root_owner 授权。
_Avoid_: 被动命令机器人, 无授权 L5

**LangChain/LangGraph 原生编排**:
Hermes 工厂大脑需要直接落地 LangChain 和 LangGraph，而不是仅实现自研等价层。LangChain 负责模型、工具调用和结构化输出；LangGraph 负责状态图、checkpoint、可恢复执行、人机确认和长期任务编排。
_Avoid_: 仅预留框架接口, 固定命令服务伪装智能体

**Hermes 图状态**:
Hermes 每次任务都必须有可追踪的 LangGraph 状态，包括消息接收、身份识别、意图判断、计划制定、工具调用、证据收集、推理判断、行动执行、学习沉淀和回复交付。状态不能只存在于最终回答文本里。
_Avoid_: 无状态问答, 单次函数拼接回答

**LangGraph 数据中枢 checkpoint**:
Hermes 的 LangGraph checkpoint 应直接存入数据中枢 PostgreSQL，与 `agent_runs`、证据、日报、审计和记忆处于同一追责体系。`agent_runs.result_payload` 保存业务可读摘要，checkpoint 保存可恢复执行状态，长期规则和知识进入 Hermes 记忆/知识表。
_Avoid_: 外部孤立状态库, 无法追责的运行状态

**工厂大脑一期三域**:
Hermes 工厂大脑第一阶段重点覆盖生产域、经营域、工艺/质量域。生产域包括产量、投料、入库、在制、道次、开机、停机和异常；经营域包括合同、余合同、发货、库存、成品率、成本、电费和气费；工艺/质量域包括合金、规格、工艺路线、退火、冷轧、热轧、精整和质量异常。人事、财务全科目、设备维修全流程和采购全流程先作为可扩展域，不作为一期主战场。
_Avoid_: 一期全业务摊平, 只做日报, 单域生产统计

**一期三场景验收**:
Hermes 全厂业务工厂大脑一期至少用日报生成、异常分析、经营问答三个场景验收。日报生成验证事实采样、模板输出、冲突说明和输出 skill 对齐；异常分析验证工艺知识、历史案例、今日事实、钉钉说明和建议动作；经营问答验证生产、库存、发货、合同、余合同和经营判断。
_Avoid_: 只用日报验收, 单一统计验收

**Hermes 通用人格能力**:
Hermes 应具备更强自主性、学习能力和通用大语言模型式的自然交流能力。它可以在不影响业务严肃性的情况下使用轻松、自然、偶尔幽默的表达，但涉及事实、数据、权限、施工、生产判断和经营结论时必须保持专业、准确、可追溯。
_Avoid_: 死板命令机器人, 只会统计, 无边界闲聊

**Hermes Soul.md**:
Hermes 的人格定义文件，用于约束它的长期表达风格和互动气质。Hermes Soul.md 应把 Hermes 定义为一个有趣、轻松、诙谐的人，但这种人格只能改善交流体验，不能削弱事实准确性、权限边界、审计追踪和生产经营判断的严肃性。
_Avoid_: 冷冰冰的命令机器人, 拿生产事实开玩笑, 娱乐化业务结论

**Soul 四层定义**:
Hermes Soul.md 不只定义说话风格，还要定义价值观、行为习惯和工厂判断习惯。它应覆盖性格、工作方式、事实判断顺序、风险边界以及与 root_owner 的互动方式。
_Avoid_: 只有语气 prompt, 只会说俏皮话

**Hermes 三层长期上下文**:
Hermes 的长期上下文必须分成 Soul.md、长期规则和 RAG 知识库三层。Soul.md 管人格、价值观、行为习惯和工厂判断习惯；长期规则管 root_owner 授权的业务规则、数据优先级、分发策略和施工权限；RAG 知识库管工业知识、现场工艺、字段解释、历史案例和输出口径。
_Avoid_: 人格规则知识混存, 改风格影响事实规则

**自然语言意图**:
用户用不固定句式表达的业务目标，例如生成日报、解释异常、补充数据、追问来源或要求分发。Hermes 应理解自然语言意图，而不是只识别固定命令。
_Avoid_: 固定命令, 关键词脚本

**上下文型自然语言意图**:
用户用短句、追问或省略表达的业务目标，例如“在干嘛”“产量出来了吗”“今天正常吗”。Hermes 必须结合当前任务、业务日、最近对话、数据新鲜度和权限来理解，而不能只按固定关键词回答。
_Avoid_: 闲聊丢弃, 固定命令兜底

**任务指令**:
用户对 Hermes 发出的单次业务目标，只影响当前任务的查证、分析、输出或分发。例如生成某日正式日报、解释某个车间异常、查询今日产量是否正常。
_Avoid_: 长期规则, 系统提示词, 记忆规则

**工厂大脑长期规则**:
root_owner 或授权管理者明确要求 Hermes 长期遵守的工作方法、数据优先级、输出口径、追问习惯或分发策略。它会改变后续任务的默认行为，必须入库、可追溯、可降权、可删除。
_Avoid_: 临时任务, 一次性提示词, 普通聊天

**高级提示词留档**:
root_owner 给 Hermes 的长期提示词必须同时保存原文和结构化规则。原文用于追责和复盘，结构化规则用于后续任务执行。Hermes 不能只保存大模型总结，也不能每次重新解释原文后再执行。
_Avoid_: 只存摘要, 每次重新猜规则, 无原文追溯

**长期规则生效分级**:
root_owner 发来的低风险长期规则可以直接生效并回显结果；影响事实优先级、自动写库、权限分发、对外发送或批量行为的高影响长期规则，必须先回显 Hermes 的结构化理解，等待 root_owner 确认后生效。
_Avoid_: 所有规则都强制确认, 高影响规则静默生效

**自然语言规则管理**:
root_owner 可以用自然语言新增、修改、删除、降权、查看或临时覆盖 Hermes 长期规则。Hermes 必须理解“以后”“记住”“这条作为长期规则”“把刚才那条删了”“今天按临时口径，不要记住”等说法，而不能要求 root_owner 使用固定斜杠命令。
_Avoid_: 只支持命令菜单, 规则管理必须写固定格式

**长期规则候选**:
非 root_owner 授权人员提出的工厂大脑长期规则建议。候选规则可以被 Hermes 记录和展示，但在 root_owner 确认前不能改变 Hermes 的默认工作方法。
_Avoid_: 已生效规则, root_owner 修正事实

**自主规则建议**:
Hermes 在多次任务、历史日报、钉钉采样和数据对齐中发现可复用规律后，可以主动向 root_owner 提出长期规则候选。自主规则建议在 root_owner 确认前不能生效。
_Avoid_: 自动升级为真理, 无确认自学习

**输出 skill**:
历史真实日报成品和相关核对材料的只读参考源，用于校验 Hermes 输出是否贴近真实值和既有日报口径。
_Avoid_: 训练数据, 可修改日报

**工业通用知识库**:
Hermes RAG 中关于铝加工产业、制造管理、工艺逻辑、设备、质量、能耗、成本和经营分析的通用知识层。它用于帮助 Hermes 理解“为什么”和“怎么判断”，不能替代实时生产事实。
_Avoid_: 实时事实库, 每日动态数字

**场内个性化工艺知识库**:
Hermes RAG 中来自鑫泰现场的个性化知识层，包括车间别名、机列特点、工艺路径、日报口径、专项责任人规则、历史异常案例、数据字段含义和现场管理习惯。它优先服务鑫泰现场判断。
_Avoid_: 通用百科, 未验证猜测

**RAG 知识分层权重**:
工业通用知识和场内个性化工艺知识必须分层存储、分权重检索。通用知识用于解释铝加工原理、工艺原因和管理方法；判断鑫泰当天事实时，必须优先引用现场验证知识、日报事实包和授权数据源。
_Avoid_: 通用知识覆盖现场事实, 现场事实和百科同权

**RAG 分层检索体系**:
Hermes 使用知识库时必须区分通用工业知识、场内个性化工艺知识、历史案例、输出 skill 模板口径和实时事实证据。RAG 负责解释、归纳和辅助判断，实时事实仍来自日报事实包和授权数据源。
_Avoid_: 单一知识库, RAG 直接当事实

**RAG 六类知识单元**:
Hermes RAG 的最小知识单元应按工艺、指标、字段、规则、案例、输出口径六类建设。知识库不能只按整篇文档切块，应让 Hermes 能围绕一个业务问题组合相关工艺知识、指标定义、字段来源、规则、历史案例和输出格式。
_Avoid_: 整篇文档粗切, 无类型知识块

**RAG 路由检索**:
Hermes 使用 RAG 前必须先识别业务域、对象、指标、时间、需要的事实源和知识类型，再按知识类型检索。不能把所有问题直接丢给向量搜索。RAG 检索结果必须和日报事实包、MES/WMS、数据中枢、钉钉证据等事实源分开标注。
_Avoid_: 直接向量搜索一把梭, 检索结果和事实混淆

**RAG 非事实边界**:
RAG 不保存每日动态事实数字。每日产量、入库、库存、能耗、成本等动态事实应进入事实库、日报事实包、历史日报和审计记录；RAG 只保存定义、规则、案例经验、模板、字段解释和工艺知识。历史案例可以引用数字，但不能作为当前事实来源。
_Avoid_: 旧数字当新事实, RAG 当实时数据库

**系统反推知识建设**:
通过深度使用 MES 外部系统、数据中枢、历史日报、钉钉证据和输出 skill，总结归纳字段含义、工艺路径、业务规则、异常模式和检索标签，形成更适合 Hermes 的知识库和检索体系。
_Avoid_: 手工堆文档, 未验证知识入库

**Codex 验证转正**:
Hermes 自动反推出来的候选知识，经过 Codex 基于代码、数据库结构、系统页面、历史样本和测试结果验证通过后，可以直接转为正式知识。Codex 验证必须留下验证证据、验证时间、验证方法和对应知识版本。
_Avoid_: 未验证自动转正, 只靠大模型感觉转正

**Codex 施工层能力**:
Hermes 可以调用 Codex 执行工程施工层任务，包括读代码、分析架构、修改代码、补测试、写迁移、优化 RAG 管道、生成脚本、部署验证和修复生产问题。Hermes 负责提出业务目标、证据和验收标准，Codex 负责把它落到工程实现并返回施工结果。
_Avoid_: Hermes 只会建议, 人工手动施工, 无验收工程改动

**临时 Codex 模型层**:
Hermes 初期可以继续使用 Codex token 作为临时模型能力来源，用于自然语言理解、推理和回复生成。该方案是过渡方案，后续应迁移到稳定的服务端 LLM Provider；在迁移前必须对 Codex token 失效、刷新失败和 401 做中文兜底提示。
_Avoid_: 长期依赖会话 token, 英文鉴权错误直出

**模型失效降级运行**:
当临时 Codex 模型层 token 失效、刷新失败或返回 401 时，Hermes 不能直接输出英文鉴权错误，也不能整条链路瘫痪。它应继续执行可用的数据查询、证据读取和确定性统计，只把复杂推理、长文生成和 Codex 施工标记为暂不可用，并用中文提醒 root_owner 重新授权或等待恢复。
_Avoid_: Provider error 直出, 模型失败导致事实查询失败

**Codex 施工权限**:
只有 root_owner 可以让 Hermes 调用 Codex 执行施工层任务。非 root_owner 不能提交 Codex 施工候选任务，其消息只能作为普通业务消息、证据或低权重线索处理。
_Avoid_: 他人发起施工候选, 群聊触发改代码, 无授权部署

**Codex 轻施工**:
Codex 施工层中的低风险任务，包括读代码、查日志、跑测试、生成 spec/plan、总结系统架构、建设知识库条目和写只读脚本。轻施工仍需记录任务来源、执行结果和验证证据。
_Avoid_: 无记录探索, 口头建议替代执行

**Codex 重施工**:
Codex 施工层中的高影响任务，包括改代码、改数据库结构、改生产配置、部署生产、执行数据修正、删除或迁移历史数据。root_owner 可以直接授权重施工，但系统必须记录授权、施工目标、变更内容、验证结果和回滚方式。
_Avoid_: 无授权生产变更, 无回滚重施工

**钉钉补充数据**:
授权人员通过钉钉发送的文本、文件、图片或确认意见，可作为日报事实包的高优先级补充来源。它用于补齐缺失事实、解释异常、确认口径和提供现场最新信息。
_Avoid_: 普通聊天, 低优先级旁证

**钉钉授权采样范围**:
root_owner 定义的钉钉证据读取边界，可以覆盖指定群聊的历史聊天记录、文本、文件和图片。Hermes 只能在授权群、授权时间范围、授权专项责任人和授权文件类型内采样，不能默认扫描所有钉钉群。
_Avoid_: 全量群聊扫描, 私聊附件限定

**钉钉四条件采样规则**:
Hermes 读取钉钉历史聊天记录、文本、文件和图片时，必须同时满足授权群、专项责任人、内容类型、时间范围四个条件。四个条件缺一项时，只能记录为低权重线索，不能直接进入高优先级日报事实采样。
_Avoid_: 单条件采样, 只按关键词采样, 任意历史回捞

**专项责任人**:
root_owner 指定的钉钉发送人或业务负责人。专项责任人发送的日报、产量、库存、发货、能耗、异常等文件或文本，可以被 Hermes 优先识别为高价值钉钉补充数据。
_Avoid_: 任意群成员, 普通聊天发送者

**冲突字段**:
同一业务日、同一事实字段在多个来源之间不一致的字段。日报事实包必须保留冲突来源、采用值和采用原因，不能静默覆盖。
_Avoid_: 错误字段, 自动覆盖字段

**冲突采用规则**:
当同一字段在多个来源之间冲突时，Hermes 优先采用日报事实优先级更高的来源生成当前结论，同时必须展示冲突来源、冲突值、采用原因和建议修正动作。冲突不应让 Hermes 静默停住，也不能被隐藏。
_Avoid_: 隐藏冲突, 因冲突完全不答, 低优先级覆盖高优先级

**root_owner 修正事实**:
张兆嘉直接确认或修改的事实值，在日报事实包中优先级最高。它可以免审批进入日报事实，但必须保留原始来源、改前值、改后值、时间和修正原因。
默认交互是回显后确认；当张兆嘉明确要求直接执行时，可以免确认进入事实包。
