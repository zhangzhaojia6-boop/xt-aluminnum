# 日报优先响应与自动更新

本轮目标：打开 `/manage/today` 优先读日报，页面停留期间自动读取所选日期的新结果。

## 边界与选择

- 基线为 `062d5e7b`；生产三个服务 active、readyz ready，近期错误级日志无记录。
- 本轮不采用十五分钟缓存：接口每次仍查询本地真实业务表及 MES 投影。
- 比较了长期缓存、全面重写汇总、优先日报并减少重复查询三个动作，选择最后一个最小闭环。
- 管理摘要、调度概览和聚合在首份日报返回后启动，避免同一页面一开始竞争服务器资源。
- 每 30 秒尝试更新日报；页面隐藏、整页仍在加载或上一份日报未完成时跳过。刷新不清空已有数字，失败保留数字并显示更新失败；换日期清空旧值，旧请求不能覆盖新日期。
- 自动更新仅重读日报，不反复请求整套经营摘要。历史图表仍按需读取，手动刷新仍刷新整页。
- 顶部已核验指标继续使用事实包，不能将“最新查询”包装成“未核验事实已经正式确认”。正式日报的 127 字段合同、权限、来源和 trace 均保留。MES/WMS 外部访问保持只读。

## TDD 与本地验证

1. 新增日报优先请求测试：先观察到三接口同时启动的失败，再改为日报完成后启动其他两项；相关测试通过。
2. 新增后台更新测试：先因缺少 `refreshDaily` 失败，实现后通过；另验证更新失败后保留数字、恢复后清错、重复请求跳过、换日期拒绝旧响应。
3. 浏览器自动更新测试：先看到页面仍停留在 42，接入定时更新后显示 53，摘要只请求一次。此处是 HTTP 测试数据，不是生产性能数据。
4. 包装事实查询预算测试：同一业务日/自然日的日值和月值正确时，原实现需要 6 次查询；复用月记录后降为 3 次，继续保留日/月计数及来源追踪。
