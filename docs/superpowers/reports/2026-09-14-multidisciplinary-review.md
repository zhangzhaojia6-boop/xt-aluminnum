# 经营、设计、产品与工程联合审查

基线：`35b958da`。本轮是全库结构审查与关键业务链路深入复核，不是所有代码逐行审计完成的证明。

## 当前状态与目标

生产、本机与 GitHub 版本一致；三个服务 active、readyz ready，近期错误级日志无记录。日报已优先读取并每 30 秒自动更新。上一轮同浏览器单次实测首份日报 4.2 秒，其他重报表仍约 17–18 秒，不能称为整体秒开。

本轮业务目标：管理者能正确理解数字和系统状态，智能体查询失败时不伪装成功，工程检查能覆盖这些真实行为。保护 `/entry`、`/manage`、127 字段正式日报合同、MES/WMS 只读访问、权限、来源与 trace。

## 覆盖方法与限制

- 按九个封档入口复核当前方向，历史综合文档只作为地图；不沿用其中的完成率。
- 当前 checkout 结构图有 16,465 节点、100,788 条边。工具未提供 head_sha 字段；以当前工作树重建及 Git 状态为证据。
- 结构盘点涉及后端 369 个 app 文件、344 个测试文件、59 个迁移文件，前端 253 个 src 文件、107 个测试文件，以及路由、部署与测试配置。数量按本轮跟踪文件筛选，不与旧清单直接换算覆盖率。
- 重点读了管理日报页面、数字与状态转换、网页 AI 状态管理、AI 路由、取证上下文、权限以及相关测试；其他模块只完成结构复核，不称为运行验收。
- 生产只读统计：事实包快照 62，agent_runs 647，outbox 1295，chat_inbox 691，网页 AI 上下文包 15。运行状态 answered 642、clarifying 5；这些计数不证明任务执行或消息投递成功。
- 独立 Hermes 仓库及外部 MES/WMS 实现不属于本次全库逐行审阅范围。

## 四个视角的判断

| 视角 | 最重要的问题 | 更改原则 |
|---|---|---|
| CEO / 经营 | 错名、错单位、假成功会影响经营判断 | 先保证决策信息可信，再扩展功能 |
| 设计师 | 主要数字与标题不匹配，技术状态混进业务界面 | 保持浅色工作台，突出准确数字与必要状态，不增加装饰性入口 |
| 产品经理 | 问题已收到、证据已查到、动作已完成缺乏清楚区分 | 错误明确可见，保留用户问题和重试路径 |
| 工程师 | 兼容降级吞掉所有错误；验证对话身份之前就执行昂贵取证 | 先校验再计算，公共入口做行为测试，缩小旧路径依赖 |

## 动作选择与验收

比较三个候选：继续重写查询、全面换视觉、先修复误导性结果。选择第三项，业务风险最低、可通过真实页面复现、无需迁移或改动事实源。

按 R1 → R2 → R3 顺序，每一项先复现、再最小修改、再验证，不能同时铺开多个未验收方向。R4–R8 保留为明确待办，不把扫描和计划写成完成。

沿用 codebase-design 的 Module / Interface 原则：用现有日报转换和会话请求 Interface 验证业务行为；不为这批修复新增服务、数据表或抽象层。

当前无需用户动作。回滚使用既有发布流程返回本轮基线；本批不修改原始生产数据。

## 本轮实施与验收

- R1 已修复：成品率卡使用百分比字段，缺失显示暂无可信数据，真实零值仍显示 0%。浏览器测试先复现吨数错误，再覆盖正常、缺失和零值。
- R2 已修复：移除失败后转旧回声接口的路径，服务失败明确显示生成失败。进一步复现并修复“停止”按钮未取消当前请求，以及消息内容更新未及时渲染的问题。停止会取消浏览器等待并丢弃迟到答案，不保证终止服务器上已经开始的模型计算。
- R3 已修复：先核对对话存在及归属，再读取事实或调用模型。真实 SQLite HTTP 测试先复现错误的 500，再验证他人及不存在的对话均返回 404，原对话不新增消息。
- 本地管理端浏览器检查 17 项全部通过，覆盖首开提问、失败、取消、成品率、日报自动刷新和响应式页面；接口错误使用浏览器 HTTP 模拟，不冒充生产模型故障实测。
- 后端 AI 路由、日报权限和审核范围检查共 27 项通过。
- 前端 Node 检查 768 项，757 通过、11 项失败；失败名称与修改前完全一致，主要是已被浅色工作台替代的旧布局/源码断言。本轮不修改旧断言制造全绿。
- R4–R8 尚未解决。GitHub CI 与生产验收以本轮 PR 和发布记录为准，不以本地测试替代。
