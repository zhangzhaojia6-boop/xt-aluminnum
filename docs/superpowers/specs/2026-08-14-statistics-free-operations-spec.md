# 去统计流与 Hermes 自成长运行 SPEC

日期：2026-08-14

状态：已批准，按阶段实施

适用产品：`鑫泰铝业 数据中枢`

## 1. 一句话目标

```text
取消人工收集、抄写、汇总、对数和催报流程；
由 Hermes 自动取数、查证、追缺、裁决、出报和复盘，
业务责任人只确认机器无法知道的现场事实与高风险冲突。
```

这不是取消责任人，也不是让模型猜数。

## 2. 已确认的产品决定

1. 采用“去掉人工统计流程”，不追求完全无人负责。
2. 每天 10:00 只有事实完整、无阻塞冲突时才发送正式日报。
3. 不完整时不发送半成品日报；Hermes 定向追缺，补齐后自动发送。
4. 先提醒直接责任人；10:00 仍未补齐时向车间负责人升级一次。
5. 同一缺项没有事实变化时不重复提醒。
6. 冲突按字段专属来源优先级和容差自动裁决；关键字段超限、时间不清或证据冲突时才转人工。
7. 补录同时支持：钉钉预填链接进入 `/entry/fill`，以及责任人在钉钉直接回复。
8. 聊天补录只有在发送人、字段、日期、单位、数值和权限都明确时才自动入库；否则要求确认或跳转表单。
9. 127 个规范字段合同保持不变。`0` 是事实值为零，`N/A` 是当天不适用，二者不能混用。
10. `N/A` 必须具有日期、字段、判断依据、责任人和 trace，不能用全局分类缩小分母。
11. 第一体验优先级是 `/entry/fill`：打开快、填写快、弱网不丢、重复提交不重复入账。
12. Hermes 以事件驱动为主，在 09:30、10:00 等业务节点做兜底巡检。
13. Hermes 采用高自主、可恢复执行模式；不要求事前审批。
14. 自动修改保留旧版本、证据、操作者、时间和 `trace_id`；删除使用软删除并支持撤销。
15. 影响关键日报字段、批量事实、来源裁决或正式记录撤销时，发送一条事后摘要。
16. Hermes 可以自我成长，但策略必须版本化、回放验证、可回滚。
17. 自我成长先保证事实可靠，再优化闭环效率、打扰次数、速度和自然表达。
18. Hermes 可读取企业应用授权范围内的群聊、单聊和文件，不设置硬群边界或僵硬关键词。
19. “可读取”不等于“可采信”；业务相关性、来源身份、时间和证据强度通过后才能进入事实链。
20. 正式去统计流后，不保留集中统计员。字段责任回到事实产生部门，车间负责人承接超时与冲突升级。

## 3. 系统边界

### 3.1 受保护主链

```text
钉钉事实 / MES-WMS 只读数据 / 扫码补录
  -> 数据中枢投影与 DailyFactBundle
  -> 字段合同校验与冲突裁决
  -> Hermes 缺项任务和 trace
  -> /entry/fill 或钉钉回复补齐
  -> 自动复核
  -> 正式日报
```

必须保护：

- `/entry`
- `/manage`
- `DailyFactBundle`
- MES/WMS 数据库只读边界
- 钉钉原始证据
- `AgentEvent`
- `AgentOutboxMessage`
- 审计、版本和 trace

### 3.2 明确不做

- 不新建日报门户。
- 不新建第二套大仪表盘。
- 不重写整套填报表单引擎。
- 不让 RAG 或历史日报填充实时生产数字。
- 不把 `D:\输出skill` 当成事实源。
- 不用固定关键词限制钉钉消息识别。
- 不把 MES 无产出直接描述成 PLC 实测停机。
- 不为了通过门禁减少 127 字段分母。

## 4. 五个业务闭环

### 4.1 日报闭环

```text
07:30 生产业务日切换
09:30 内勤与专项字段截止
10:00 正式日报判断
完整 -> 发送正式日报
不完整 -> 定向追缺，不发送半成品
补齐 -> 自动复核并发送正式日报
```

关键经营字段必须 100% 有真实来源且口径正确。缺失时保持缺失状态，禁止使用估算值、历史值或 `0` 代替。

### 4.2 精准补录闭环

钉钉链接携带 `business_date`、`entry_fields`、任务 trace 和责任信息。`/entry/fill` 复用现有表单，只显示本次需要补的字段，同时保留完整表单的普通入口。逐卷录入必须一并显示后端建立有效记录所需的岗位必填依赖；依赖清单在统一字段契约阶段正式版本化。

提交后：

1. 立即写入可审计事实。
2. 触发目标日期事实包刷新。
3. 关闭已满足的缺项事件。
4. 仍有冲突时更新原任务，不重复新建。
5. 10:00 后满足正式条件时自动生成并投递日报。

### 4.3 钉钉聊天补录闭环

Hermes 从授权范围内理解自然语言，不依赖单一模板。

自动写入条件：

- 发送人可映射到有效用户和责任范围。
- 业务日期唯一明确。
- 字段唯一明确。
- 数值、单位和正负方向明确。
- 字段校验通过。
- 没有未解决的高优先级来源冲突。

任一条件不满足时，Hermes 只追问最小必要信息，或发送精准补录链接。

### 4.4 系统判定开停机闭环

当前没有 PLC 设备信号。系统记录的名称必须是“系统判定开停机”，不能标记为“设备实测”。

Hermes 使用最近 30 个有效生产日，按“设备 + 产品规格 + 班次”学习动态节拍，过滤检修、换辊、异常和无效样本。

可信度：

- 高：明显超过动态节拍，且至少两项证据一致；可进入日报。
- 中：只有一项强证据；建立记录并定向确认一次。
- 低：样本不足或接近阈值；只在管理端观察，不发消息。

责任人可在钉钉回复或精准补录页面纠正。原判断、证据、修正和策略版本全部保留。

### 4.5 自我成长闭环

```text
执行 -> 观察结果 -> 接收纠正 -> 沉淀案例
-> 生成候选策略 -> 历史真实样本回放
-> 对比旧版本 -> 自动发布或拒绝
-> 持续监控 -> 自动回滚
```

可自动升级：

- 消息理解和字段映射。
- 责任人路由。
- 设备动态节拍。
- 提醒时机和打扰抑制。
- 回答长度、称呼和关注点。

需先影子运行再自动升级：

- 字段来源优先级。
- 字段容差。
- 权限策略。
- 关键经营口径。

## 5. 版本化字段合同

127 个规范字段只有一个合同来源。前端、后端、日报和 Hermes 读取同一版本。

每个字段至少包含：

```yaml
field_id: total_output_daily
label: 全厂总产量
unit: t
contract_version: 2026-08-14
business_date_rule: production_07_30
applicability:
  rule: active_production_day
  declared_na_required: true
source_plan:
  - source: dingtalk_evidence
    priority: 100
  - source: mes_wms_readonly
    priority: 80
  - source: scan_supplement
    priority: 60
owner:
  role: planning_owner
  escalation_role: workshop_director
deadline: "10:00"
validation:
  type: number
  minimum: 0
tolerance:
  absolute: 20
  relative_percent: 2
entry:
  route: /entry/fill
  control: number
  targeted: true
```

规则：

- 每个字段使用自己的单位和容差。
- 所有字段绝对误差上限不得超过 `20`，但字段可配置更严格范围。
- 比率、吨、分钟、电量不能共用同一个误差解释。
- 合同变更生成新版本并执行影响检查。
- 页面继续复用现有业务表单；合同提供元数据，不生成第二套通用表单系统。

## 6. 流畅性与稳定性 SLO

### 6.1 `/entry/fill`

- 95% 的访问在 3 秒内达到可填写状态。
- 输入无明显阻塞。
- 95% 的提交在 2 秒内返回成功或明确进入可靠重试。
- 已输入文本和数字在刷新、退出或断网后可恢复。
- 网络恢复后自动重试。
- 数据丢失数为 0。
- 重复入账数为 0。

### 6.2 `/manage`

- 今日关键结果、待办和异常在 3 秒内出现。
- 趋势和明细按需加载，不阻塞首屏。
- 核心接口错误率低于 1%。
- 关键生产、缺项和异常采用事件更新，并以 30 至 60 秒刷新兜底。
- 每个数字显示业务时间、来源和新鲜度状态。

### 6.3 Hermes

- 钉钉消息 5 秒内确认已受理。
- 复杂查证异步完成后返回最终结果。
- 同一事实无变化时不重复提醒。
- 每个关键结论具有来源和 trace。

## 7. 去统计流验收门槛

运行 7 个完整业务日的影子验收。原统计人员只核对最终结果，不参与收集、抄写、汇总和催报。

第一阶段目标：

- 适用字段自动取得率达到 80%。
- 关键字段真实来源覆盖率 100%。

正式切换目标：

- 适用字段自动取得率达到 95%。
- 适用字段完整率达到 95%。
- 适用字段准确率达到 95%。
- 关键经营字段真实来源与口径正确率 100%。
- 超出字段容差的数字为 0。
- 人工抄数、汇总和催报次数为 0。
- 人工动作只剩现场事实确认与高风险冲突处理。

## 8. 分阶段顺序

1. **阶段 1：真实基线与 `/entry/fill` 可靠性。** 接入现有草稿、弱网队列、提交去重、精准字段显示和前端性能遥测。
2. **阶段 2：唯一 127 字段合同。** 统一字段元数据、适用性、来源、责任人、容差和控件映射。
3. **阶段 3：Hermes 主动追缺。** 事件驱动、分级催办、聊天补录、冲突裁决和事后摘要。
4. **阶段 4：系统判定开停机。** MES 动态节拍、证据融合、可信度和纠正学习。
5. **阶段 5：管理大仪表盘流畅性。** 首屏关键链、按需加载、缓存和异常优先布局。
6. **阶段 6：7 日影子验收与正式切换。** 达标后停止人工统计流程。

任何阶段未通过自己的真实验收，不得并行进入下一阶段。
