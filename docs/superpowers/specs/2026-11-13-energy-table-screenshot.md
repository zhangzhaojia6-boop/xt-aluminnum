# 用电表截图自动入库

## 背景

刘宪伟从 11/14 起每天私聊张兆嘉发《各车间电耗统计表》的截图（`image.png`），不发 Excel。截图版式和原 Excel 一样：表头首格「车间/日期」，后面是「1日 … N日」，每行首格是车间名，末尾有「合计」「高压合计」「差值」。

现状：钉钉同步对 `.png` 记 `unsupported_file_type`，原图在同步的临时目录里随后被删，能耗字段一直缺失。

## 做法

1. 同步收到私聊图片（`.png/.jpg/.jpeg`，频道 `dingtalk_private`）时，把图片交给现有的 `ingest_dingtalk_energy_file`。
2. `ingest_dingtalk_energy_file` 遇到图片：
   - 调后端已配的大模型（现为 Agent Plan 豆包 seed，能看图），把表格转成制表符分隔文本。
   - 找到业务日对应的「N日」列。该列里「合计」前各行之和必须等于「合计」，有「高压合计」「差值」时，「高压合计 − 合计」必须等于「差值」。对不上就记 `blocked / image_table_check_failed`，不入库。
   - 通过后写成 xlsx，文件名按表头判断：含「车间/日期」记为「各车间电耗统计表-截图.xlsx」，否则记为未识别并跳过。再走现有暂存流程。
3. 登记规则自动正式入库时，按暂存文件名匹配规则（Excel 的暂存文件名本来就带原文件名，行为不变），这样截图也能命中「各车间电耗统计表」规则。
4. 刘宪伟第一张截图进来后，用现有 `register_energy_file_sender.py` 登记他的发送人和会话，并对该证据补一次正式入库。

## 不做

- 天然气表截图：版式有合并表头，等真实截图到了再接。
- 一张图里其他日期的补数。
- 新增配置项、新服务、图片长期存储。

## 风险与处理

- 模型读错数字：靠表格自带的合计、差值核对，对不上整天不入库。用 11/13 真实截图验证，模型读出的 1–12 日全部通过核对（5 日「彩涂」40 起初被人工看成 0，按合计倒推应为 40，是人看错）。
- 模型慢（约 60 秒）：只对私聊图片调用，量很小；超时按 blocked 记，不影响其他证据。

## 验收

- 单测（数字为虚构，版式同真实截图）：核对通过的一天解析出高压合计和合计两个字段；改错一格的一天核对失败、不暂存；非能耗图片跳过；Excel 原路径不变。
- 生产：用 11/13 的真实截图（用户提供）演练一次识别和核对；刘宪伟首张截图进来后登记并核对 11/13 能耗字段入库。
