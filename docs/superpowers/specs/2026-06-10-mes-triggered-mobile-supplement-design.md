# MES 触发待补录设计方案

日期：2026-06-10
系统：鑫泰铝业 数据中枢

## 目标

把主操现场动作从“MES 一体机扫随行卡录下机数据，再扫机台二维码，再扫随行卡补录”简化为：

```text
MES 一体机扫随行卡并保存下机数据
  ↓
数据中枢自动抓到 MES 下机记录
  ↓
手机端扫机台二维码
  ↓
看到本机台待补录卷材
  ↓
点选卷材，只补 MES 没有的字段
```

正常情况下，主操不需要在手机端第二次扫随行卡。

更大的方向是：前端页面优先映射 MES 数据库中的真实生产数据，填报端从“重复录产量”转成“补录 MES 没有的字段 + 异常审核 + 纠偏说明”。

## 核心判断

MES 一体机已经记录了产量相关的关键字段，因此产量类数据可以优先以 MES 为主账。

手机填报不再重复承担“产量真值”的职责，改为承担：

- 补录 MES 没有设计的现场字段。
- 确认这卷料确实属于当前机台。
- 补充异常、质量问题、备注、废料、套筒等现场信息。
- 在 MES 机列匹配不准时做人工兜底选择。
- 对 MES 数据异常做人工审核，而不是直接覆盖 MES 主账。

## 新增设计前提

- 冷轧三个车间需要按“每卷每道次”展示和补录，不能只看一卷最终下机重量。
- 热轧、铸轧在 MES 中也可能上传坯料卷信息，不能只围绕冷轧卷材设计。
- 前端管理端、调度墙、日报页优先使用 MES 投影数据作为主要展示来源。
- 填报端用于补录、确认、异常审核、纠偏说明。
- 铸锭新增每日汇总角色，填写铸锭块数、投料量、下机量。
- 自动计算数据要进入前端合适位置展示，包括各项吨耗、成品率、废料等。
- 填报端补录业务日改为早上 `09:30` 到次日 `09:30`。

## 当前代码基础

系统已经具备以下基础，不需要从零开始：

- MES 卷材快照表：`mes_coil_snapshots`
- MES 工序记录表：`mes_workshop_process_records`
- MES 入库记录表：`mes_stock_records`
- 手机填报主表：`work_order_entries`
- 生产业务日口径：早上 `07:30` 到次日 `07:30`
- 手机扫码服务：`scan_lookup_service`
- MES 辅助字段服务：`mes_assisted_fill_service`
- 手机统一填报页：`UnifiedEntryForm.vue`

其中 `mes_workshop_process_records` 已有上机重量、下机重量、机台名、员工、工序、业务日等字段，适合生成“待补录卷材”。

需要调整的地方：

- 当前生产业务日基础口径仍是 `07:30`，本方案要求新增“补录业务日”口径 `09:30`。
- 不能直接把所有统计口径粗暴改成 `09:30`，要先明确哪些页面读 MES 主数据，哪些页面读补录审核数据。
- 冷轧道次、热轧坯料卷、铸轧坯料卷需要从 MES 工序和卷材快照中单独梳理映射。

## 页面数据分层

前端页面分三层展示，避免“MES 数据”和“人工填报数据”混在一起：

### 第一层：MES 主数据

用于管理端主看板、调度墙、日报主数值。

包括：

- 卷材当前所在车间、工艺、机列。
- 每卷工序记录。
- 每卷上下机重量。
- 包装入库产量。
- 坯料卷信息。
- 冷轧每卷道次信息。

### 第二层：补录和审核数据

用于填报明细、异常审核、差异对照。

包括：

- 手机端人工补录字段。
- 质量问题。
- 废料、套筒、托盘等 MES 没有或不稳定的字段。
- 机列不匹配确认。
- MES 错误纠偏说明。

### 第三层：自动计算指标

由 MES 主数据和补录数据共同计算，不由人工直接填写。

包括：

- 吨耗。
- 成品率。
- 废料率。
- 工序成材率。
- 机台产出效率。
- 能耗/吨。

这些指标应在管理端、车间看板、日报页展示为“系统自动计算”，不要混入填报输入区。

## 推荐方案

### 方案 A：动态待补录列表，第一阶段推荐

不新增大表，后端根据 MES 工序记录实时计算“哪些卷材还没补录”。

计算逻辑：

1. 按当前机台、车间、业务日查询 MES 工序记录。
2. 用 `device_name` 优先匹配本系统机台。
3. 如果 MES 没有明确机台，则用车间 + 工艺 + 机台别名做候选匹配。
4. 排除已经存在本地补录记录的卷材。
5. 返回待补录列表给手机端。

优点：

- 改动小。
- 不容易产生脏草稿。
- MES 数据更新后，待补录列表能自然刷新。

缺点：

- 如果用户需要“已忽略、已确认不是本机”的状态，后续需要增加一张轻量状态表。

### 方案 B：自动生成草稿表

MES 每同步一条下机记录，就生成一条本地草稿。

优点：

- 追溯清晰。
- 能记录待办状态。

缺点：

- 更容易出现重复草稿、过期草稿。
- 需要更多清理逻辑。

### 方案 C：继续扫码随行卡

保留现在的“扫随行卡带出字段”作为主流程。

优点：

- 实现最简单。

缺点：

- 没有解决现场最痛的问题，主操仍然要重复扫随行卡。

结论：第一阶段采用方案 A，保留方案 C 作为兜底，不直接采用方案 B。

### 方案 D：MES 主数据 + 补录审核，修订后推荐

把系统分成“MES 主数据层”和“人工补录审核层”。

做法：

1. 后台持续同步 MES 工序、卷材、入库、坯料数据。
2. 管理端主要页面优先读取 MES 投影数据。
3. 手机端只显示当前机台或当前角色需要补录的内容。
4. 人工补录不覆盖 MES 主账，只产生补录记录和异常审核记录。
5. 管理端同时展示 MES 主值、人工补录值、系统计算值、差异原因。

优点：

- 现场填报最省事。
- 管理端数字来源更统一。
- 后续日报和调度墙可以围绕 MES 主数据做实时展示。

缺点：

- 对 MES 字段完整度、机列匹配、道次识别要求更高。
- 第一阶段必须认真做只读核对，不能直接切换。

结论：最终方向采用方案 D，落地时先按方案 A 做最小可用版本。

## 冷轧道次设计

冷轧三个车间的关键不是“一卷有没有填”，而是“一卷经过了哪些道次，每道次在哪台机、上下机重量和规格是什么”。

设计口径：

- 一个随行卡号可以对应多条冷轧工序记录。
- 每条工序记录视为一个道次。
- 道次顺序优先按 MES 工序时间排序。
- 如果 MES 有道次号，优先使用 MES 道次号。
- 如果 MES 没有道次号，则用同一随行卡下的冷轧工序时间排序生成 `第1道、第2道、第3道`。

冷轧手机端不要求主操重复录每个道次的产量。

冷轧手机端只处理：

- 当前机台待补录的道次。
- 道次异常说明。
- 废料、套筒、质量问题等补录字段。
- MES 道次与当前机台不一致时的确认。

管理端展示：

```text
随行卡 26A04967
第1道｜2050冷轧｜上机 6.50t｜下机 6.35t｜规格 1.20 -> 0.96
第2道｜在线退火｜上机 6.35t｜下机 6.35t｜状态 H24
第3道｜包装入库｜入库 6.30t
```

这样管理端能看清一卷料完整流转，手机端不用重复录道次。

## 热轧和铸轧坯料卷设计

热轧、铸轧如果在 MES 中已经上传坯料卷信息，也应进入同一套主数据层。

设计口径：

- 坯料卷、铸轧卷、热轧卷都先作为 MES 卷材或工序实体进入数据中枢。
- 如果 MES 字段中能识别来源工序，就按工序挂到对应车间。
- 如果 MES 只提供批号、坯料号、重量，则先进入“坯料卷参考数据”，等待别名和工艺映射完善。
- 热轧、铸轧的产量主值优先从 MES 工序记录或坯料卷记录读取。
- 手机端只补录 MES 没有的异常、废料、备注、质量问题。

需要只读核对：

- MES 是否有热轧坯料卷表或字段。
- MES 是否有铸轧坯料卷表或字段。
- 坯料卷号和随行卡号是否能互相追踪。
- 坯料重量单位是 kg 还是 t。
- 坯料卷是否有机台名、工序名和保存时间。

如果坯料卷信息完整，前端调度墙可以显示：

```text
铸轧坯料卷：今日 18 卷｜合计 126.5t
热轧坯料卷：今日 12 卷｜合计 92.4t
```

如果坯料卷信息不完整，先展示为“MES 坯料参考”，不要直接进主产量。

## 铸锭每日汇总角色

新增一个铸锭角色，按每日一录处理。

角色建议：

```text
铸锭内勤
```

填报周期：

```text
09:30 到次日 09:30
```

字段：

| 字段 | 单位 | 来源 | 是否必填 |
| --- | --- | --- | --- |
| 铸锭块数 | 块 | 人工填报 | 是 |
| 投料量 | 吨 | 人工填报 | 是 |
| 下机量 | 吨 | 人工填报 | 是 |
| 异常说明 | 文本 | 人工填报 | 否 |

铸锭数据定位：

- 不和 MES 卷材记录混在一起。
- 作为每日汇总数据进入管理端。
- 可参与全厂物料平衡、投料趋势、下机量趋势。
- 不直接替代包装入库口径。

## 手机端交互

主操扫机台二维码进入填报端后，页面顶部显示：

```text
当前机台：园区在线退火 1#线
业务日：2026-06-10
待补录：3 卷
```

中间显示待补录列表：

```text
26A04967
0.96*1220*C｜1060 H24｜河南永晟
下机 6.35 吨｜10:52｜MES 已入账
按钮：补录
```

点击“补录”后进入简化表单：

- MES 已有字段只展示，不要求重复填。
- 手机端只显示需要人工补充的字段。
- 没有质量问题时，只点一次确认即可提交。
- 有质量问题时，再展开问题类型、描述、照片。
- 冷轧页面显示当前道次，不要求人工选择全部道次。
- 热轧、铸轧页面如有 MES 坯料卷，优先从待补录列表点选坯料卷。

保留一个小入口：

```text
找不到卷材？扫随行卡兜底
```

这个入口只用于 MES 延迟、机列匹配失败、临时补录等异常场景。

## 补录业务日

填报端补录业务日改为：

```text
09:30 到次日 09:30
```

影响范围：

- 手机端待补录列表。
- 手机端历史补录。
- 缺报判断。
- 补录完成率。
- 铸锭每日汇总。
- 人工异常审核。

不应直接影响的范围：

- MES 原始记录时间。
- MES 入库记录原始时间。
- 已发布历史日报。

需要评估后再统一的范围：

- 管理端日报主统计窗口。
- 调度墙“今日”窗口。
- MES 在制料日切窗口。

原因：MES 主数据如果按 07:30 统计，而补录按 09:30 统计，会导致待补录和日报数字边界不同。最终建议把“主生产业务日”也统一到 `09:30`，但必须先做历史数据对比，确认不会导致日报突然跳数。

## 机列匹配规则

匹配分三级：

| 等级 | 规则 | 处理方式 |
| --- | --- | --- |
| 高可信 | MES `device_name` 能直接匹配本系统机台别名 | 自动归到该机台 |
| 中可信 | MES 只有车间和工艺，能推断到少数候选机台 | 手机端让主操点选 |
| 低可信 | MES 只有随行卡或批号，没有可靠机台信息 | 不自动归属，只能扫码兜底 |

如果 MES 机台和当前机台二维码不一致，页面提示：

```text
这卷料在 MES 中显示为其他机台，请确认是否扫错机台。
```

默认不阻断，但必须记录差异。

## 数据保存方式

第一阶段不把 MES 记录伪装成人工填报记录。

提交补录时写入 `work_order_entries`：

- `machine_id`
- `workshop_id`
- `business_date`
- `on_machine_time`
- `off_machine_time`
- `input_weight`
- `output_weight`
- `input_spec`
- `output_spec`
- `material_state`
- 人工补录字段
- `extra_payload.mes_reference`

其中产量字段来自 MES，人工补录字段来自手机端。

`extra_payload.mes_reference` 保存：

- MES 工序记录 ID
- 随行卡号
- MES 机台名
- MES 员工名
- MES 保存时间
- 匹配等级
- 匹配方式

这样管理端既能按 MES 主账统计，也能追溯是谁在手机端补录了现场字段。

## 统计口径

产量主口径：

- 全厂最终产量：继续取 MES 入库/包装入库口径。
- 车间过工序产量：取 MES 工序记录下机重量。
- 机台产量：取 MES 工序记录，并通过机台匹配归属。
- 冷轧道次产量：取 MES 每道工序下机重量，作为道次产出，不重复加总为全厂最终产量。
- 热轧、铸轧坯料产量：优先取 MES 坯料卷或对应工序记录，先作为车间过程产量，不直接替代包装入库口径。
- 铸锭每日汇总：取铸锭角色每日填报，不混入卷材级 MES 记录。

手机端补录不再直接改写产量真值。

如果人工认为 MES 错了，不直接覆盖 MES 主账，而是走“纠错/差异记录”：

```text
MES 下机重量：6.35 吨
现场认为：6.30 吨
原因：现场复核发现一处录入误差
```

管理端可以展示差异，但日报主口径仍以 MES 为准，除非管理端明确走审批纠偏。

## 自动计算指标展示

自动计算指标不放在手机输入区，放在管理端和车间看板。

推荐位置：

- `/manage/live`：显示实时吨耗、成品率、废料率、机台效率。
- `/manage/today`：显示本业务日自动计算结果和昨日对比。
- `/manage/daily-report`：显示日报最终口径、MES 主值、人工补录对照。
- 车间主任看板：只显示本车间吨耗、成品率、废料、异常、未补录。

指标来源：

| 指标 | 推荐算法 |
| --- | --- |
| 吨耗 | 能耗 / MES 产量 |
| 成品率 | MES 包装入库或最终成品 / 投料 |
| 废料率 | 补录废料 / MES 投料或上机重量 |
| 工序成材率 | MES 下机重量 / MES 上机重量 |
| 机台效率 | 业务日内该机台 MES 下机吨数和卷数 |

显示原则：

- 有数据就显示真实值。
- 没数据就显示 `0` 或 `暂无数据`，但要能区分“真 0”和“未同步”。
- 指标旁边标明来源：MES、人工补录、系统计算。
- 不允许把人工补录值伪装成 MES 主值。

## 接口设计

新增或扩展接口：

```text
GET /api/v1/mobile/mes-pending-supplements
```

用途：当前机台登录后，获取本机台待补录卷材。

入参：

- 当前登录用户或机台二维码身份。
- 可选 `business_date`，默认当前补录业务日。

返回：

- 待补录卷材列表。
- MES 字段。
- 冷轧道次信息。
- 热轧/铸轧坯料卷信息。
- 机台匹配等级。
- 是否已补录。
- 是否存在机台不一致风险。

提交接口可复用现有手机填报保存接口，但需要支持传入：

```text
mes_process_record_id
mes_reference
supplement_fields
```

新增或扩展铸锭每日汇总接口：

```text
POST /api/v1/mobile/owner-daily/casting-ingot
```

提交字段：

```text
business_date
ingot_count
input_tons
output_tons
exception_note
```

如果现有每日一录接口已经能承载，则优先复用现有接口，不单独新建路由。

## 后端执行阶段

### 阶段 1：只读核对

目标：确认 MES 下机记录、冷轧道次、热轧/铸轧坯料卷是否稳定可用。

验证：

- 抽取最近 100 条 MES 工序记录。
- 统计有机台名的比例。
- 统计有下机重量的比例。
- 统计能匹配到本系统机台的比例。
- 找出不能匹配的机台名，补别名。
- 抽取冷轧随行卡，核对每卷是否能还原道次。
- 抽取热轧、铸轧记录，核对是否有坯料卷号、重量、机台、时间。
- 核对 07:30 和 09:30 两种业务日窗口对日报数字的影响。

通过标准：

- 下机重量完整率达到可用水平。
- 高可信或中可信机台匹配率达到现场可接受水平。
- 未匹配原因能列清楚。
- 冷轧道次能按随行卡稳定归集。
- 热轧、铸轧坯料卷数据能说明来源和单位。

### 阶段 2：后端待补录服务

目标：按机台返回待补录卷材列表。

验证：

- 同一业务日只返回当前机台范围。
- 已补录卷材不再出现在待补录列表。
- MES 延迟或无数据时返回空列表，不报错。
- 机台不一致时返回风险标记。
- 冷轧待补录能定位到具体道次。
- 热轧、铸轧待补录能显示坯料卷。

### 阶段 3：手机端简化补录

目标：手机端显示“待补录列表”，点选后只填 MES 没有的字段。

验证：

- 不再要求正常流程第二次扫随行卡。
- 没有质量问题时可以一键确认。
- 有问题时可以展开补充。
- 找不到卷材时仍可扫随行卡兜底。
- 铸锭角色可按每日一录填写块数、投料量、下机量。
- 补录业务日按 09:30 切换。

### 阶段 4：管理端对账

目标：管理端能看懂 MES 主账、手机补录、差异。

验证：

- 填报明细不把 MES 原始记录当成人工填报。
- 能看到哪些 MES 下机记录尚未补录。
- 能看到机台匹配失败原因。
- 能看到 MES 值和人工补录字段。
- 能看到冷轧每卷道次链路。
- 能看到热轧、铸轧坯料卷参考。
- 能看到铸锭每日汇总。
- 能看到吨耗、成品率、废料率等自动计算指标。

### 阶段 5：灰度切换

目标：把主操产量填报逐步从“人工录产量”切到“MES 产量主账 + 人工补录”。

验证：

- 先开一个车间或一类工序。
- 连续观察 3-7 天。
- 如果缺失、错配、延迟都可控，再扩大范围。

## 不做的事

- 不让手机端直接连接 SQL Server。
- 不把 MES 数据写回 MES。
- 不删除现有扫码随行卡兜底入口。
- 不立刻删除旧字段和旧表。
- 不把 MES 原始数据混进“人工填报明细”。
- 不让前端用假动画掩盖后端数据延迟。
- 不把冷轧每道次产量重复累加成全厂总产量。
- 不在未核对清楚前把热轧、铸轧坯料卷直接当最终产量。
- 不让铸锭每日汇总混入卷材级填报明细。

## 风险和处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| MES 机台名不完整 | 待补录挂错机台 | 用别名映射和匹配等级控制 |
| MES 保存延迟 | 手机端暂时看不到刚下机卷材 | 保留扫随行卡兜底 |
| 同一车间多条相似线 | 自动匹配不准 | 中可信时让主操点选 |
| MES 重量录错 | 日报主口径受影响 | 管理端做差异和审批纠偏 |
| 手机补录漏填 | 现场字段缺失 | 待补录列表保留未完成状态 |
| 旧报表仍读手机产量 | 数字口径不一致 | 阶段 4 统一管理端展示 |
| 冷轧道次重复统计 | 车间产量虚高 | 道次只算过程产量，不算全厂最终产量 |
| 热轧/铸轧坯料单位不清 | 吨数错误 | 只读核对单位后再展示 |
| 09:30 口径和旧 07:30 口径冲突 | 日报边界跳数 | 先做双窗口对照，再切换 |
| 自动计算指标来源混乱 | 管理端不可信 | 指标标明 MES、补录、系统计算来源 |

- 冷轧道次按随行卡归集。

- 扫随行卡兜底仍可用。

- 铸锭角色显示每日汇总字段。

## 验收标准

- 正常流程下，主操不需要在手机端第二次扫随行卡。
- 手机端能按当前机台看到待补录卷材。
- 产量主账来自 MES，不再靠手机端重复输入。
- 手机端仍能补 MES 没有的字段。
- 管理端能区分 MES 主账、手机补录、差异纠偏。
- 出错时有兜底路径，不阻断现场填报。
- 冷轧能看到每卷道次链路。
- 热轧、铸轧能看到 MES 坯料卷参考或主数据。
- 铸锭有每日汇总角色和三个核心字段。
- 补录周期按 09:30 到次日 09:30。
- 自动计算指标能在管理端合适位置展示，并标明来源。

## 推荐下一步

先执行阶段 1：只读核对 MES 最近工序记录、冷轧道次、热轧/铸轧坯料卷。

如果数据证明 MES 机台名和下机重量可用，再进入阶段 2 和阶段 3。

如果阶段 1 发现 MES 机台名缺失严重，就先补机台别名映射，不急着改手机端。

如果 09:30 业务日与历史 07:30 报表差异较大，先让补录端按 09:30 运行，管理端主报表保留双窗口对照，确认后再统一切换。
