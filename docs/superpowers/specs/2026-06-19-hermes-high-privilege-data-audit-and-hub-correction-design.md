# Hermes 高权限数据核验与数据中枢修正通道设计

日期：2026-06-19

## 1. 一句话目标

先不做统一事实包。

先让 Hermes 拥有足够高的读写能力，直接核验三边数据：

```text
MES 原始数据
数据中枢当前数据
D:\输出skill 历史成品
```

Hermes 要先找出数据到底哪里不准、谁更可信、需要修哪张表、哪个字段、哪条映射规则。

小白版理解：现在不是先把数据包装成一个漂亮结果，而是先让 Hermes 当“高权限数据侦探”，把错账查清楚。

## 2. 已确认的现实情况

### 2.1 系统边界

- `鑫泰铝业 数据中枢` 不是 MES。
- MES 是外部生产系统和外部数据源。
- 数据中枢可以同步、补齐、修正、重算、发布自己的业务数据。
- Hermes 是多 Agent 平台里的高权限执行者，最终日报、核验、修正建议和外发动作都可以由 Agent 完成。

### 2.2 云端核验证据

本轮只读核验过以下事实：

| 项 | 结果 |
|---|---|
| 数据中枢云端 | `xtmijd.com` 可登录，管理端可用 |
| 数据中枢健康检查 | `/api/v1/readyz` 返回 ready |
| MES 同步状态 | `sqlserver / fresh / success` |
| MES 站点 | `mes.xintaily.com` 可登录，能看到合同、投料、包装统计等模块 |
| MES SQL Server | 只读可连，关键表不是空库 |
| 输出 skill | `D:\skill` 为空，真实成品目录是 `D:\输出skill` |
| 输出 skill 最新日报 | 2026-06-18 有日报正文、核对记录、Excel 和图片输入 |
| 输出 skill 对齐页 | 云端已挂载参考目录，能看到 3 个可解析文件和 16 张系统源表 |

### 2.3 已发现的核心断点

2026-06-18 这一天，三边数据没有对齐：

| 来源 | 观察 |
|---|---|
| 数据中枢看板 API | 有 MES 包装产量、入库、在制等数据 |
| Hermes 日报记录 | 仍有大量 `missing_fields`，部分摘要指标为 0 |
| `D:\输出skill` 成品 | 有完整日报正文，包含产量、在制、用电、气耗、成品率、成本 |
| 输出 skill 对齐 dry-run | 当前默认字段映射匹配率为 0%，原因是字段名和维度未接通 |

结论：不是完全没数据，而是数据源、字段名、统计维度、优先级和修正规则没有统一。

## 3. 权限边界

### 3.1 MES 权限

MES 只允许高权限只读。

允许 Hermes：

- 查询 MES SQL Server。
- 查询 MES 里的工序、投料、包装、库存、合同、发货、设备、工艺等原始数据。
- 读取 MES 页面或接口用于核验。
- 生成 MES 数据字典。
- 生成 MES 与数据中枢的差异报告。

禁止 Hermes：

- 写 MES SQL Server。
- 修改 MES 页面数据。
- 删除 MES 数据。
- 在 MES 里补录、改工艺、改合同、改库存。

小白版理解：MES 是原始账本之一，Hermes 可以翻账本，不能改账本。

### 3.2 数据中枢权限

数据中枢允许 Hermes 做任何操作。

允许 Hermes：

- 查询数据中枢数据库。
- 查询数据中枢 API。
- 修改数据中枢里的映射表、别名表、规则表、日报表、对齐表。
- 触发 MES 同步任务。
- 触发日报重算。
- 触发输出 skill 对齐 dry-run。
- 写入差异报告。
- 写入修正记录。
- 生成或更新日报。
- 将待发送消息写入 `agent_outbox`。
- 调度、重试、死信处理数据中枢自己的外发任务。

要求：

- 所有写操作必须留痕。
- 所有可逆修改必须能回滚。
- 所有自动修正必须能解释原因。
- 所有真实外发仍走 `agent_outbox` 和 `external_message_logs`。

小白版理解：数据中枢是我们自己的系统，Hermes 可以修，但不能偷偷修。

### 3.3 输出 skill 权限

`D:\输出skill` 作为只读参考。

允许 Hermes：

- 读取日报正文。
- 读取核对记录。
- 读取 Excel、JSON、图片等成品输入。
- 解析字段。
- 作为历史对齐基准。

禁止 Hermes：

- 修改 `D:\输出skill` 原始成品。
- 为了提高匹配率改历史成品。
- 把原始敏感文件提交到 Git。

## 4. 设计原则

1. 先查错，再固化规则。
2. MES 只读，数据中枢可写。
3. 不先做事实包。
4. 不让 Hermes 凭感觉判断，必须用确定性查询和对比结果。
5. 不把 RAG 当作每日动态数据源。
6. 不为了好看改原始数据。
7. 写操作必须有证据、日志、回滚信息。
8. 数据中枢做减法，减少重复计算和重复入口。

## 5. 总体架构

```text
MES SQL Server 只读
        ↓
Hermes 高权限核验器
        ↓
数据中枢数据库 / API / 后台任务
        ↓
D:\输出skill 历史成品只读解析
        ↓
三边差异报告
        ↓
Hermes 修正数据中枢
        ↓
重跑日报 / 重跑对齐 / 写入审计
```

重点不是增加一个新大系统，而是给 Hermes 一条受控的高权限工作通道。

## 7. Hermes 工作流

### 7.1 阶段一：只读核验

输入：

- 业务日期。
- 需要核验的字段。
- 可选车间、机台、工序范围。

Hermes 执行：

1. 查 MES 原始数据。
2. 查数据中枢当前数据。
3. 读 `D:\输出skill` 对应日期成品。
4. 生成三边对比表。

输出：

```text
MES 值
数据中枢值
输出 skill 值
差异
可能原因
推荐修正动作
可信度判断
```

### 7.2 阶段二：修正数据中枢

Hermes 可以对数据中枢执行修正。

修正类型：

| 类型 | 例子 |
|---|---|
| 字段映射修正 | `total_electricity_kwh` 对应 `energy_kwh` |
| 单位修正 | kg 转吨 |
| 车间别名修正 | `精整车间` 对齐 `精整` |
| 班次别名修正 | `白班` 对齐 `长白班` |
| 业务日修正 | 自然日改成生产业务日 |
| 设备绑定修正 | MES 里的 `PC` 绑定到真实机列 |
| 日报重算 | 修正后重新生成日报 |
| 对齐记录保存 | 保存 dry-run 和最终对齐结果 |

修正要求：

```text
改前值
改后值
修正原因
证据来源
执行人 / Agent
执行时间
回滚方式
```

### 7.3 阶段三：重跑与验收

Hermes 修正数据中枢后，必须重跑：

1. MES 同步或投影刷新。
2. 输出 skill 对齐 dry-run。
3. 日报生成。
4. Agent 审计记录。

如果匹配率没有提升，Hermes 必须输出失败原因，不能假装成功。

## 8. 数据中枢做减法

当前不应该重写系统。

应该减少这些重复：

| 问题 | 减法方向 |
|---|---|
| 多个服务各算一套产量 | 收口到同一套核验规则 |
| 日报、看板、对齐页字段名不一致 | 统一字段映射表 |
| RAG 里混入动态数字 | RAG 只放规则和字典 |
| 页面有数但 Hermes 缺字段 | 让 Hermes 直接查源表和对齐结果 |
| dry-run 能跑但字段对不上 | 补默认字段映射和解析规则 |
| Agent 通道演练与正式混淆 | 明确演练、待发送、真实发送状态 |

## 9. 第一批关键字段

第一期只抓最影响日报可信度的字段。

| 字段 | 优先核验来源 |
|---|---|
| 全厂总产量 | 输出 skill、MES 包装/入库、数据中枢日报 |
| 车间产量 | MES 工序、输出 skill 产量表、数据中枢投影 |
| 在制料 | MES 库存/在制、输出 skill 次晨截图/记录、数据中枢在制表 |
| 入库量 | WMS 入库、输出 skill 正文、数据中枢日报 |
| 用电 | 输出 skill 能耗表、数据中枢能耗表 |
| 天然气 | 输出 skill 天然气表、数据中枢能耗表 |
| 成品率 | 输出 skill 成品率表、数据中枢成品率计算 |
| 合同量 | MES 合同/发货、输出 skill 合同表、数据中枢看板 |
| 吨成本 | 输出 skill 成本公式、数据中枢成本表 |

## 10. 输出 skill 对齐规则

当前云端 dry-run 已证明：

- 输出 skill 文件能解析。
- 系统行能拉到。
- 但默认字段匹配没有接通。

第一批需要补的映射：

| 输出 skill 字段 | 数据中枢字段方向 |
|---|---|
| `total_electricity_kwh` | `energy_kwh` / 高压总用电 |
| `total_gas_m3` | `gas_m3` / 天然气合计 |
| `wip_total` | `wip_tons` |
| 正文“车间总产量” | 全厂产量 |
| 正文“入库成品日合计” | 入库量 |
| 正文“日成品率” | `yield_rate` |
| 正文“当天接合同” | 合同量 |
| 正文“总余合同量” | 剩余合同量 |

对齐结果必须分类：

```text
完全匹配
单位差异
日期差异
车间别名差异
班次别名差异
字段缺失
系统多行
输出 skill 多行
算法口径差异
无法判断
```

## 11. 审计与回滚

Hermes 对数据中枢的写操作必须进入审计。

建议记录结构：

```json
{
  "actor": "hermes",
  "operation": "update_mapping_rule",
  "target_table": "master_code_aliases",
  "target_key": "...",
  "before": {},
  "after": {},
  "reason": "输出skill与MES车间别名不一致",
  "evidence": {
    "mes_query": "...",
    "hub_query": "...",
    "output_skill_file": "2026-6-18_核对记录.txt"
  },
  "rollback_available": true,
  "created_at": "..."
}
```

敏感信息不能写入审计正文：

- 数据库密码。
- 连接串。
- Token。
- 钉钉 secret。
- Webhook 明文。

## 12. 安全控制

即使 Hermes 能对数据中枢做任何操作，也需要这些保护：

| 控制 | 说明 |
|---|---|
| MES 只读账号 | Hermes 不能写 MES |
| 查询日志 | 记录 Hermes 查过什么 |
| 写操作审计 | 记录 Hermes 改过什么 |
| 回滚记录 | 关键修正可撤回 |
| 外发走 outbox | 不绕过外部通讯治理 |
| 敏感信息脱敏 | 不把密码和 token 写入日志 |
| 大查询限制 | 防止一次拉爆数据库 |
| 操作分级 | 普通修正规则可自动执行，高风险发布可进入审批 |

## 14. 成功标准

第一阶段成功标准：

| 项 | 标准 |
|---|---|
| MES 查询 | Hermes 能只读查关键 MES 表 |
| 数据中枢操作 | Hermes 能修改数据中枢规则和触发重算 |
| 输出 skill 解析 | 近 3 天日报正文和核对记录可解析 |
| 对齐率 | 关键字段从当前 0% 提升到 85%+ |
| 差异解释 | 未对齐字段必须有原因分类 |
| 审计 | Hermes 写操作有改前、改后、原因、证据 |
| 回滚 | 映射和规则类修改可回滚 |

第二阶段再追求：

```text
关键字段 95%+ 同口径匹配
日报正文与输出 skill 高相似
Hermes 能自动指出当天缺哪类数据
Hermes 能自动修正数据中枢低风险映射问题
```

## 15. 不做的事

本设计不做：

- 不让 Hermes 写 MES。
- 不先做统一事实包。
- 不重写整个数据中枢。
- 不训练或微调模型。
- 不把每日动态数字塞进 RAG 当事实。
- 不修改 `D:\输出skill` 历史成品。
- 不绕过 `agent_outbox` 真实外发。
- 不为了匹配率静默覆盖原始数据。

## 16. 推荐实施顺序

1. 给 Hermes 增加 MES SQL Server 只读查询能力。
2. 给 Hermes 增加数据中枢高权限操作能力。
3. 给 Hermes 增加 `D:\输出skill` 只读解析能力。
4. 做 2026-06-16 到 2026-06-18 三天三边对比。
5. 补输出 skill 字段映射和维度别名。
6. 允许 Hermes 修正数据中枢映射表和规则表。
7. 重跑 dry-run，对齐率提升到 85%+。
8. 重跑日报，检查 Hermes 输出是否接近 `D:\输出skill` 成品。
9. 把所有写操作纳入审计和回滚。
10. 再决定是否进入统一事实包阶段。

## 17. 最终判断

当前最大问题不是 Hermes 不够会写，而是 Hermes 没有足够权力和工具去查清原始数据。

所以第一阶段要把 Hermes 从“日报生成者”升级为：

```text
高权限数据核验者
数据中枢修正执行者
输出 skill 对齐审计者
```

等 Hermes 把数据查准、规则修准、历史三天对齐通过后，再考虑是否建设统一事实包。
