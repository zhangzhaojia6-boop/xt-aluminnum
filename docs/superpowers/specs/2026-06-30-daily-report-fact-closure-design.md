# 日报事实闭环与 Hermes 增强设计

日期：2026-06-30

状态：方案 B 已确认 / 进入实施

适用项目：`鑫泰铝业 数据中枢`

## 目标

本轮不重写系统，也不新增日报门户。

目标是把现有主链路打通：

```text
D:\输出skill 真实日报样本
  -> 字段级差异
  -> 缺口归因
  -> 钉钉 / MES 只读 / 扫码补录 / root_owner 修正
  -> DailyFactBundle
  -> Hermes 判断和 trace
  -> /manage 可见
```

## 一行行系统架构

1. 一线人员扫码进入 `/entry`。
2. `/entry` 负责补 MES 没有或不适合直接当最终日报的数据。
3. 管理人员进入 `/manage`。
4. `/manage` 是大仪表盘主线，不再新增平行门户。
5. 前端只调 FastAPI 后端接口。
6. 后端保存扫码填报、钉钉证据、MES 投影、历史日报和日报事实包。
7. MES/WMS 是外部只读来源，不是本产品名字。
8. 钉钉群文件和聊天内容是最高优先级事实入口。
9. DailyFactBundle 汇总 MES、钉钉、扫码补录、历史日报和 root_owner 修正。
10. 日报正文只能从事实包渲染，不能让模型猜数字。
11. `D:\输出skill` 的日报正文 txt 是验收标尺，不反向改生产数据。
12. Hermes 对外身份是 `鑫泰铝业智能大脑`，只用中文。
13. Hermes 要主动查证、判断冲突、留下追踪编号并推动补齐。
14. 普通生产业务日按 `07:50-07:50`。
15. 铸二、铸三、热轧按 `10:00-10:00`。
16. 内勤每日一录按 `09:30` 归属业务日。

## 软件减法

本轮不做：

- 不新建第二套日报系统。
- 不新建第二套数据中枢。
- 不新增大页面。
- 不删除生产证据、审计、trace、MES/WMS、钉钉或 DailyFactBundle 链路。

本轮只增强：

- 日报缺字段和差异字段的归因。
- 对齐脚本的可读输出。
- Hermes 可以读取的事实缺口计划。

## 智能体加法

Hermes 增强方向：

1. 能看到字段为什么缺。
2. 能知道缺口该找钉钉、MES、扫码补录还是 root_owner。
3. 能把缺口推进成下一步动作。
4. 保持消息识别宽松，不把口语、错别字、省略句挡掉。
5. 保持高自主，但所有事实写入和修正必须有来源、trace 和回滚线索。

## 验收标准

1. 最近 3 到 5 个已完成业务日能用 `D:\输出skill` 跑字段级对齐。
2. 对齐失败时，输出字段级缺口计划，不只给百分比。
3. 缺字段能分到 `dingtalk_evidence`、`mes_readonly`、`scan_fill`、`computed_or_root_owner` 等行动方向。
4. DailyFactBundle 返回 `gap_plan`。
5. Hermes 通过数据中枢工具可看到缺字段、来源和下一步。
6. 业务时间测试继续通过。
7. 不新增入口，不破坏 `/entry`、`/manage`、MES 只读、钉钉和 trace。
