# 数据中枢整体改造设计

日期：2026-11-08

状态：待负责人审阅

适用产品：`鑫泰铝业 数据中枢`

## 1. 总目标

沿用 2026-08-14 已批准、2026-10-31 负责人再次确认的「去统计流」目标：

```text
每天 10:00 自动发出事实完整、来源可查的 127 项正式日报；
人工只确认机器无法知道的现场事实和高风险冲突。
```

前后端改造服务这个目标。能让日报发出去的先做，其余后做。

不变的底线：

- 127 项字段合同不减。
- MES 只读。
- 缺数就显示缺，不估算，不用历史值或 `0` 代替。
- `D:\输出skill` 只作比对，不作事实源。
- 每个数字可追溯到来源和 trace。
- 真实外发保持演练模式；第一次给真实员工发钉钉前，内容先给负责人过目。

## 3. 方案比较

| 方案 | 做法 | 优点 | 问题 |
|---|---|---|---|
| A 闭环优先，原地收口（采用） | 先恢复使用和补齐数据，再围绕真实使用收口页面和后端 | 每步都能用真实数据验收，可回滚，符合封档方向 | 前期界面变化小 |
| B 先重做管理端大仪表盘 | 先把前端收成一个大屏 | 看起来变化最大 | 数字还是缺，也没有用户数据判断哪些页面该留 |
| C 重写或拆分后端 | 重新划分 189 个服务 | 长期结构干净 | 风险最高，不增加任何一项日报数据，还可能伤到受保护主链 |

采用 A。B 的目标放到子项目 3 分步实现，C 只保留其中有依据的减量部分（子项目 4）。

## 4. 子项目拆分

按顺序做，上一个通过真实验收才进入下一个，每个子项目单独写实施计划。

### 子项目 0：恢复现场可用

目标：现场人员能再次扫码进入系统。

| 动作 | 负责 |
|---|---|
| 张贴 `D:\鑫泰智能车间\二维码-公网IP-20261102.pdf`，先试扫一张，再撤掉旧码 | 现场 |
| 把钉钉后台应用首页地址改成 `https://8.140.218.13` | 负责人 |
| 询问 8 月下旬使用量下滑的原因 | 负责人 |
| 观察扫码登录恢复情况，每天报告 | 系统 |

验收：连续 3 个工作日有真实扫码登录，且覆盖原有活跃岗位。

### 子项目 1：日报闭环

目标：缺口持续缩小，晚到的数据能反映到日报。

| 项 | 内容 |
|---|---|
| 修复迟到数据 | 10:00 后缺口复查发现事实变化时，重写日报记录的内容和缺口，不触发投递；投递条件不变 |
| 能耗 48 项 | 能源统计员每天把两张表私聊发送；首份到达后用 `backend/scripts/register_energy_file_sender.py` 登记，写库前备份 |
| 车间产量 30 项 | 各车间给出统计口径后逐个接入，决策写入 ADR；口径未定的保持缺失 |
| 回收、磨辊、外加工、寄存 | 确定责任人，走子项目 2 的精准补录 |
| 字段责任表 | 把 127 项的来源、责任人、截止时间统一到一份合同，供日报、Hermes、`/entry` 共用 |
| 追缺消息 | 缺口事件按责任人合并成一条消息，先演练；样稿经负责人过目后，只对第一位责任人开启真实发送 |

验收：

- 迟到数据测试：表晚到后日报记录缺口下降，且没有新增外发。
- 第一阶段：适用字段自动取得率 ≥ 80%，关键字段真实来源覆盖 100%。
- 全过程不调整 127 分母。

### 子项目 2：精准补录

目标：责任人从钉钉链接点开，只看到这次要补的字段，1 分钟内提交。

- 复用 `/entry/fill` 和 `UnifiedEntryForm`，不新建表单系统。
- 按链接参数只显示目标字段及后端必填的依赖字段。
- 接入已有草稿和弱网队列，班次提交收口为一次请求，重复提交不重复入账。
- 提交后触发目标日期事实刷新，关闭已满足的缺口。

验收：8/14 SPEC 第 6.1 节的指标（3 秒可填写、2 秒返回、数据丢失 0、重复入账 0），用手机真机和弱网各测一次。

### 子项目 3：管理端收口

目标：管理者打开 `/manage/today` 就能看完全局、来源状态和异常。

- 一级入口收到 5 个：`/manage/today`（大仪表盘）、`/manage/live`、`/manage/production`、`/manage/coils`、`/manage/alerts`。
- 其余页面先退到设置抽屉，路由保留，登记到 `docs/datahub-deprecation-register.md`。
- 用现有 telemetry 统计页面访问，满 14 天无访问且无依赖的才进入候选删除。
- 数字统一显示 `confirmed`、`candidate`、`missing`、`conflict` 状态和来源入口，不加解释文案。
- 视觉方向在本子项目的设计阶段用真实页面出样，负责人选定后再实施。

依赖：必须在子项目 0 恢复使用之后开始，否则没有访问数据作判断。

验收：今日页 3 秒内出现关键结果，每个关键数字能点到来源；按 AGENTS.md 核对云端构建文件、实际返回的资源和 Service Worker。

### 子项目 4：后端减量

目标：减少未被使用的服务和接口，不动受保护主链。

- 受保护：`DailyFactBundle`、MES/WMS 只读链路、钉钉证据、Hermes 依赖链、审计、trace。
- 候选来自调用分析和访问日志，先冻结观察 7 到 14 天，再合并或删除。已知线索：铝价抓取每天报错且只有 `/executive` 读取；`views/reports/LiveDashboard.vue` 4029 行需核对是否仍在使用。
- 不删生产表、原始证据和审计日志。

验收：后端全量测试通过；每项减量都有依赖核对和回滚方式。

### 暂不做

- 系统判定开停机（8/14 阶段 4）：不在 127 项合同内，不阻塞日报，放到日报闭环通过之后。
- Hermes 自我成长和两个已暂停的定时任务：保持暂停，不修它们的模型。
- 网页 AI（PR #83）：原定稳定期结束后决定。它不阻塞日报，放到子项目 3 一并判断。

## 5. 错误处理和回滚

| 场景 | 处理 |
|---|---|
| 来源晚到或缺失 | 保持缺失，15 分钟复查自动补入 |
| 来源冲突 | 按字段来源优先级裁决，写入 trace；超限转人工 |
| 部署异常 | 走 `deploy_ff.sh`（备份、ff-only、重启、readyz），回退到上一提交 |
| 写生产库 | 先备份并留 trace |
| 页面收口后有人需要 | 路由保留，改回导航配置即可恢复 |
| 真实发送出问题 | 恢复 `DINGTALK_NOTIFY_DRY_RUN=true` 和渠道演练设置 |
