# Hermes 知识库成型与数据中枢减法瘦身设计

日期：2026-06-25

状态：正式 spec

## 1. 一句话目标

下一阶段不再继续堆新功能。

目标是让 Hermes 更像真正的工厂超级大脑：

```text
先知道每个数从哪里来
再知道哪些知识能解释这些数
最后再帮数据中枢减掉重复、过期、低价值的东西
```

通俗说：

```text
先把脑子的知识和证据整理清楚，再给身体减肥。
```

## 2. 背景

当前 Hermes 工厂大脑已经具备这些基础能力：

- 自然语言入口。
- 长期规则。
- DingTalk 四条件采样。
- 日报事实包。
- 历史日报、月累计、年累计和经营分析底座。
- 专业知识库表。
- LangChain 工具层。
- LangGraph 编排层。
- Codex 施工记录。
- 生产灰度能力。

但要继续变强，还有三个核心问题：

1. Hermes 知识库还没有形成稳定的工厂知识体系。
2. Hermes 回答时还不一定能清楚说出每个关键数字的来源链路。
3. 数据中枢已经积累了旧页面、旧路由、旧文档、旧报表加工层，不能一直变胖。

本 spec 解决的不是“多加几个命令”，而是把 Hermes 和数据中枢整理到一个能长期成长的结构里。

## 3. 核心决定

### 3.1 先做知识库和事实来源地图，再做删除

不能直接开始大删代码、大删表、大删页面。

正确顺序是：

```text
事实来源地图
  -> Hermes 知识库种子
  -> 数据中枢减法审计
  -> 冻结/合并/降级
  -> 灰度观察
  -> 最后删除
```

原因很简单：

```text
如果不知道某个页面、接口、表、字段是不是还在喂 Hermes，就不能删。
```

### 3.2 数据中枢减法先从“报表加工层”和“旧入口”开始

优先减这些：

- 重复日报加工逻辑。
- 重复看板取数逻辑。
- 旧管理入口。
- 旧移动入口。
- 旧参考页。
- 过期文档。
- 已被 DailyFactBundle 替代的中间拼装逻辑。

暂时不能减这些：

- MES/WMS 本地投影。
- 原始证据。
- 审计日志。
- DingTalk 消息和文件证据。
- DailyFactBundle 快照。
- 历史日报。
- root_owner 修正记录。
- LangGraph checkpoint。
- Codex 施工记录。

### 3.3 Hermes 知识库只放“知识”，不放每日实时数字

RAG 和专业知识库负责解释：

- 铝加工通用知识。
- 鑫泰现场工艺。
- 指标口径。
- 字段含义。
- 表关系。
- 异常案例。
- 日报输出规则。

不能把下面这些当知识塞进 RAG：

```text
今天总产量 239.55 吨
6月19日成品入库 366 吨
2050 今天产量 80 吨
```

每日实时数字应该进入：

- DailyFactBundle。
- 历史日报。
- 事实快照。
- 审计记录。
- DingTalk 证据。

### 3.4 DingTalk 是高优先级补充数据

DingTalk 文本、文件、图片、表格可以成为高优先级补充来源，但必须满足四个条件：

```text
授权群
专项责任人
内容类型
时间范围
```

四个条件不全时，只能作为普通线索，不能直接覆盖正式事实。

### 3.5 数据中枢可以被 Hermes 修正，但必须可追溯

root_owner 张兆嘉可以授权 Hermes 对数据中枢做写入、修正、归档、降级、冻结、删除。

但每次动作都必须留下：

- 谁授权。
- 改了什么。
- 改前值。
- 改后值。
- 采用原因。
- 原始证据。
- trace_id。
- 回滚办法。

MES 和 WMS 继续保持高权限只读。

## 4. 成功标准

这一阶段完成后，要达到这些结果：

1. Hermes 能回答“这个数从哪里来的”。
2. Hermes 能把日报、异常、经营问答里的关键数字连到来源链路。
3. Hermes 专业知识库至少有第一批正式知识单元。
4. 知识单元能区分通用工业知识、鑫泰现场工艺、字段、规则、案例和输出口径。
5. DingTalk 文件和文本能进入候选知识或事实证据，但不会无条件覆盖正式事实。
6. 数据中枢有一份明确的减法审计报告。
7. 每个被建议减掉的页面、接口、服务、表、文档都有分类原因。
8. 没有任何生产数据表被直接删除。
9. 没有任何 Hermes 依赖链路被误删。
10. Hermes 通过至少 20 条自然语言问题测试。

## 5. 总体架构

```text
MES / WMS / 数据中枢 / DingTalk / 历史日报 / 输出 skill
        |
        v
事实来源地图
        |
        +--> DailyFactBundle
        +--> Hermes 工具调用
        +--> Hermes 来源解释
        |
        v
专业知识库
        |
        +--> 通用铝加工知识
        +--> 鑫泰现场工艺
        +--> 字段和表关系
        +--> 指标口径
        +--> 异常案例
        +--> 输出模板
        |
        v
数据中枢减法审计
        |
        +--> 保留
        +--> 合并
        +--> 冻结
        +--> 候选删除
```

## 6. 事实来源地图

事实来源地图要回答一个问题：

```text
这个指标从哪里来，经过哪些代码和表，最后在哪里展示或被 Hermes 使用？
```

每条记录至少包含：

| 字段 | 含义 |
|---|---|
| `metric_key` | 机器可读指标名，比如 `total_output_daily` |
| `display_name` | 人能看懂的名字，比如 `车间总产量日合计` |
| `domain` | 生产、经营、能耗、库存、质量、工艺 |
| `priority_sources` | 事实优先级 |
| `source_tables` | 涉及表 |
| `source_services` | 涉及后端服务 |
| `api_routes` | 涉及接口 |
| `frontend_pages` | 涉及页面 |
| `hermes_tools` | Hermes 会调用的工具 |
| `delete_protection` | 是否禁止删除 |
| `known_risks` | 已知风险 |
| `verification_status` | 已证实、候选、待复核 |

第一批必须覆盖：

- 总产量。
- 入库成品。
- 各车间产量。
- 在制料。
- 用电。
- 用气。
- 吨耗。
- 合同。
- 投料。
- 成品率。
- 成本核算。
- 月累计。
- 年累计。
- 异常说明。

## 7. 知识库设计

### 7.1 六层知识库

Hermes 知识库按六层建设：

| 层 | 内容 |
|---|---|
| A | 铝加工通用工业知识 |
| B | 鑫泰现场个性化工艺知识 |
| C | 数据中枢字段和表关系 |
| D | MES/WMS 外部系统字段知识 |
| E | 历史日报和输出 skill 口径 |
| F | 典型异常案例 |

### 7.2 六类知识单元

每条知识不要按整篇文档粗塞，要拆成小单元：

| 类型 | 例子 |
|---|---|
| 工艺单元 | 冷轧 1650、1850、2050 的工艺差异 |
| 指标单元 | 吨电耗、成品率、入库、投料的定义 |
| 字段单元 | `mes_workshop_process_records.output_weight_tons` 的含义 |
| 规则单元 | DingTalk 专项责任人文件优先级 |
| 案例单元 | 2050 电耗异常的历史原因 |
| 输出口径单元 | 日报先总后分、再能耗、合同、成品率、成本 |

### 7.3 知识状态

知识有三种状态：

| 状态 | 含义 |
|---|---|
| 候选知识 | Hermes 从数据、文档、DingTalk、历史日报里总结出来，未验证 |
| 正式知识 | Codex 或 root_owner 验证通过，可用于正式回答 |
| 废弃知识 | 已过期、不准、冲突或不再适用 |

候选知识不能直接当最终规则。

## 8. 数据中枢减法分类

### 8.1 保留

必须保留：

- `/manage/today` 日报工作台。
- `/manage/live` 生产实时大屏。
- `/manage/production` 生产分析。
- `/manage/coils` 卷级线索。
- `/entry/*` 手机填报。
- DingTalk 入站和外发日志。
- Hermes 工厂大脑。
- DailyFactBundle。
- RAG 和专业知识库。
- MES/WMS 本地投影。
- 审计日志。
- 历史日报。

### 8.2 合并

优先合并：

- 多个日报事实拼装入口。
- 多个产量来源解释逻辑。
- 多个历史日报查询逻辑。
- 多个相似的管理端概览卡片。
- 重复的旧命令入口。

### 8.3 冻结

可以先冻结：

- 旧 `/review/*` 入口。
- 旧 `/admin/*` 入口。
- 旧 `/mobile/*` 入口。
- 未挂载生产的参考页面。
- 过期计划文档。
- 旧 smoke 脚本。

冻结表示：

```text
不再新增功能，只保留兼容和跳转。
```

### 8.4 候选删除

只有同时满足下面条件，才进入候选删除：

1. 没有生产路由引用。
2. 没有前端导航引用。
3. 没有 API 调用引用。
4. 没有测试依赖。
5. 没有 Hermes 工具依赖。
6. 没有 DailyFactBundle 依赖。
7. 没有历史二维码或收藏入口风险。
8. 已有回滚方式。

本阶段只产出候选删除清单，不直接大规模删除。

## 9. Hermes 回答质量要求

Hermes 回答不能只给一个数字。

标准回答结构：

```text
结论
关键数字
来源
冲突
缺口
建议动作
trace_id
```

例子：

```text
结论：今天全厂产量已出，当前可信值为 239.55 吨。
来源：DailyFactBundle -> template_daily_report -> MES 包装量投影。
冲突：暂未发现高优先级 DingTalk 修正。
缺口：若要出正式日报，还需要核对入库、能耗和成本字段。
建议：先跑日报事实包对齐，再生成正式日报草稿。
trace_id：xxx
```

## 10. 第一批验收问题

至少用这些问题测试 Hermes：

```text
今天产量出来了吗？
今天这个数从哪来的？
生成昨天日报草稿。
6月19日正式日报和历史成品能对齐吗？
2050 今天吨电耗为什么高？
今天生产和发货会不会影响合同交付？
本月经营情况怎么样？
今年累计产量和成本趋势怎么样？
哪个车间今天异常最大？
这个钉钉文件能作为正式数据吗？
这个数能信吗？
如果 MES 和钉钉冲突，采用谁？
日报里的成品率怎么算？
入库和包装为什么不是一个数？
数据中枢哪些旧页面可以冻结？
哪些表绝对不能删？
哪些文档已经过期？
把今天日报按老板看的版本发我。
把这条规则记住，以后日报先看责任人文件。
现在你缺什么证据？
```

## 11. 非目标

本阶段不做：

- 直接删除生产表。
- 直接删除历史日报。
- 让前端直连 MES SQL Server。
- 把 MES/WMS 改成可写。
- 默认扫描所有 DingTalk 群。
- 把每日实时数字塞进 RAG。
- 大改前端视觉。
- 替换已有 Factory Brain 架构。
- 关闭旧命令 fallback。

## 13. 小白版总结

这一步不是让 Hermes 继续背更多台词。

这一步是让 Hermes 搞清楚三件事：

```text
我知道什么。
我为什么知道。
哪些旧东西可以慢慢拿掉。
```

数据中枢减法不是立刻删东西，而是：

```text
先贴标签，再观察，再合并，最后再删。
```

这样 Hermes 会越来越聪明，数据中枢也会越来越轻。
