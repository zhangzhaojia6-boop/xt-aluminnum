# Hermes 钉钉私聊与群聊权限设计

日期：2026-08-20

状态：已确认设计，待实施

## 1. 目标

在不限制钉钉群范围、不新建机器人实例的前提下，将 Hermes 的钉钉入口固定为：

- 张兆嘉和孟玉杰可以私聊机器人。
- 其他组织成员只能在群聊中真实 `@机器人` 使用。
- 张兆嘉继续是唯一最高权限负责人；孟玉杰获得私聊入口，但不继承系统和架构权限。

## 2. 稳定身份

权限只匹配钉钉稳定 `userid`，不使用姓名、昵称、手机号或手机号尾号。

| 人员 | 钉钉 `userid` | 私聊 | 系统与架构权限 |
|---|---|---|---|
| 张兆嘉 | `666327013924069283` | 允许 | root owner，保留现有最高权限 |
| 孟玉杰账号 1 | `076765530923422118` | 允许 | 不允许 |
| 孟玉杰账号 2 | `081323311123422118` | 允许 | 不允许 |

两个孟玉杰账号均由钉钉 CLI 查询为河南鑫泰铝业、人力资源科的“孟玉杰”，并按负责人确认同时授权私聊。

## 3. 选定方案

复用现有 NousResearch Hermes 钉钉适配器，增加独立的私聊白名单：

```text
DINGTALK_DM_ALLOWED_USERS=<张兆嘉 userid>,<孟玉杰 userid 1>,<孟玉杰 userid 2>
```

群聊授权与私聊授权分开：

```text
私聊消息
  -> 检查 DINGTALK_DM_ALLOWED_USERS
  -> 命中才进入 Hermes
  -> 未命中静默忽略

群聊消息
  -> 不检查私聊白名单
  -> 不设置群 ID 白名单
  -> 必须由钉钉结构化事件证明真实 @机器人
  -> 命中后进入 Hermes
```

## 4. 配置规则

- `DINGTALK_DM_ALLOWED_USERS`：固定为上述三个 `userid`。
- `DINGTALK_REQUIRE_MENTION=true`：所有群聊必须真实 `@机器人`。
- `DINGTALK_ALLOWED_CHATS` 保持为空：不建立硬群边界。
- `DINGTALK_FREE_RESPONSE_CHATS` 保持为空：没有免 `@` 群。
- `DINGTALK_ALLOW_ALL_USERS=true`：允许组织成员通过群聊进入网关；私聊仍由适配器的独立白名单先行拦截。
- 未授权私聊的行为固定为静默忽略，不返回配对码或提示消息。

## 5. 权限边界

私聊资格只代表可以和 Hermes 对话，不代表可以执行高权限操作。

- 张兆嘉继续通过数据中枢的 `HERMES_OWNER_DINGTALK_USER_IDS` 和现有 root owner 判定获得系统、架构及运维指令权限。
- 孟玉杰的两个 `userid` 不加入 root owner 配置，不获得系统改造、部署、架构变更或最高审批权限。
- 群聊用户只能使用普通 Hermes 能力；需要 root owner 的意图继续走现有服务端权限门禁。
- 不以提示词代替权限检查，权限必须在消息进入智能体执行链前由确定性代码判断。

## 6. 事实收集边界

钉钉消息进入鑫泰证据中继发生在回复权限判断之前，因此：

- 未授权私聊和未 `@` 的群消息仍可按现有授权范围留下来源 trace 和事实候选。
- 是否记录为正式事实继续遵循现有证据采用规则。
- 本设计只控制 Hermes 是否响应和执行，不改变日报事实优先级。

## 7. 失败处理与回滚

生产变更前备份：

- Hermes 钉钉适配器代码及对应运行环境。
- Hermes systemd 环境覆盖配置。
- 当前网关状态与钉钉 Stream 状态。

出现以下任一情况立即回滚：

- 张兆嘉或孟玉杰无法私聊。
- 其他人员仍能私聊。
- 群聊真实 `@机器人` 无响应。
- 未 `@` 的群消息触发机器人回复。
- 钉钉 Stream 未恢复为 `connected`。
- Hermes 主模型或降级模型探针失败。

## 8. 验收标准

自动化测试必须证明：

1. 三个白名单 `userid` 的私聊通过。
2. 白名单外 `userid` 的私聊被静默拒绝。
3. 白名单外用户在群聊真实 `@机器人` 时通过。
4. 群聊未 `@机器人` 时拒绝。
5. 群聊不受私聊白名单和群 ID 白名单限制。
6. 孟玉杰不被识别为 root owner。
7. 张兆嘉仍被识别为 root owner。

生产验收必须证明：

1. `hermes-gateway` 为 `active`。
2. 钉钉 Stream 为 `connected`。
3. 生效配置仅包含三个私聊 `userid`，且不输出任何密钥。
4. 使用合成事件分别跑通允许私聊、拒绝私聊、群聊有 `@`、群聊无 `@` 四条路径。
5. Luna 主模型与 Sol 自动降级链保持可用。

## 9. 不做什么

- 不新建第二个机器人或第二套 Hermes 服务。
- 不设置群 ID 白名单。
- 不按手机号尾号、姓名或昵称鉴权。
- 不把孟玉杰提升为 root owner 或数据中枢管理员。
- 不改变 MES、数据中枢、日报事实包和钉钉证据采用顺序。
