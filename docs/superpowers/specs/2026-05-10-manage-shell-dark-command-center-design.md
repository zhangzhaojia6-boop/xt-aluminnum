# 管理端深海工业指挥台重构设计

Date: 2026-05-10  
Status: 待用户审阅  
适用系统: 鑫泰铝业 数据中枢

## 1. 背景

这次重构不是重写业务能力，而是把现有 `/manage` 从“页面集合”改成“工业中枢”。目标图文件夹里的 6 张参考图已经给出足够明确的方向：

- 图 1 / 图 5：管理端大屏。共同特征是深色底、左侧固定导航、顶部状态带、密集 KPI、中心主画布、右侧事件/AI 侧栏、底部运行状态条。
- 图 2：经营驾驶舱。重点不是单个图表，而是指标条、趋势图、成本结构、排名、建议卡的并列编排。
- 图 3：移动端。说明系统品牌不能只靠桌面大屏成立，但本阶段不改移动端，只提炼同一套品牌语言。
- 图 4 / 图 6：能力蓝图。说明系统不是平铺菜单，而是按层级、职责和流向组织：总览层、业务层、AI 层、治理层、来源层。

结论很明确：第一阶段必须先把管理端的壳、导航和视觉秩序立住，再逐个页面收口。

## 2. 目标

1. `/manage` 首屏一眼看出这是 `数据中枢`，不是普通后台。
2. 管理端默认采用深色工业指挥屏风格。
3. 角色视角切换先做 UI 视角，不改真实权限边界。
4. 导航从平铺长菜单改成“少一级、多子模块”。
5. 管理端所有页面共享同一套壳层、状态条、模块标题和视觉语言。
6. 第一阶段只改 shell、导航和视觉 token，不碰后端权限、不增 API、不改路由名。

## 3. 非目标

- 不重写后端权限体系。
- 不新增 UI 框架。
- 不把管理端改成营销页或登录页风格。
- 不把 `数据中枢` 写成 `MES`。
- 不在第一阶段重做所有页面内容。
- 不在管理端使用大面积紫蓝渐变、玻璃拟态或模板式三卡片。

## 4. 视觉方向

方向名：**深海工业指挥台**。

这一版要留下的记忆点只有一个：

- 黑蓝近黑的全屏底面
- 蓝色运行线和高亮边
- 密集但有序的指标块
- 右侧 AI / 事件侧舱
- 底部状态条

设计原则：

- 用深色层级表达深度，不靠大阴影。
- 用状态色表达运行态，不靠长文案解释。
- 用小半径、细分割、紧凑网格表达工程感。
- 用真实业务名，避免“智能”“洞察”“next-gen”这类空词。

要避免的默认模式：

- 白底卡片堆叠
- 居中 hero
- 三段式大标题 + 副标题 + 两个 CTA
- 统一圆角、统一阴影的模板卡片墙
- 过亮的紫蓝渐变

## 5. 角色视角

这里的“角色视角”是 UI 镜头，不是新的权限系统。真实访问仍沿用当前 `review/admin` 边界。

| 视角 | 默认落点 | 优先看到的模块 | 作用 |
|---|---|---|---|
| 总览视角 | `/manage/overview` | 工厂总览、生产指挥、经营与交付、AI 助手 | 给管理层看全局 |
| 生产视角 | `/manage/factory` | 工厂总览、生产指挥、质量与告警 | 给生产管理看执行 |
| 经营视角 | `/manage/executive` | 经营与交付、成本核算、日报交付 | 给经营/财务看结果 |
| 质量视角 | `/manage/quality` | 质量与告警、生产指挥、日报交付 | 给审阅处置看异常 |
| 系统视角 | `/manage/admin/settings` | 数据治理、主数据与权限、系统运行 | 给管理员看配置 |

切换视角只改变：

- 导航排序
- 默认首页
- 页面上方的标题语义
- 快捷入口

不改变：

- 可访问路由
- 数据权限
- 后端行为

## 6. 一级模块与子模块

侧边栏不再显示一长串页面名，而是固定成 8 个一级模块，模块内再展开子模块。

| 一级模块 | 子模块 | 现有路由示例 |
|---|---|---|
| 工厂总览 | 总览、工厂看板、车间看板、统计看板 | `/manage/overview`、`/manage/factory`、`/manage/workshop`、`/manage/statistics` |
| 生产指挥 | 生产流转、车间机列、卷级追踪、库存去向、异常地图 | `/manage/factory/flow`、`/manage/factory/machine-lines`、`/manage/factory/coils`、`/manage/factory/destinations`、`/manage/factory/exceptions` |
| 经营与交付 | 经营驾驶舱、经营效益、加工费管理、日报与交付 | `/manage/executive`、`/manage/factory/cost`、`/manage/executive/processing-fees`、`/manage/reports` |
| 质量与告警 | 异常与补录、差异核对、质量中心、异常审核 | `/manage/entry-center`、`/manage/reconciliation`、`/manage/quality`、`/manage/anomaly` |
| 数据治理 | 数据接入、导入历史、别名映射 | `/manage/ingestion`、`/manage/imports`、`/manage/alias` |
| 主数据与权限 | 主数据、模板中心、规则配置、用户管理、权限治理 | `/manage/master`、`/manage/admin/templates`、`/manage/admin/rules`、`/manage/admin/users`、`/manage/admin/governance` |
| AI 助手 | AI 助手 | `/manage/ai-assistant` |
| 系统运行 | 系统设置、运行保障 | `/manage/admin/settings` |

说明：

- 一级模块名尽量短，避免把完整页面标题直接塞进侧边栏。
- 子模块可以显示完整业务名，但每项不超过一眼能扫完的长度。
- 历史兼容入口继续保留重定向，不进入一级导航。

## 7. 外壳布局

管理端壳层采用固定左栏 + 顶部状态带 + 全宽内容区的结构。

### 7.1 左侧主导航

- 宽度：252px，收起后 64px。
- 背景：近黑蓝，不用浅色底。
- 顶部保留品牌区：logo + `鑫泰铝业 数据中枢`。
- 视角切换放在品牌区下方或顶部辅助位，用短标签按钮或紧凑分段控件。
- 当前模块高亮不要用 3px 左边框，改用背景层级 + 小状态点 + 图标高亮。

### 7.2 顶部状态带

- 左侧：当前模块标题 + 面包屑。
- 中间：搜索框，搜索对象是模块、报表、数据和操作入口。
- 右侧：日期、同步状态、AI 助手、通知、用户菜单。
- 状态带是固定的，不随页面跳动。

### 7.3 内容区

- 总览/经营/工厂类页面采用全宽大屏，不强行收成窄版容器。
- 配置类、表单类页面允许有较窄的正文宽度，但不能回到白底后台感。
- 页面正文上方必须有模块标题和当前视角提示，不再只留一个抽象页面名。

### 7.4 底部状态条

在总览类页面保留一条细的运行状态带，显示：

- 系统运行
- 数据源新鲜度
- 任务调度
- AI 服务状态

这条状态带是目标图压迫感的重要来源，不能删。

## 8. 页面家族

第一阶段不要求所有页面长得一模一样，但要共享同一套骨架。

| 页面家族 | 结构模板 | 适用页面 |
|---|---|---|
| 指挥中心型 | KPI 条 + 主画布 + 右侧事件/AI 侧栏 + 底部状态条 | 总览、工厂看板、经营驾驶舱 |
| 运营分析型 | KPI 条 + 图表/排名区 + 辅助列表 | 经营效益、统计、日报 |
| 处置列表型 | 顶部筛选 + 主表格 + 右侧详情 | 质量、差异核对、异常补录、导入历史 |
| 配置管理型 | 页头 + 紧凑表单/表格 + 审计信息 | 主数据、模板、规则、权限、系统运行 |

共同规则：

- 不用大块解释文字。
- 不用白卡片堆在浅灰底上。
- 表格和指标都要紧凑，数字右对齐。
- 详情靠抽屉或右侧栏，不靠长段落说明。

## 9. 视觉 token

管理端单独采用深色壳层 token，和移动端/入口页分开。

| 角色 | 语义 |
|---|---|
| canvas | 近黑蓝底，作为全屏背景 |
| panel | 低透明深面板，用于主内容块 |
| panel-strong | 更亮一档的面板，用于关键 KPI 或侧栏 |
| border | 白色低透明细线，只做分隔 |
| text | 86% 左右的高亮文字 |
| muted | 56% 左右的辅助文字 |
| primary | 工业蓝 |
| success | 运行绿 |
| warning | 告警橙 |
| danger | 异常红 |
| accent | 少量铜金，只做能量点 |

半径策略：

- 主面板 12px
- 次级面板 8px
- 按钮/标签 8px 或 pill
- 不把所有组件做成同一种圆角

排版策略：

- 继续使用项目现有字体栈，不额外引入整站新字体。
- 数字统一用等宽数值字体。
- 大数字和大标题的字距更紧，避免松散。

## 10. 组件规则

### 10.1 导航项

- 高度 44-48px。
- 图标、主标签、次标签分层显示。
- 激活态用背景层级和状态点，不用厚左边框。
- 收起态只保留图标和标题提示。

### 10.2 模块入口卡

- 只用于首页或模块总入口。
- 卡面上半部放图形，下半部放 3 个关键指标和 1 个主动作。
- 不做“纯图标 + 一句文案”的空卡。

### 10.3 KPI 条

- 每张卡高度统一，但内容不必完全一样。
- 数值占主位，标签退后。
- 同一行内所有数字右对齐。

### 10.4 表格

- 表头深色、行高紧凑、数字用等宽体。
- 关键状态用胶囊，不要只靠颜色。
- 表格边线用细线，不用重框。

### 10.5 按钮和标签

- 主按钮：深蓝或工业蓝，按下有轻微缩放。
- 次按钮：深面板上用描边或弱底色。
- 标签：pill 形态，用于状态和筛选。

### 10.6 搜索与抽屉

- 搜索用于模块跳转和快速定位，不做通用内容检索。
- 抽屉用于单元详情、告警详情、模块辅助操作。
- 不把复杂交互塞进模态窗。

## 11. 分阶段执行

### Phase 1：壳层与导航

目标：

- 改 `ManageShell.vue`
- 改 `manage-navigation.js`
- 统一深色管理壳层 token
- 加入视角切换
- 收敛一级模块和子模块

结果：

- 任何 `/manage/*` 页面都能套进同一套深色工业壳。
- 侧边栏变短，模块层级更清楚。
- 旧路由可继续跑，不需要大改页面内容。

### Phase 2：总览与经营

目标页面：

- `/manage/overview`
- `/manage/factory`
- `/manage/executive`
- `/manage/factory/cost`

结果：

- 先把最接近目标图 1 / 2 / 5 的页面做成完整指挥台。
- KPI 条、主画布、右侧事件栏、底部状态条风格统一。

### Phase 3：生产与处置

目标页面：

- `/manage/factory/flow`
- `/manage/factory/machine-lines`
- `/manage/factory/coils`
- `/manage/factory/destinations`
- `/manage/factory/exceptions`
- `/manage/entry-center`
- `/manage/reconciliation`
- `/manage/quality`

结果：

- 处置类页面改成高密度账本式页面。
- 生产类页面加入更强的流向和状态感。

### Phase 4：治理与系统

目标页面：

- `/manage/ingestion`
- `/manage/imports`
- `/manage/alias`
- `/manage/master`
- `/manage/admin/templates`
- `/manage/admin/rules`
- `/manage/admin/users`
- `/manage/admin/governance`
- `/manage/admin/settings`

结果：

- 配置类页面仍然深色，但更克制、密集、清晰。
- 继续收敛字段展示，不做解释型长文案。

### Phase 5：收尾

- 统一标题层级
- 统一空状态、加载态、错误态
- 统一按钮、标签、表格的 hover / active 状态
- 删除明显不再需要的旧样式分支

## 12. 验收标准

1. `/manage` 第一眼像工业指挥台，不像普通后台。
2. 侧边栏只有少量一级模块，子模块在展开后出现。
3. 角色视角切换存在，但不改变真实权限边界。
4. 总览/经营类页面有明确的 KPI 条、主画布、右侧侧栏和底部状态条。
5. 表格、卡片、标签、按钮在整个管理端风格统一。
6. 没有白底卡片墙、紫蓝渐变 hero、居中营销布局。
7. 旧路由、旧权限、旧 API 均不被破坏。
8. `frontend` 可正常构建。

## 13. 风险与边界

- 风险 1：页面太多，导航重新组织后容易迷路。  
  应对：视角切换只改顺序，不改路由；搜索保留。

- 风险 2：深色壳层会把页面内容压暗。  
  应对：总览/经营页允许更亮一档的面板，表格和配置页再往深处收。

- 风险 3：一口气改太多页面会失控。  
  应对：先壳层，再首页，再经营与生产，再治理页，最后收尾。

- 风险 4：为了“像目标图”而堆很多装饰。  
  应对：只保留有业务含义的发光、状态和图形，不做纯装饰。

## 15. 结论

这次重构的本质不是“更漂亮的后台”，而是把管理端做成真正的深海工业指挥台：能看、能扫、能分层、能切换、能逐步推进。

先把壳层和导航定住，后面每个页面就不再各说各话。
