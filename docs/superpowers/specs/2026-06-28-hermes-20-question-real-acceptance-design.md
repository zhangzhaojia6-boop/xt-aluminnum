# 鑫泰铝业智能大脑 20 问真实验收设计

日期：2026-06-28

状态：已批准设计 / 待写实施计划

适用项目：`鑫泰铝业 数据中枢`

## 1. 背景

当前方向已经封档：

- 数据中枢做减法：少入口、少页面、少重复服务、少散乱文档。
- 智能体做加法：在 NousResearch Hermes 基础上增强 `鑫泰铝业智能大脑`。
- 钉钉群文件和群聊天内容是最高优先级事实来源。
- MES/WMS 是外部生产系统和数据库来源，读取边界保持只读。
- 管理端围绕 `/manage` 收口成大仪表盘，不再随意新开门户。

本轮优化不以“再加一个功能”为目标，而以“证明智能大脑真的能办事”为目标。

一句话目标：

```text
用 20 个真实自然语言问题，验收鑫泰铝业智能大脑是否能查真实来源、判断冲突、中文回答、留下追踪编号，并真实发到指定测试群和指定个人。
```

## 2. 已批准决策

本设计基于需求澄清后的 7 个决定：

| 项 | 决定 |
|---|---|
| 验收范围 | 一次性覆盖完整 20 问。 |
| 真实度 | 生产真实联调，包含真实钉钉回群或通知。 |
| 外发范围 | 只发到指定测试群和指定个人。 |
| 达标线 | 核心链路 20/20 必过；真实外发最多允许 2 个环境型失败。 |
| 核心链路 | 理解、来源计划、真实取数、数值或缺失、冲突判断、追踪编号都必须验。 |
| 数据源范围 | 钉钉、MES/WMS 只读链路、数据中枢投影、DailyFactBundle、历史日报、未来能耗库配置状态。 |
| 减法范围 | 可以删除旧服务代码，但必须先证明无生产主链路、Hermes、钉钉、MES/WMS、DailyFactBundle、trace、审计依赖。 |

## 3. 设计目标

### 3.1 智能体目标

`鑫泰铝业智能大脑` 对每个关键问题必须做到：

- 能理解用户自然语言。
- 能找到对应指标、日期、车间或业务对象。
- 能按事实来源地图生成来源计划。
- 能实际查真实来源，而不是只写计划。
- 能返回真实数值和单位；查不到时说明缺什么。
- 能识别来源冲突，说明采用哪个来源、放弃哪个来源、为什么。
- 能对外只用中文回答。
- 能对外写 `追踪编号`，不把内部 `trace_id` 当用户文案。
- 能把缺失或冲突推进成下一步动作。

### 3.2 软件减法目标

数据中枢本体只保留主链路：

- `/entry`
- `/manage`
- Hermes / 鑫泰铝业智能大脑
- 钉钉证据链路
- MES/WMS 只读读取链路
- DailyFactBundle / 历史日报
- trace / agent_runs / 审计日志

旧入口、旧页面、旧服务、旧文档要分为：

| 分类 | 动作 |
|---|---|
| `protect` | 主链路，不能删。 |
| `freeze` | 冻结观察，不新增能力。 |
| `merge` | 有真实重复时合并。 |
| `candidate_delete` | 证据充分后删除。 |

### 3.3 不做目标

本轮不做：

- 不新建第二套后台。
- 不新建第二套日报系统。
- 不把 `数据中枢` 叫成 MES。
- 不把 RAG 当实时数字来源。
- 不把模型猜测写成事实。
- 不向所有生产群批量外发。
- 不删除原始证据、审计日志、trace、Hermes、钉钉、MES/WMS 或 DailyFactBundle 依赖链。

## 5. 分层闸门

每个问题分 4 层验收。

### 5.1 第一层：理解闸门

必须证明：

- 识别出指标或能力类型。
- 识别出日期范围。
- 识别出车间、全厂、库存、能耗、异常等业务对象。
- 追问能继承上下文，例如“昨天呢”不能丢失上一个问题的业务域。
- 模糊问题只问一个最短澄清问题，不做硬关键词拒绝。

失败示例：

```text
用户问“今天产量咋样”，系统没有识别成生产问题。
用户问“昨天呢”，系统不知道昨天指的是上一轮的产量。
```

### 5.2 第二层：来源闸门

必须证明：

- 来源计划对齐 `docs/hermes/fact-source-map.md`。
- 钉钉群文件和群聊天内容排在最高优先级。
- 外接只读数据库排在数据中枢投影之前。
- RAG 只用于口径解释，不用于实时数字。
- 涉及 MES/WMS 的问题必须检查只读读取链路。

失败示例：

```text
有钉钉群事实，但系统优先采用数据中枢投影。
RAG 里有历史口径，系统直接当成今天数字。
```

### 5.3 第三层：回答闸门

必须证明回答包含：

| 字段 | 要求 |
|---|---|
| 结论 | 先直接回答。 |
| 数值和单位 | 能查到时必须返回。 |
| 时间范围 | 必须写清。 |
| 来源 | 必须写实际采用来源。 |
| 状态 | `confirmed`、`candidate`、`missing`、`conflict` 之一。 |
| 追踪编号 | 对外必须写中文 `追踪编号`。 |
| 下一步 | 缺失或冲突时必须写。 |

对外回答必须满足：

- 使用 `鑫泰铝业智能大脑` 身份。
- 只用中文。
- 不出现研发助手、代码助手、后台执行器等身份。
- 不暴露内部字段名给业务用户，除非是追溯系统内部记录时必要。

### 5.4 第四层：钉钉真实送达闸门

必须证明：

- 20 问会真实发送到指定测试群或指定个人。
- 每次发送有 outbox 记录。
- 成功或失败都有外部通讯日志。
- 失败时保留钉钉返回体或可读失败原因。
- 不向未批准生产群扩散。

外发最多允许 2 个环境型失败。

环境型失败只包括：

- 测试群配置问题。
- 钉钉账号或应用权限问题。
- 钉钉接口限流或临时不可用。
- 网络或云端运行环境临时异常。

不允许归为环境型失败：

- 问题没识别出来。
- 没有查真实来源。
- 没有追踪编号。
- 回答不是中文。
- 来源优先级错误。
- 冲突没有说明。
- 代码异常或测试夹具错误。

## 6. 真实数据源设计

### 6.1 钉钉群文件和群聊天

钉钉内容是最高优先级事实来源。

要求：

- 读取授权测试群里的聊天内容和文件证据。
- 群聊天和群文件都统一归入 `dingtalk_group_content`。
- 消息识别不能太硬，口语、省略句、错别字和追问要做最佳努力。
- 只有实在不清楚时，才问一个最短澄清问题。

验收重点：

```text
如果钉钉群内容和 MES/WMS 或数据中枢投影冲突，先按钉钉群内容回答，并把冲突写进 trace。
```

### 6.2 MES/WMS 只读链路

MES/WMS 是外部生产系统和数据库来源，不是本产品名字。

要求：

```text
MES/WMS 只读连接
  -> adapter
  -> 数据中枢投影或事实表
  -> Hermes 来源计划
  -> 回答、状态、trace
```

验收重点：

- 生产、库存、在制、包装、投料等问题必须检查链路。
- 链路不通时不能假装 confirmed。
- 失败要区分缺权限、缺配置、缺同步、空数据、超时。
- 错误信息不能泄露密钥、token、数据库口令。

### 6.3 数据中枢投影

数据中枢投影用于展示、缓存、审计和回查。

要求：

- 可以作为事实来源，但不是最高事实源。
- 与上游事实冲突时，要显示冲突。
- 不覆盖钉钉群事实或外接只读数据库事实。

### 6.4 DailyFactBundle 和历史日报

要求：

- 能作为日报、累计、历史追溯的重要来源。
- 缺历史日期时，要提示累计不完整。
- 不能用历史日报冒充今天实时事实。

### 6.5 未来能耗库

当前物联网能耗库可能未配置。

要求：

- 测试要检查配置状态。
- 未配置时返回 `missing` 或 `unconfigured` 类状态。
- 未配置不是系统故障。
- 不能把机列明细直接当全厂总能耗。

## 7. 减法删除设计

本轮允许删除旧服务代码，但先证据后删除。

### 7.1 删除前检查

每个删除候选必须回答：

| 问题 | 必须结论 |
|---|---|
| 有没有生产路由调用？ | 没有。 |
| 有没有 `/entry` 或 `/manage` 主链路依赖？ | 没有。 |
| 有没有 Hermes / 鑫泰铝业智能大脑依赖？ | 没有。 |
| 有没有钉钉依赖？ | 没有。 |
| 有没有 MES/WMS 只读链路依赖？ | 没有。 |
| 有没有 DailyFactBundle 或历史日报依赖？ | 没有。 |
| 有没有 trace、agent_runs、审计日志依赖？ | 没有。 |
| 有没有测试或部署脚本仍引用？ | 没有，或同步删除。 |
| 有没有回滚方式？ | 有。 |

### 7.2 删除顺序

推荐顺序：

1. 列出候选。
2. 查路由、服务、测试、脚本、文档引用。
3. 写入或更新减法登记。
4. 删除无引用候选。
5. 跑定向测试。
6. 跑 `git diff --check`。
7. 记录删除结果和回滚方式。

### 7.3 禁删对象

以下对象本轮不能删：

- `/entry/*`
- `/manage/today`
- `/manage/live`
- `/manage/production`
- `/manage/alerts`
- `/manage/ai-control` 或现有 AI 控制/治理入口
- Hermes / 鑫泰铝业智能大脑链路
- 钉钉入站、出站、outbox、external_message_logs
- MES/WMS adapter、投影表、同步日志
- DailyFactBundle、历史日报、日报生成链路
- trace、agent_runs、审计日志
- 原始证据和上传文件记录

## 9. 通过标准

本轮算通过必须同时满足：

| 类别 | 标准 |
|---|---|
| 核心链路 | 20/20 全过。 |
| 钉钉真实外发 | 至少 18/20 成功；失败必须是环境型并写清原因。 |
| 中文身份 | 20/20 都使用 `鑫泰铝业智能大脑`，且只用中文。 |
| 追踪 | 20/20 都有对外 `追踪编号`，内部可回查 trace。 |
| 来源 | 20/20 都有真实来源查询记录或明确缺失记录。 |
| 冲突 | 有冲突时必须说明采用、放弃和原因。 |
| RAG 边界 | 没有把 RAG 当实时事实来源。 |
| MES/WMS | 涉及生产事实的问题能证明只读链路状态。 |
| 减法 | 删除对象都有依赖证据、回滚方式和测试结果。 |
| 回归 | Hermes、钉钉、MES/WMS、`/entry`、`/manage` 主链路定向测试通过。 |

## 10. 失败分级

失败分 4 类，避免一锅粥：

| 级别 | 含义 | 处理 |
|---|---|---|
| P0 | 核心链路失败，例如没查来源、没追踪编号、来源优先级错。 | 必须修。 |
| P1 | 真实外发失败，但不是环境型。 | 必须修。 |
| P2 | 外部环境失败，例如钉钉限流或测试群权限。 | 可进入环境失败额度。 |
| P3 | 展示或报告不够清楚，但不影响链路。 | 记录后优化。 |

## 11. 风险和控制

| 风险 | 控制 |
|---|---|
| 钉钉真实外发影响现场 | 只发指定测试群和指定个人。 |
| 真实数据源不稳定 | 允许返回 missing，但必须说明查了哪里和缺什么。 |
| 删除旧服务误伤主链路 | 删除前做依赖检查，删除后跑定向回归。 |
| 20 问一次性太大 | 分层报告，失败能定位到理解、来源、回答或外发。 |
| 能耗库未配置 | 作为配置状态检查，不误判成系统崩溃。 |
| 消息识别太硬 | 用语义和最佳努力处理，实在不清楚才问一个最短澄清问题。 |

## 12. 后续计划入口

本设计批准后，下一步进入实施计划，计划应拆成：

1. 20 问验收夹具和评分器。
2. 真实来源适配和 trace 记录补强。
3. 钉钉测试群/个人真实外发门禁。
4. 管理端来源状态或追踪结果可见性补强。
5. 旧服务删除候选审计和回归。
6. 完成后跑门禁、合并、同步云端。
