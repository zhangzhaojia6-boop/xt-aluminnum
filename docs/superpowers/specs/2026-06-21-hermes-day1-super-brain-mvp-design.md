# Hermes Day-1 Super Brain MVP 设计

日期：2026-06-21

## 1. 一句话目标

Hermes 不是统计员，也不是只会回答问题的报表助手。

Hermes 要成为 `鑫泰铝业 数据中枢` 里的制造业工厂超级大脑：

```text
感知现场 -> 理解业务 -> 判断风险 -> 推动动作 -> 复盘结果 -> 自主成长
```

第一阶段先做 Day-1 MVP：

> 张兆嘉在钉钉私聊 Hermes 一句话，Hermes 能主动查 MES、数据中枢、WMS、钉钉文本/文件、RAG、历史日报和输出 skill 样本，生成 root_owner 完整版三段式日报，并把证据、冲突和成长反馈发回钉钉。

小白版理解：Hermes 不是等人把数喂给它，而是自己去找原始证据、自己判断哪里不对、自己生成能用的日报，再告诉最高权限者它这次学到了什么。

## 2. 范围选择：B + C

本规格采用 `B + C`。

### 2.1 B：Day-1 Super Brain MVP

第一阶段必须优先做出可用闭环：

- 钉钉私聊作为 root_owner 的主入口。
- Hermes 能接收自然语言指令。
- Hermes 能主动查证多数据源。
- Hermes 能生成三段式日报。
- Hermes 能识别数据缺失和冲突。
- Hermes 能把成长反馈私聊发给 root_owner。
- Hermes 能自动入库关键钉钉消息和文件。

### 2.2 C：完整超级大脑平台

整体架构按完整平台设计，但不要求第一阶段全部做完：

- LangGraph 状态编排。
- LangChain 工具和 RAG 接入。
- ReAct 单次任务思考循环。
- Harness Loop 长期评测和成长闭环。
- 4 大 Engine 分层。
- 多角色钉钉权限分发。
- 高自主执行、可追责、可回滚。
- 长期记忆、案例记忆、偏好记忆、能力复盘。

## 4. 权限模型

### 4.1 root_owner

最高权限者是张兆嘉的钉钉身份。

当前截图确认信息：

- 姓名：张兆嘉
- 企业：河南鑫泰铝业有限公司
- 钉钉号：`14s-qokug9kxuo`
- 部门：企业/管理部-人力资源科

系统实现时不要只用姓名绑定最高权限，因为姓名可能重复。应优先绑定钉钉内部身份：

```text
dingtalk_user_id / unionid > 钉钉号 > 姓名
```

`root_owner` 权限：

- 查看所有版本输出。
- 配置钉钉分发权限。
- 授权 Hermes 进入 L5 高自主执行。
- 查看完整审计链路。
- 撤销、降权、删除 Hermes 学到的记忆。
- 指定业务日、车间、角色版本重新生成日报。

### 4.2 权限分发原则

Hermes 使用同一事实底座，但对不同人输出不同版本。

| 角色 | 默认可见内容 |
|---|---|
| root_owner | 全部内容、全部证据、全部审计、全部成长反馈 |
| 老板/总经理 | 全厂经营、生产、成本、库存、发货、重大风险 |
| 生产厂长 | 生产执行、车间、机列、班次、异常、协调动作 |
| 车间主任 | 本车间明细、本车间异常、本车间待补录 |
| 能源/成本负责人 | 用电、用气、吨耗、成本、能耗异常 |
| 数据工程/系统管理员 | 数据源失败、字段冲突、入库状态、修正记录 |
| 普通员工/班组 | 本人任务、补录提醒、被打回原因 |

Day-1 MVP 初期只自动发送给 root_owner。其他角色分发由 root_owner 后续在钉钉里授权。

## 5. 主交互入口

### 5.1 钉钉私聊是 root_owner 驾驶舱

root_owner 不需要先打开网页。

主入口是钉钉私聊 Hermes：

```text
张兆嘉：生成 6月19日 root_owner 完整版三段式日报。

Hermes：已收到。正在查 MES、数据中枢、钉钉日报文件、RAG 和历史模板。
```

Hermes 需要能识别自然语言指令：

- 生成某日 root_owner 完整版三段式日报。
- 生成某日老板视角摘要。
- 重新生成某日正式日报。
- 解释某车间产量或能耗异常。
- 把某个文件纳入日报采样。
- 以后这类文件都作为日报证据。
- 给某类角色发送对应版本。
- 删除或降权某条记忆。
- 查看某次修正的审计记录。

### 5.2 群聊不是最高权限入口

群聊可以作为证据来源和分发渠道，但 root_owner 的高权限指令优先走私聊。

群聊里的消息默认先进入证据分类，不直接变成高风险动作。

## 6. 4 大 Engine

### 6.1 Perception Engine：感知引擎

负责“看见东西”。

数据源：

- MES 只读数据。
- WMS 数据。
- 数据中枢数据库和 API。
- 钉钉文本。
- 钉钉文件。
- RAG 知识库。
- 历史日报。
- 输出 skill 样本。
- 人工填报和补录记录。

Day-1 MVP 要求：

- 能按业务日期拉取可用证据。
- 能发现钉钉中疑似日报、产量表、库存表、发货表、异常说明的消息和文件。
- 能记录每个证据的来源、时间、发送人、文件名、哈希、解析状态。

### 6.2 Reasoning Engine：推理引擎

负责“想明白”。

能力：

- 判断数据源可信度。
- 判断字段缺失。
- 判断 MES、数据中枢、WMS、钉钉、输出 skill 之间的冲突。
- 判断某个数据是否可用于正式日报。
- 判断下一步该查哪个工具。
- 判断是否需要追问 root_owner。

Day-1 MVP 要求：

- 不能只给一个数字，要说明证据来自哪里。
- 数据冲突时不静默选一个，要列出冲突来源。
- 缺字段时要主动说明缺什么、建议查什么。

### 6.3 Action Engine：行动引擎

负责“推动事情”。

完整平台动作类型。下面列表不是全部 Day-1 必做，Day-1 必做范围以本小节后面的清单为准：

- 生成日报草稿。
- 生成 root_owner 完整版三段式日报。
- 生成正式日报正文。
- 生成各车间明细。
- 自动归档钉钉关键文件。
- 自动建立待补录任务。
- 标记疑似异常。
- 写入数据中枢修正记录。
- 写入 `agent_outbox` 等待外发。

Day-1 MVP 必做写动作：

- 写入钉钉文本/文件证据入库记录。
- 写入 Hermes 任务、报告产物、证据摘要和冲突摘要。
- 写入成长反馈和记忆候选。
- 写入 root_owner 私聊回复或对应 outbox 记录。
- 所有这些写动作必须有审计记录。

Day-1 MVP 预留但不强制完成：

- 自动建立真实业务补录任务。
- 自动执行正式数据中枢修正。
- 自动多角色外发。
- 定时 7:30/9:35 自动发布。
- 批量回滚界面。

如果 root_owner 明确授权 L5 试点，Day-1 可以执行单条数据中枢修正，但必须记录改前值、改后值、证据、原因和回滚方式。

### 6.4 Learning Engine：学习引擎

负责“长记性”。

记忆类型：

| 类型 | 内容 |
|---|---|
| 事实记忆 | 已确认的稳定事实，如业务时间、车间别名、字段口径 |
| 规则记忆 | 可复用规则，如哪些文件名进入日报采样 |
| 偏好记忆 | root_owner 最近关注点，如成本、发货、2050 |
| 案例记忆 | 历史异常、原因、处理结果 |
| 能力记忆 | Hermes 做任务后的复盘，如哪个工具有效 |

边界：

- Hermes 可以自动学习“路径经验”。
- Hermes 不能自动把猜测升级为业务真理。
- 高影响记忆需要 root_owner 可确认、降权或删除。

Day-1 MVP 不做前端成长面板。成长反馈直接通过钉钉私聊发给 root_owner，同时数据库留痕。

## 7. 技术骨架

### 7.1 LangGraph

LangGraph 管 Hermes 的主流程编排。

建议状态流：

```text
接收钉钉指令
  -> 识别身份和权限
  -> 识别任务意图
  -> 制定查证计划
  -> 调用工具查数据
  -> 证据归类和冲突判断
  -> 生成日报/动作/反馈
  -> 写审计和记忆候选
  -> 钉钉回复 root_owner
```

### 7.2 LangChain

LangChain 管工具和 RAG 接入。

工具清单：

- MES read-only 查询工具。
- WMS 查询工具。
- 数据中枢查询工具。
- 数据中枢受控写入工具。
- 钉钉文本读取工具。
- 钉钉文件读取/下载/归档工具。
- RAG 检索工具。
- 输出 skill 样本读取工具。
- 日报生成工具。
- outbox 外发工具。

### 7.3 ReAct Loop

ReAct 管 Hermes 单次任务的思考方式。

每次任务遵循：

```text
Observe：我看到了什么？
Think：现在缺什么证据？
Act：我要查哪个工具？
Reflect：查完后证据是否足够？
Answer：输出结论、正文、明细、证据和下一步。
```

### 7.4 Harness Loop

Harness Loop 管 Hermes 的长期测试和成长。

它不是生产主流程，而是评估系统。

评估问题：

- Hermes 有没有查对数据源？
- 有没有误用钉钉闲聊？
- 有没有漏掉关键异常？
- 有没有把过程数据误当最终日报数？
- 输出是否对齐人工成品？
- 本次经验是否值得进入记忆？

### 7.5 Policy / Audit Gate

这里不做低自主刹车，而做高自主可追责门禁。

原则：

- MES 仍然只读。
- 数据中枢允许高自主写入。
- 高风险动作可以执行，但必须有证据、审计和回滚路径。
- 不能泄露密码、token、数据库连接串。
- 不能无记录地修改正式数据。

## 8. 主动性等级

Hermes 主动性分 5 级。

| 等级 | 含义 | Day-1 目标 |
|---|---|---|
| L1 | 被动回答 | 不是目标 |
| L2 | 主动补证据 | 必须支持 |
| L3 | 主动发现问题 | 必须支持基础版 |
| L4 | 主动执行低中风险动作 | 默认目标 |
| L5 | 主动执行高风险动作，可追责可回滚 | root_owner 授权后支持 |

Day-1 MVP 默认运行在 L4。

root_owner 可授权具体任务进入 L5。

## 9. 钉钉文本和文件规则

钉钉资料可以进入最终输出，但必须带来源身份。

### 9.1 证据分类

| 类型 | 例子 | 处理方式 | 最终输出作用 |
|---|---|---|---|
| 事实型文件 | 产量表、库存表、发货表、日报表 | 授权通道内自动入库，解析字段，进入证据池 | 可参与比对，必要时进入日报采样 |
| 解释型文本 | “2050 停机 2 小时，所以产量低” | 授权通道内自动入库，保留上下文 | 可作为原因说明 |
| 指令型文本 | “把昨天数据改成这个数” | 授权通道内自动入库，生成动作和审计 | 可触发 L5 数据中枢修正试点 |
| 噪声型文本 | 闲聊、表情、重复无效文件 | 丢弃或低权重记录 | 不进入最终输出 |

Day-1 只处理 root_owner 私聊和 root_owner 明确授权的钉钉群/通道，不扫描所有群聊。

### 9.2 自动入库触发词

Day-1 MVP 至少识别这些关键词：

- 日报
- 产量
- 每日产量
- 库存
- 发货
- 入库
- 在制
- 电耗
- 气耗
- 成品率
- 成本
- 异常
- 停机
- 补录
- 重发
- 以这个为准

### 9.3 入库元数据

每条入库资料至少记录：

- 来源类型：文本/文件。
- 钉钉群或私聊。
- 发送人。
- 接收时间。
- 消息时间。
- 文件名。
- 文件哈希。
- 业务日期。
- 解析状态。
- 证据等级。
- 是否进入日报采样。

## 10. 日报输出

Hermes 最终输出采用三段式：

```text
工厂大脑判断单
正式日报正文
各车间明细
```

### 10.1 工厂大脑判断单

给 root_owner 和老板视角快速看。

内容：

- 一句话结论。
- 今日生产是否正常。
- 主要风险。
- 关键数据冲突。
- 哪些字段缺失。
- Hermes 已查证的数据源。
- Hermes 已执行或建议执行的动作。
- 本次成长反馈摘要。

示例：

```text
【Hermes判断】
6月19日总产量较昨日明显上升，但 2050 吨电耗高于月均，需结合班次、开机和异常说明复核。
本次日报主要证据来自钉钉日报文件、数据中枢、MES/WMS 投影和历史模板。
```

### 10.2 正式日报正文

正式日报正文按人工成品模板风格生成。

必须接近以下语言节奏：

```text
6月19日，车间总产量日合计366吨（外加工31吨）比昨日↑125吨，月累计5971吨（外加工月累计370吨）。

铸轧分厂开机5条，日产量104吨，月累计产量1662吨；铸锭车间日产量261吨，月累计产量5576吨；热轧车间日产量251吨，月累计产量5230吨；1650车间日产量130吨，月累计产量2819吨，日道次67道，月累计道次969道；1850车间日产量46吨，月累计产量816吨，日道次33道，月累计道次418道；2050车间日产量80吨，月累计产量2422吨，日道次58道，月累计道次1404道；轧机日产量256吨，月累计产量6056吨，日道次158道，月累计道次2791道；在线退火日产量375吨，月累计产量6274吨，拉矫日产量64吨，月累计产量2677吨，精整车间日产量37吨，月累计产量1592吨，剪切车间日产量144吨，月累计产量1609吨，彩涂车间日产量0吨，月累计产量0吨；回收车间日产量67吨，月累计产量1332吨，大修日磨辊10根，月累计磨辊172根。
```

正文必须覆盖：

- 总产量。
- 外加工。
- 月累计。
- 各车间日产量和月累计。
- 冷轧道次。
- 在制料。
- 用电、用气、吨耗。
- 入库成品。
- 合同和余合同量。
- 成品率。
- 成本核算。

### 10.3 各车间明细

正式正文后必须追加车间明细。

每个车间明细建议包含：

- 日产量。
- 月累计产量。
- 日投料。
- 日入库。
- 道次。
- 在制料。
- 日吨电耗。
- 月吨电耗。
- 日吨气耗。
- 月吨气耗。
- 成品率。
- 异常说明。
- 数据来源。
- Hermes 判断。

示例：

```text
【2050车间】
日产量：80吨，月累计：2422吨。
日投料：469吨，道次：58道，月累计道次：1404道。
在制料：522.5吨。
日吨电耗：223.1度，月吨电耗：157.4度。
Hermes判断：吨电耗高于月均，需要结合开机、班次和钉钉异常说明继续核查。
数据来源：钉钉日报文件、数据中枢、MES/WMS 证据。
```

## 11. 多角色输出

Day-1 MVP 只自动发 root_owner。

完整平台支持 root_owner 授权后的多角色分发：

```text
同一事实底座 -> 按角色裁剪 -> 钉钉私聊/群聊/待办分发
```

示例指令：

```text
以后每日 8 点，把车间版日报发给各车间主任。
```

Hermes 应回复：

```text
已记录分发规则：每日 8 点，向各车间主任发送本人车间日报明细。
范围：仅本车间数据，不含成本和全厂敏感信息。
```

## 12. 成长反馈

不做前端成长面板。

Hermes 每次完成重要任务后，直接钉钉私聊 root_owner。

格式：

```text
【Hermes成长反馈】
本次任务：生成 6月19日生产日报
```

## 13. Day-1 MVP 成功标准

第一阶段成功标准：

1. root_owner 可以在钉钉私聊 Hermes。
2. Hermes 可以识别“生成 6月19日 root_owner 完整版三段式日报”这类自然语言指令。
3. Hermes 会主动查 MES、数据中枢、WMS、钉钉文本/文件、RAG、历史日报和输出 skill 样本。
4. Hermes 可以生成三段式输出，标题固定为：`工厂大脑判断单`、`正式日报正文`、`各车间明细`。
5. Hermes 可以说明数据来源、冲突和缺失字段。
6. Hermes 可以把授权私聊/群里的事实型钉钉文件和解释型钉钉文本自动入库。
7. Hermes 可以把成长反馈私聊发给 root_owner。
8. 关键动作有审计记录。
9. 生产验证至少覆盖一个真实业务日，例如 2026-06-19。
10. 输入一句 `生成 6月19日正式日报` 时，输出必须严格分成 3 段，且第一段标题固定叫 `工厂大脑判断单`。

Day-1 MVP 暂不要求：

- 完整多角色自动分发。
- 所有车间主任权限配置完美。
- 完整 WMS 深度接入。
- 完整自动修正所有数据中枢事实。
- 自动建立真实业务补录任务。
- 定时 7:30/9:35 自动发布。
- 前端成长面板。

## 14. 成熟度测试

Hermes 不是靠“说话像人”证明聪明，而是靠查证路径、证据质量、主动补洞、受控行动、复盘成长证明自己变强。

测试集分 6 类：

| 测试 | 输入 | 合格表现 |
|---|---|---|
| 主动查证测试 | “昨天产量是不是正常？” | 主动查 MES、数据中枢、历史均值、钉钉异常说明 |
| 数据冲突测试 | MES=A、数据中枢=B、钉钉=C | 标出冲突，给可信度排序，不硬选 |
| 缺数据追问测试 | 某字段缺失 | 主动追问、生成补录建议或建议查 WMS/钉钉 |
| 钉钉证据分类测试 | 一批文本和文件 | 分出事实型、解释型、指令型、噪声型 |
| 记忆成长测试 | 第二次遇到类似问题 | 能引用上次确认过的规则 |
| 高自主可追责测试 | 要求修正数据中枢 | 可执行，但要有证据、审计、前后值和回滚 |

## 15. 数据安全和不可取消底线

本项目采用高自主，不采用“每一步都要人批准”的低自主模式。

但以下底线不能取消：

- MES 是外部系统，只读。
- 不泄露密码、token、数据库连接串。
- 不无记录地改正式数据。
- 不把钉钉闲聊直接当事实。
- 不把 RAG 历史数字当实时生产事实。
- 不修改输出 skill 原始历史成品。

通俗版：

> Hermes 可以大胆做事，但不能偷偷做事。
