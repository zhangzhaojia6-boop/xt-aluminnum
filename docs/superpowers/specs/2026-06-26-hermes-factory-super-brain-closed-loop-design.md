# Hermes 工厂超级大脑闭环升级设计

日期：2026-06-26

状态：正式 spec

## 1. 一句话目标

Hermes 要从“会查日报和产量的机器人”升级为 `鑫泰铝业 数据中枢` 的工厂超级大脑。

它的核心闭环是：

```text
感知输入
  -> 理解意图
  -> 统一口径
  -> 思考计划
  -> 调用工具
  -> 生成结果
  -> 接收反馈
  -> 沉淀知识
  -> 下次变强
```

日报、产量、能耗、库存只是第一批验收场景，不是 Hermes 的能力边界。

Hermes 最终要覆盖全厂业务，能像一个懂生产、懂经营、懂工艺、会查数据、会写材料、会做文件、会复盘问题、会推动改造的综合智能体。

## 2. 背景

当前 Hermes 已经具备部分数据查询和日报生成能力，但还存在几个关键问题：

1. 它更像固定命令机器人，不够像自然语言大模型。
2. 钉钉里 `/今日产量` 这类斜杠命令会被平台拦截，导致用户体验差。
3. 常见业务问法没有先用规则快速识别，全部交给模型会慢，也容易不稳定。
4. RAG、数据查询、工具调用、skill、Codex 施工层还没有完全统一。
5. MES、WMS、数据中枢、钉钉文件、历史日报之间缺少强归一化层。
6. Hermes 的反馈学习还不够闭环，纠错不能稳定变成正式知识。
7. 钉钉上缺少“处理进度可见”的体验，用户不知道 Hermes 在查什么。
8. Hermes 还缺少成果物生成层，不能稳定生成表格、文档、图表、图片。
9. browse 和 computer use 能力还没有作为正式工具路径纳入整体编排。
10. 新 skill 的生产方式还不够规范，容易变成零散 prompt。

本 spec 的目标是把这些能力合成一个统一的 `Factory Brain Runtime`。

## 3. 产品定位

系统正式名称：

```text
鑫泰铝业 数据中枢
```

注意：

- `数据中枢` 是本系统身份。
- `MES` 是外部生产系统和数据源，不是本系统名称。
- `WMS` 是仓储数据源。
- 钉钉文本、钉钉文件、历史日报也属于重要数据源。

Hermes 的定位：

```text
鑫泰铝业工厂超级大脑
```

它不是单纯的日报统计助手，而是全厂业务智能体。

## 4. 核心原则

### 4.1 自然语言优先

用户不需要学习命令。

下面这些都应该能被 Hermes 理解：

```text
产量
今天怎么样
昨日日报
1650 今天是不是低了
本月经营情况总结一下
能耗是不是异常
帮我看一下今天生产哪里不对劲
```

规则识别在后台做，不暴露给用户。

### 4.2 规则先行，模型兜底

常见业务问法先走规则识别。

规则识别不到，再交给模型判断。

```text
自然语言输入
  -> 常见业务规则识别
  -> 识别成功：进入对应业务工作流
  -> 识别失败：模型判断意图
  -> 非业务问题：模型直接回答
  -> 模糊问题：自然追问
```

这样既快，又保留大模型的灵活。

### 4.3 归一化层是核心底座

归一化层优先级高于继续堆 prompt 和 skill。

Hermes 必须先把不同来源的数据翻译成统一的工厂语言，再做分析和输出。

归一化对象包括：

- 组织：车间、分厂、产线、机组、工序。
- 指标：产量、入库量、投料、成品率、能耗、成本、库存、合同。
- 时间：自然日、业务日、班次日、月累计、年累计。
- 单位：吨、kg、支、根、度、m3、万元、元/吨。
- 口径：包装产量、入库成品、外加工、寄存、在制料。
- 数据源优先级：钉钉责任人文件、MES、WMS、数据中枢、历史日报、RAG。
- 可信度：来源、更新时间、口径、置信度。

### 4.4 数字必须可追溯

Hermes 内部每个关键数字都必须带来源。

示例：

```json
{
  "metric": "daily_output",
  "value": 366.21,
  "unit": "ton",
  "date": "2026-06-19",
  "scope": "factory",
  "source": "dingtalk_daily_report",
  "source_file": "6月19日日报.txt",
  "business_definition": "入库成品日合计，含寄存",
  "confidence": 0.96
}
```

给用户展示时按场景决定：

- 简短问答：展示核心数字和简单来源。
- 正式日报/月报/经营分析：展示完整来源、口径、异常和未确认项。

### 4.5 不展示完整思维链，展示可审计步骤

钉钉上不要展示模型内部逐字思考过程。

应该展示“可审计工作步骤”：

- 正在理解问题。
- 已识别业务意图。
- 正在查询数据源。
- 正在校验口径。
- 正在生成结果。
- 等待用户反馈。

这能让用户知道 Hermes 在工作，又不会把中间猜测误当结论。

## 5. 权限原则

最高权限用户：

```text
root_owner：张兆嘉
```

权限设计：

1. root_owner 可以授权 Hermes 直接执行高权限动作。
2. 其他人只能提交普通业务请求、查看自己权限内的结果。
3. 其他人不能提交候选施工任务。
4. 涉及正式规则、正式知识、系统改造、跨部门分发时，以 root_owner 权限为准。

Hermes 可以自主做：

- 分析。
- 查询。
- 整理。
- 建议。
- 草拟。
- 生成日报。
- 发现异常。
- 读取授权范围内的钉钉文本和文件。
- 生成候选知识。
- 生成 Codex 施工单。

真实业务变更按权限执行。

## 6. 总体架构

目标架构：

```text
DingTalk / Web / API 输入
  ↓
Factory Brain Runtime
  ├─ Intent Router：自然语言意图识别
  ├─ Normalization Layer：统一工厂口径
  ├─ LangGraph Orchestrator：决定下一步
  ├─ LangChain Tool Layer：封装模型、工具、RAG、API
  ├─ Skill Registry：选择业务技能
  ├─ Data Query Layer：MES / WMS / 数据中枢 / 钉钉 / 历史日报
  ├─ RAG Layer：四层知识库
  ├─ Artifact Engine：表格 / 文档 / 图表 / 图片
  ├─ DingTalk Card Layer：互动卡片进度和反馈
  ├─ Feedback Loop：纠错和学习
  ├─ Meta Skill Factory：生产新 skill
  └─ Codex Worker：施工层改造
  ↓
文本 / 互动卡片 / 文件 / 图片 / 报表 输出
```

LangGraph 负责流程和状态。

LangChain 负责工具封装、RAG、模型调用。

Skill 负责可复用业务能力。

Meta Skill 负责生产新 skill。

Codex 负责改代码、补接口、补测试、补知识库。

## 7. 主链路设计

### 7.1 感知

输入来源：

- 钉钉私聊。
- 钉钉群聊。
- 钉钉群文件。
- 钉钉责任人文本。
- 数据中枢页面/API。
- MES SQL Server 只读。
- WMS。
- 历史日报文件。
- 用户上传的表格、文档、图片。
- browse 读取的网页。
- computer use 操作得到的页面和文件。

钉钉文件读取范围：

- 覆盖群聊里的聊天记录和文件。
- 支持按专项责任人定义采样范围。
- 支持文本、表格、文档、图片 OCR。

### 7.2 意图识别

第一层：规则识别常见业务问法。

示例：

```text
产量 -> production_daily
今日产量 -> production_daily
昨日日报 -> daily_report
本月经营情况 -> monthly_operation
年度经营情况 -> yearly_operation
成品率 -> yield_analysis
能耗 -> energy_analysis
库存 -> inventory_query
合同余量 -> contract_balance
```

第二层：模型兜底。

模型判断：

- 是否为业务问题。
- 属于哪个业务域。
- 是否需要追问。
- 是否需要查数据。
- 是否只是普通闲聊。

第三层：非业务直答。

如果不是业务问题，Hermes 直接以通用大模型方式回答，可以轻松、自然、诙谐。

### 7.3 归一化

归一化层输出标准对象。

示例：

```json
{
  "intent": "production_daily",
  "date": "today",
  "business_date": "2026-06-26",
  "scope": "factory",
  "org_units": ["factory"],
  "metrics": ["daily_output", "monthly_output", "workshop_detail"],
  "preferred_output": "short_answer"
}
```

归一化层必须维护：

- 车间别名表。
- 指标定义表。
- 单位换算表。
- 时间规则。
- 口径规则。
- 数据源优先级。
- 权限和接收人规则。

### 7.4 计划

Hermes 遇到业务问题后，不直接生成答案。

先生成执行计划：

```text
要回答什么
需要哪些指标
优先查哪些数据源
需要不需要 RAG
需要不需要钉钉文件
是否需要生成文件
是否需要互动卡片
是否需要反馈学习
```

### 7.5 工具调用

工具优先级：

```text
API / SQL / 文件解析
  -> browse
  -> computer use
  -> 人工追问
```

原则：

- 能用 SQL/API 就不用网页点选。
- 能用文件解析就不用截图识别。
- browse 适合网页读取和公开资料。
- computer use 适合没有 API 的人工流程。

### 7.6 输出

输出分两类。

正式业务输出：

- 日报。
- 月报。
- 年报。
- 经营分析。
- 车间明细。
- 发给不同人的正式版本。

自由对话输出：

- 简短解释。
- 分析建议。
- 问题复盘。
- 轻松闲聊。
- 主动追问。

Hermes 需要根据用户语气自动切换。

### 7.7 反馈学习

学习分三档：

1. 自动记忆  
   记住低风险偏好，比如日报格式、输出长短、常问指标。

2. 候选知识  
   涉及业务口径、数据映射、车间规则、责任人文件来源、异常判断逻辑时，先生成候选知识。

3. 正式知识  
   经 root_owner 确认，或经 Codex 验证后，写入正式知识库。

闭环：

```text
用户纠错
  -> Hermes 生成候选知识
  -> Codex 验证代码/数据/文档
  -> root_owner 确认或低风险自动通过
  -> 写入正式知识库
  -> 后续回答生效
```

## 8. 数据源优先级

默认优先级：

1. 钉钉专项责任人文件/文本。
2. MES 原始明细。
3. WMS 原始明细。
4. 数据中枢归一化结果。
5. 历史日报成品。
6. RAG 知识库。
7. 大模型自身知识。

说明：

- RAG 不作为数字事实源。
- 大模型不能凭空生成数字。
- 历史日报用于对齐模板、反推口径、校验累计值。
- 责任人确认过的钉钉文件优先级最高。

## 9. 四层 RAG 设计

RAG 不能混成一个大库。

分为四层：

### 9.1 行业通用知识

覆盖：

- 铝加工。
- 铸轧。
- 铸锭。
- 热轧。
- 冷轧。
- 退火。
- 拉矫。
- 精整。
- 剪切。
- 彩涂。
- 回收。
- 能耗。
- 成品率。
- 质量缺陷。
- 工艺参数。

### 9.2 鑫泰本厂工艺知识

覆盖：

- 本厂车间。
- 机组。
- 产线。
- 工艺路径。
- 特殊叫法。
- 统计口径。
- 日报模板。
- 车间明细。
- 历史修正规则。

### 9.3 数据路由知识

覆盖：

- 某类问题去哪查。
- 哪些表可信。
- 哪些表只能参考。
- 钉钉文件怎么找。
- MES/WMS/数据中枢如何互相校验。

### 9.4 经验型知识

来源：

- 用户纠错。
- Codex 验证。
- 历史问答。
- 历史日报反推。
- 异常复盘。

检索顺序：

```text
鑫泰本厂口径
  -> 数据路由知识
  -> 行业通用知识
  -> 经验型知识
  -> 模型推理
```

## 10. RAG 查不到时的行为

Hermes 不能瞎编，也不能只说不知道。

标准行为：

1. 说明当前缺口。
2. 输出能确认的临时答案。
3. 标注置信度和来源。
4. 给出补数方案。
5. 生成候选知识任务。
6. 等待确认或继续查证。

示例：

```text
目前 MES 有包装产量，但没有命中外加工口径。
WMS 入库量可作为校验，钉钉日报文件暂未找到。
我先给出临时值，并创建补数任务：补齐 2026-06-25 外加工产量口径。
```

## 11. DingTalk 互动卡片设计

钉钉上使用互动卡片展示进度。

要求：

- 不刷屏。
- 同一张卡片持续更新。
- 展示可审计步骤。
- 支持反馈按钮。

卡片阶段：

```text
已接收
  -> 已识别
  -> 查询中
  -> 校验中
  -> 生成中
  -> 已完成
  -> 等待反馈
```

卡片示例：

```text
Hermes 正在处理：今日产量

当前阶段：数据校验中
已识别：生产日报 / 今日 / 全厂
已查询：MES、WMS、数据中枢
正在补充：钉钉日报文件
数据状态：2 个指标已对齐，1 个指标待确认

[查看来源] [重新查询] [采纳结果] [标记不准]
```

可用官方能力参考：

- 钉钉互动卡片。
- 机器人发送互动卡片。
- 按卡片业务 ID 更新同一张卡片。

## 14. 成果物生成层

Hermes 必须具备一等成果物能力。

新增 `Artifact Engine`。

支持：

1. 表格  
   Excel、CSV、经营指标表、车间明细表、异常清单、对账表。

2. 文档  
   Word、PDF、日报、月报、年报、经营分析、会议纪要、问题复盘。

3. 图表  
   趋势图、柱状图、折线图、车间对比图、异常热力图。

4. 图片  
   经营看板截图、流程图、工艺图、知识卡片。

5. 图像生成  
   可接图像生成 API，用于培训材料、汇报封面、流程示意、宣传图。

原则：

- 表格、文档、图表优先用 skill 和本地脚本生成。
- AI 图片接图像生成 API。
- 生成图不能当真实现场照片。
- 重要报表必须保存源数据快照和生成参数。
- 文件发送到钉钉后要记录版本和来源。

## 17. Meta Skill Factory

所有新增 skill 优先走 Meta Skill 流程。

流程：

```text
发现能力缺口
  -> 生成 skill 需求说明
  -> 查 GitHub 是否有成熟 skill/agent 设计
  -> 有成熟设计：参考结构，本地化改造
  -> 没有成熟设计：用 Meta Skill 生成新 skill
  -> Codex 验证
  -> 真实业务案例测试
  -> root_owner 确认
  -> 进入正式 Hermes skill 库
```

Meta Skill 需要生成：

- `SKILL.md`
- `scripts/`
- `references/`
- `assets/`
- 示例输入输出。
- 工具权限说明。
- 测试用例。
- 失败兜底策略。

示例：

```text
factory-normalization/
  SKILL.md
  references/
    xintaily_workshop_aliases.md
    metric_definitions.md
    unit_rules.md
    data_source_priority.md
  scripts/
    normalize_metric.py
    normalize_org.py
    normalize_time.py
  tests/
    test_normalization_cases.py
```

说明：

- 先参考 GitHub 上成熟的 skill/agent 设计。
- 若没有合适设计，再用 Meta Skill 自研。
- 不复制无关开源内容，只吸收结构和方法。
- 强业务 skill 必须本地化到鑫泰铝业。

## 18. Codex 施工层

Hermes 可以调用 Codex，但必须通过施工单。

适合调用 Codex 的场景：

- 缺少数据接口。
- SQL 查询不准。
- 需要新增日报字段。
- 需要补归一化规则。
- 需要新增 RAG 文档。
- 需要修 Hermes skill。
- 需要写测试。
- 需要把候选知识落成代码、文档或配置。

施工单格式：

```json
{
  "title": "补齐 1650 车间日产量归一化规则",
  "reason": "用户反馈 1650冷轧 与 1650车间 是同一口径",
  "evidence": ["钉钉反馈", "历史日报样例", "MES字段"],
  "expected_change": "新增别名映射和测试",
  "approval": "张兆嘉"
}
```

Codex 完成后必须：

- 运行测试。
- 输出变更摘要。
- 给 Hermes 回传结果。
- 需要时生成候选知识。

## 19. 记忆和人格

Hermes 需要有长期人格定义。

人格方向：

```text
懂工厂、懂生产、聪明、主动、轻松、有趣、诙谐，但正式业务输出严谨可靠。
```

它可以开玩笑，但不能拿数字开玩笑。

记忆内容：

- root_owner 偏好。
- 日报模板。
- 常用指标。
- 常问问题。
- 常用输出格式。
- 常用接收人。
- 纠错历史。
- 已确认业务规则。

## 23. 验收标准

Day-1 MVP 验收标准：

1. 钉钉自然语言可用  
   用户发 `产量`、`今天怎么样`、`昨日日报`、`本月经营情况`，Hermes 能正确识别。

2. 常见业务问题有结果  
   生产、仓储、合同、成品率、能源、成本、异常分析 7 类能回答。

3. 数字可追溯  
   每个关键数字内部有来源、口径、日期、单位、置信度。

4. 日报能对齐历史成品  
   用 D 盘历史日报真实值测试，核心指标误差必须可解释。

5. 互动卡片能显示进度  
   钉钉不刷屏，同一张卡片更新状态。

6. RAG 不胡说  
   检索不到时说明缺口，并给下一步方案。

7. 反馈能进入学习闭环  
   用户纠错后，Hermes 能生成候选知识，验证后变成正式知识。

8. 能生成成果物  
   至少支持文本、表格、文档、图表。

9. 能调用 Codex  
   Hermes 能生成施工单，让 Codex 补规则、补接口、补测试。

10. 模型路径稳定  
    不再出现 `Codex token refresh failed with status 401` 影响钉钉主流程。

## 24. 非目标

Day-1 不做：

- 一次性覆盖所有工厂业务深水区。
- 让 RAG 代替真实数字来源。
- 让大模型凭空编造经营数字。
- 把完整模型思维链展示给用户。
- 把所有开源 skill 原样复制进系统。
- 让 computer use 替代稳定 API 和 SQL。

## 25. 成功状态

当用户在钉钉里随口说：

```text
今天怎么样？
```

Hermes 应该能做到：

1. 识别这是经营/生产综合问题。
2. 自动查生产、入库、合同、能耗、成本、成品率。
3. 用归一化层统一口径。
4. 对照历史日报和钉钉文件。
5. 找出异常。
6. 生成简短结论。
7. 可展开为正式日报、表格、文档或图表。
8. 在钉钉卡片上显示处理进度。
9. 接收用户纠错。
10. 把确认过的新口径沉淀为正式知识。

这才是 Hermes 作为工厂超级大脑的 Day-1 成功状态。
