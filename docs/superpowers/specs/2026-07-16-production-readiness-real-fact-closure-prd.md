# 鑫泰铝业数据中枢真实事实闭环投产 PRD

## Problem Statement

鑫泰铝业数据中枢和 NousResearch Hermes 的基础服务已经能够运行，MES/WMS 只读同步也处于健康状态，但“服务在线”还不能证明系统可以正式替代人工完成生产日报和业务追踪。

当前生产证据显示：

- 最近三个已完成业务日的纯真实源答案钥匙已出现字段匹配率仅为 8.66%（11/127）、6.30%（8/127）、5.83%（7/120）；其中 2026-07-13 按 127 字段规范覆盖率计算仅为 5.51%（7/127），另有 7 个 `reference_absent` 字段尚未取得 N/A 或补证结论。
- 五个关键事实尚不能在每个业务日都给出可信来源、状态和 trace。
- Hermes 20 问核心答案为 12/20，发送链路为 20/20。
- 钉钉 Stream 已连接，但验收时尚未取得服务启动后的真实聊天和文件入库证据。
- 当前 20 问主要验证数据中枢确定性 Agent，不能完整证明 NousResearch Hermes 原生推理和工具调用能力。
- Hermes 原生回复与数据中枢业务回复存在双轨职责，尚未形成唯一调度和幂等回复合同。

系统真正需要解决的不是继续增加页面，而是形成每天可重复证明的事实闭环：真实消息和数据库记录进入系统，日报只使用真实来源，缺失字段自动形成补录任务，Hermes 能理解、查证、推动补齐，并且所有结果可审计、可恢复、可回滚。

## Solution

建立一条由 Phase 0 基线和 Phase 1 至 Phase 13 组成的十四阶段投产路径。每个阶段都使用同一闭环顺序：冻结证据、建立失败用例、完成最小修改、执行自动测试、执行真实环境验证、进行规格评审、进行代码质量评审、验证回滚、提交同步、归档证据。当前阶段门禁没有通过时，不进入下一阶段。

系统最终保持两个清晰边界：

- 鑫泰铝业数据中枢负责扫码填报、事实存储、MES/WMS 投影、日报事实包、管理大仪表盘、任务、审计和可回滚业务动作。
- NousResearch Hermes 增强智能体负责钉钉入口、中文理解、推理、工具选择、主动追踪和统一回复调度。

MES/WMS 始终是外部只读事实源。钉钉聊天和文件是最高优先业务证据入口。`D:\输出skill` 只作为 compare-only 答案钥匙，不得用于生成或补齐生产事实。

## User Stories

1. 作为公司负责人，我希望每天看到一份来源清楚的生产日报，从而知道每个数字都能被查证。
2. 作为公司负责人，我希望日报数字缺失时系统明确说缺什么，而不是生成看似完整的假数字。
3. 作为公司负责人，我希望 Hermes 主动追踪缺口，从而不需要我自己逐个联系责任人。
4. 作为管理人员，我希望在一个管理大仪表盘中看到日报、来源、异常、任务和 trace，从而不在多个入口之间切换。
5. 作为管理人员，我希望能点击数字查看证据，从而判断数字来自钉钉、MES/WMS、扫码补录还是数据中枢投影。
6. 作为管理人员，我希望系统正确区分 13 个活跃生产车间和 15 项宽口径数据，从而避免统计口径混淆。
7. 作为管理人员，我希望系统正确应用标准生产 07:50、铸二/铸三/热轧 10:00、责任人每日一录 09:30 和 10:00 迟报截止，从而避免跨日错算。
8. 作为车间责任人，我希望收到明确的缺字段补录任务，从而知道填什么、填哪一天、何时截止。
9. 作为车间责任人，我希望通过现有扫码入口完成补录，从而不需要安装或学习新的系统。
10. 作为车间责任人，我希望补录后立即看到任务状态变化，从而确认数据已经进入日报事实包。
11. 作为钉钉用户，我希望普通说法、简称和不完整表达也能被保存，从而不会因为关键词不匹配丢失业务证据。
12. 作为钉钉用户，我希望聊天、图片、Excel 和 PDF 都能进入证据链，从而保留真实工作方式。
13. 作为钉钉用户，我希望重复事件不会产生重复回复或重复事实，从而避免群内干扰。
14. 作为钉钉用户，我希望 Hermes 始终使用中文并以鑫泰铝业智能大脑身份工作。
15. 作为钉钉用户，我希望 Hermes 在证据冲突时解释冲突并继续查证，而不是静默选择一个数字。
16. 作为数据管理员，我希望 MES/WMS 连接始终只读，从而不会由本系统改坏外部生产系统。
17. 作为数据管理员，我希望看到 MES/WMS 同步游标、延迟和错误，从而能及时处理断线或口径变化。
18. 作为数据管理员，我希望责任人纠错保留修改前后证据，从而可以追溯谁在何时修正了什么。
19. 作为系统管理员，我希望密钥不出现在 Git、前端包、截图和普通日志中，从而降低泄露风险。
20. 作为系统管理员，我希望数据库可以从真实备份恢复，从而在发布失败时可以恢复业务。
21. 作为系统管理员，我希望每条外部消息只产生一次正式回复，从而避免 Hermes 与数据中枢重复发言。
22. 作为开发维护者，我希望每个阶段都有失败测试和回归测试，从而能区分旧问题和新回归。
23. 作为开发维护者，我希望旧入口只有在零访问和零依赖证据下才删除，从而安全完成数据中枢减法。
24. 作为验收人员，我希望使用真实角色测试管理端和扫码端，从而不把管理员账号错误地当作一线填报角色。
25. 作为验收人员，我希望连续七个业务日观察自动日报，从而证明系统不是偶然通过一天。
26. 作为验收人员，我希望正式 20 问和额外模糊问题都走 NousResearch Hermes 原生循环，从而验证真正的智能体能力。
27. 作为验收人员，我希望答案钥匙只参与比较，从而确认日报确实由真实事实源生成。
28. 作为验收人员，我希望所有可比数字采用字段级误差阈值且绝不超过 20，从而不通过放宽门槛制造成功。
29. 作为发布负责人，我希望灰度发布前有备份、版本标签和回滚命令，从而可以安全放量。
30. 作为公司负责人，我希望只有全部证据门禁通过后才宣布可投产，从而避免把健康检查等同于业务完成。

## Implementation Decisions

- 以一个结构化的“生产就绪门禁”作为最高测试接缝，汇总各阶段状态、证据位置、失败原因和回滚状态。
- 每个阶段必须独立可验证、可提交、可回滚，不在一个提交中混合多个阶段的业务改动。
- 当前业务时间合同以现行代码为准：标准生产业务日 07:50 起算；铸二、铸三、热轧 10:00 起算；责任人每日一录 09:30 起算；责任人迟报截止为 10:00。
- 钉钉企业内部应用的授权范围是接收边界，不增加硬群边界或硬关键词拒绝规则。
- 所有钉钉事件先持久化和建立 trace，再决定是否回复或是否能够提取事实。
- 钉钉聊天和文件是最高优先业务证据。授权责任人修正属于显式纠错通道，必须保留原值、理由、责任人和审计记录，不得静默覆盖。
- MES/WMS 连接保持 SQL Server 只读，只允许已登记查询；数据中枢页面只读取本地投影或事实服务。
- 日报事实包只接收真实来源。答案钥匙仅用于 compare-only 验证。
- 日报合同固定包含 127 个规范字段。每天的答案钥匙可以少写字段，但只有被明确声明为 N/A 的字段才能从当日匹配分母中扣除；未写且未声明 N/A 的字段记为 `reference_absent`，保持门禁阻塞。
- 对齐报告同时输出“答案钥匙已出现字段匹配率”和“127 字段规范覆盖率”，最终投产必须同时满足规范覆盖和匹配要求，不能通过缩小分母过关。
- 五个关键事实必须全部确认才能发布日报。整体字段匹配率目标为每个业务日不低于 90%。
- 数值阈值按字段和单位定义，任何可比数值的绝对容差不得超过 20；百分比等字段使用更严格阈值。
- Hermes 正式验收必须穿过 NousResearch Hermes 原生推理和工具调用循环，不能只调用数据中枢确定性回答器。
- `hermes-gateway` 是钉钉智能调度优先入口。数据中枢保留事实、任务、动作和 outbox，但正式回复必须遵守唯一所有者合同。
- Hermes 可自主读取、分析、生成日报、创建任务、要求补录和发送审计内提醒。MES 写入和不可逆数据操作不属于自主权限。
- 数据中枢界面只围绕 `/entry` 和 `/manage` 收口，不新增日报门户或第二套管理大屏。
- 删除旧页面、路由、服务或文档前必须证明零访问、零依赖且不属于受保护链路。
- 第一次真实钉钉验收前轮换已暴露的钉钉凭据、执行密钥扫描并建立可恢复备份；投产前再次验证角色权限、数据库恢复和密钥状态。
- 最终采用连续七个已完成业务日影子运行和灰度发布，不采用一次性通过作为投产证明。

## Testing Decisions

- 单元测试只验证可观察行为，例如事件是否入库、事实是否确认、重复事件是否幂等、缺字段是否形成任务。
- 集成测试覆盖钉钉 Stream 到数据中枢证据、MES/WMS 到本地投影、事实包到日报、缺口到扫码补录、Hermes 到 outbox 的完整链路。
- 合同测试锁定来源顺序、业务时间、字段单位、误差阈值、只读 SQL 和唯一回复所有者。
- 生产验证优先使用只读查询。会产生外部消息或业务写入的测试必须使用明确验收目标并记录副作用。
- 浏览器验收分别使用管理员、车间主任和真实填报角色，不使用管理员代替扫码填报角色。
- Hermes 通过正式 20 问、30 个模糊或冲突问题和零生产数字幻觉门禁。
- 日报先验证最近三个已完成业务日，再连续影子运行七个业务日。
- 每个阶段完成前必须进行规格符合性评审和代码质量评审，所有发现修复后重新评审。
- 发布验证必须同时检查应用健康细项、真实数据库样本、消息证据、日报对齐、浏览器页面和回滚能力。

## Out of Scope

- 新建独立日报门户、第二套管理大屏或新的移动端应用。
- 将本产品重命名为 MES，或向外部 MES/WMS 写入数据。
- 使用 RAG、历史答案或 `D:\输出skill` 填充实时生产数字。
- 为通过验收而放宽来源要求、提高误差上限或把缺失值改成零。
- 在没有访问和依赖证据时大规模删除旧链路。
- 在本 PRD 内接入尚未具备凭据和正式字段合同的未来能耗数据库。
