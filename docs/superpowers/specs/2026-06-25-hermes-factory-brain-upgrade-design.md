# Hermes 全厂业务工厂大脑升级设计

日期：2026-06-25

状态：正式 spec

## 1. 一句话目标

Hermes 不再是日报统计助手，也不是固定命令机器人。

Hermes 要升级为 `鑫泰铝业 数据中枢` 的全厂业务工厂大脑：

```text
听懂自然语言
  -> 主动查证全厂数据
  -> 理解生产、经营、工艺和质量
  -> 判断风险和冲突
  -> 推动低风险动作
  -> 调用 Codex 做施工层任务
  -> 沉淀长期规则、知识和经验
  -> 用轻松有趣但严谨可靠的方式与 root_owner 互动
```

日报只是第一个验收场景，不是 Hermes 的能力边界。

## 2. 背景和当前问题

当前 Hermes 已经能回答部分产量、日报、异常类问题，但仍有明显短板：

1. 它更像固定命令机器人，不像制造业超级大脑。
2. `在干嘛`、`产量出来了吗` 这类自然表达没有被当成上下文型业务意图。
3. root_owner 不能方便地下达高级提示词和长期工作规则。
4. 钉钉文本和文件还没有形成严格的授权采样体系。
5. RAG 还不够专业，没有按铝加工通用知识、鑫泰现场工艺、字段、规则、案例、输出口径分层。
6. Day-1 日报能力容易把 Hermes 拉回“日报助手”定位。
7. 截图中的 `Codex token refresh failed with status 401` 说明当前模型层有鉴权失效风险，需要降级兜底。

本 spec 解决的是主架构方向，不是修几个命令。

## 3. 产品定位

系统名称必须使用：

```text
鑫泰铝业 数据中枢
```

`MES` 是外部生产系统和数据源，不是本系统名称。

Hermes 的定位：

```text
全厂业务工厂大脑
```

它覆盖：

- 生产
- 库存
- 发货
- 合同
- 质量
- 能耗
- 成本
- 设备
- 人员
- 异常
- 工艺
- 经营分析

第一阶段不一次铺满所有业务，先做深一期三域。

## 4. 一期业务范围

一期先覆盖三个高价值业务域。

### 4.1 生产域

覆盖：

- 产量
- 投料
- 入库
- 在制
- 道次
- 开机
- 停机
- 异常

典型问题：

```text
今天产量出来了吗？
1650 为什么产量低？
今日入库和包装产量差多少？
今天哪个车间异常最大？
```

### 4.2 经营域

覆盖：

- 合同
- 余合同
- 发货
- 库存
- 成品率
- 成本
- 电费
- 气费

典型问题：

```text
今天生产和发货会不会影响合同交付？
库存够不够支撑这批合同？
今天吨成本为什么高？
```

### 4.3 工艺/质量域

覆盖：

- 合金
- 规格
- 工艺路线
- 铸轧
- 铸锭
- 热轧
- 冷轧
- 退火
- 拉矫
- 精整
- 剪切
- 质量异常

典型问题：

```text
2050 今天吨电耗为什么高？
这个规格走哪条工艺路线？
热轧异常会影响后续哪些工序？
```

暂不作为一期主战场：

- 人事全流程
- 财务全科目
- 设备维修全流程
- 采购全流程

这些业务后续作为可扩展域接入。

## 5. 一期验收场景

一期必须至少用三个场景验收，避免 Hermes 又被做回日报助手。

### 5.1 日报生成

输入示例：

```text
生成 6月19日正式日报
```

验证能力：

- 多源事实采样
- 钉钉专项责任人文件采样
- 日报模板输出
- 冲突透明展示
- 输出 skill 对齐
- 成长反馈

### 5.2 异常分析

输入示例：

```text
2050 今天电耗为什么高？
```

验证能力：

- 识别业务域和指标
- 查询今日事实
- 检索冷轧和吨电耗知识
- 查历史案例
- 查钉钉异常说明
- 给出原因排序和建议动作

### 5.3 经营问答

输入示例：

```text
今天生产和发货有没有影响合同交付？
```

验证能力：

- 打通生产、库存、发货、合同、余合同
- 形成经营判断
- 说明证据和缺口
- 不把单一产量数字当最终经营结论

## 6. root_owner 和权限

最高权限者是 root_owner 张兆嘉。

绑定原则：

```text
dingtalk_user_id / unionid > 钉钉号 > 姓名
```

不能只靠姓名判断最高权限。

root_owner 可以：

- 直接下达任务指令
- 写入长期规则
- 修改、删除、降权长期规则
- 授权 L5 主动性
- 调用 Codex 施工层能力
- 让 Hermes 直接执行重施工
- 查看完整审计、证据、运行状态和学习记录

非 root_owner：

- 可以按权限提供业务证据
- 授权管理者可以提交长期规则候选
- 不能直接写入最高级长期规则
- 不能提交 Codex 施工候选任务
- 不能通过群聊触发改代码、部署或数据修正

## 7. 自然语言入口

Hermes 必须理解自然语言，而不是要求用户记固定命令。

### 7.1 任务指令

任务指令只影响当前任务。

例子：

```text
生成 6月19日正式日报
帮我分析今天产量为什么低
看看今天生产有没有风险
2050 电耗为什么高？
```

### 7.2 工厂大脑长期规则

长期规则会改变 Hermes 以后默认工作方式。

例子：

```text
以后日报先看专项责任人发的钉钉文件
回答我时先给结论，再给数据来源
遇到产量冲突时必须列出冲突来源
```

长期规则必须保存：

- 原始提示词
- Hermes 结构化理解
- 生效范围
- 生效人
- 生效时间
- 当前状态
- 版本
- 审计记录

### 7.3 上下文型自然语言意图

Hermes 必须支持短句、追问、省略表达。

例子：

```text
在干嘛
产量出来了吗
今天正常吗
这个数能信吗
```

处理方式：

- 结合当前任务
- 结合最近对话
- 结合业务日
- 结合数据新鲜度
- 结合 root_owner 权限

不能简单当闲聊丢弃。

## 8. 长期规则管理

长期规则支持自然语言管理，不要求斜杠命令。

Hermes 要听懂：

```text
以后……
记住……
这条作为长期规则……
把刚才那条规则删了
把钉钉文件优先级降一下
查看我给你的长期规则
今天按临时口径，不要记住
这次只是临时任务
```

对应动作：

- 新增长期规则
- 修改长期规则
- 删除长期规则
- 降权长期规则
- 查看长期规则
- 临时覆盖但不入库

生效分级：

```text
低风险规则：直接生效并回显
高影响规则：先回显结构化理解，等待 root_owner 确认
```

高影响规则包括：

- 改变事实优先级
- 自动写数据中枢
- 对外分发
- 权限变更
- 批量行为
- Codex 重施工

## 9. 钉钉四条件采样

钉钉文件和聊天记录是高优先级补充数据，但不能默认扫描所有群。

Hermes 读取钉钉历史聊天记录、文本、文件和图片时，必须同时满足四个条件：

```text
1. 授权群
2. 专项责任人
3. 内容类型
4. 时间范围
```

四个条件缺一项时，只能作为低权重线索，不能直接进入高优先级日报事实采样。

示例：

```text
授权群：生产日报群、仓库日报群
专项责任人：产量负责人、入库负责人、能耗负责人
内容类型：日报、产量表、库存表、发货表、能耗表、异常说明
时间范围：默认最近 30 天；历史日报可追溯到当月 1 日
```

每条钉钉证据必须记录：

- 群
- 发送人
- 专项责任人身份
- 消息时间
- 采样时间
- 文件名
- 文件哈希
- 内容类型
- 业务日期
- 解析状态
- 证据等级
- 是否进入事实采样

## 10. 日报事实优先级

事实采用顺序：

```text
1. root_owner 直接确认或修正
2. 满足四条件的专项责任人钉钉证据
3. 数据中枢已落库事实
4. MES/WMS 只读原始数据
5. RAG、历史日报、输出 skill 口径参考
```

RAG、历史日报和输出 skill 不能直接当今天实时事实。

冲突规则：

```text
高优先级来源优先采用
但必须透明展示冲突来源、冲突值、采用原因和建议动作
```

示例：

```text
采用值：366 吨
采用来源：生产日报群，专项责任人发送的《每日产量.xlsx》
冲突来源：
- 数据中枢：361 吨
- MES：359.8 吨
采用原因：专项责任人授权文件优先级更高，且文件时间晚于数据中枢更新时间。
建议动作：将数据中枢对应字段标记为待核对，必要时发起修正记录。
```

Hermes 不能隐藏冲突，也不能因为有冲突就完全不答。

## 11. RAG 知识库设计

RAG 不是实时数字库。

RAG 负责帮助 Hermes 理解：

- 铝加工工业知识
- 鑫泰现场工艺
- 字段含义
- 规则
- 历史案例
- 输出口径
- 判断方法

实时事实仍来自：

- 日报事实包
- 数据中枢
- MES/WMS 只读数据
- 授权钉钉证据
- 审计记录

### 11.1 知识分层

RAG 至少分为六层：

```text
A. 铝加工通用工业知识
B. 鑫泰现场个性化工艺知识
C. 数据中枢字段和表关系知识
D. MES/WMS 外部系统字段知识
E. 历史日报和输出 skill 口径知识
F. 典型异常案例知识
```

### 11.2 六类知识单元

最小知识单元不按整篇文档粗切，而按业务知识类型建设：

```text
1. 工艺单元
2. 指标单元
3. 字段单元
4. 规则单元
5. 案例单元
6. 输出口径单元
```

例子：

用户问：

```text
2050 今天吨电耗为什么高？
```

Hermes 应组合：

- 2050 现场知识
- 吨电耗指标定义
- 冷轧工艺知识
- 历史异常案例
- 今日事实数据
- 钉钉异常说明

### 11.3 路由检索

Hermes 检索 RAG 前必须先判断：

- 业务域
- 对象
- 指标
- 时间
- 需要的事实源
- 需要的知识类型

不能把所有问题直接丢给向量搜索。

### 11.4 RAG 非事实边界

RAG 不保存每日动态事实数字。

不能把这些当知识塞进去：

```text
6月19日总产量 366 吨
今天 2050 产量 80 吨
今日入库 228.60 吨
```

这些应该进入事实库、日报事实包、历史日报和审计记录。

历史案例可以引用数字，但只能作为案例的一部分，不能作为当前事实来源。

## 12. 知识反推和 Codex 验证转正

Hermes 可以通过深入使用 MES、数据中枢、历史日报、钉钉证据和输出 skill，自动反推候选知识。

反推内容包括：

- 字段含义
- 表关系
- 工艺路径
- 业务规则
- 异常模式
- 检索标签
- 专项责任人文件规律
- 输出口径

知识状态：

```text
候选知识：Hermes 自动总结，未验证
正式知识：经过 Codex 验证通过
废弃知识：发现不准、过期或不适用
```

Codex 验证通过后，候选知识可直接转为正式知识。

Codex 验证必须保留：

- 验证时间
- 验证方法
- 验证证据
- 涉及代码、数据库、页面或样本
- 知识版本

## 13. LangChain / LangGraph 原生落地

本项目直接落地 LangChain 和 LangGraph，不只做自研等价层。

### 13.1 LangChain 职责

LangChain 负责：

- 模型调用
- 工具注册
- 工具调用
- 结构化输出
- RAG 接入
- Agent 工具链

工具必须白名单化。

一期工具包括：

- 数据中枢查询工具
- MES 只读查询工具
- WMS 只读/投影查询工具
- 钉钉证据工具
- RAG 路由检索工具
- 历史日报工具
- 输出 skill 对齐工具
- 长期规则工具
- Codex 施工工具

### 13.2 LangGraph 职责

LangGraph 负责：

- 状态图
- checkpoint
- 可恢复执行
- 人机确认
- 长任务编排
- 节点级重试
- 工具调用轨迹
- 状态可视化和审计

核心状态流：

```text
received
  -> identify_actor
  -> classify_intent
  -> load_soul_rules_knowledge
  -> plan_task
  -> route_tools
  -> collect_evidence
  -> reason_about_conflicts
  -> act_or_prepare_action
  -> generate_response
  -> persist_memory_and_audit
  -> reply_to_dingtalk
```

阻断状态：

```text
unauthorized
model_degraded
missing_required_facts
source_failed_visible
needs_root_owner_confirmation
codex_construction_not_authorized
persistence_failed
```

### 13.3 checkpoint 存储

LangGraph checkpoint 直接存入数据中枢 PostgreSQL。

不要单独起孤立状态库。

建议保存分工：

```text
LangGraph checkpoint：
保存可恢复执行状态。

agent_runs.result_payload：
保存业务可读摘要、工具调用轨迹和最终结论。

Hermes 记忆/知识表：
保存长期规则、候选知识、正式知识、学习反馈。
```

## 14. Codex 施工层能力

Hermes 可以调用 Codex 执行工程施工层任务。

Hermes 负责：

- 提出业务目标
- 提供证据
- 定义验收标准
- 判断是否需要施工

Codex 负责：

- 读代码
- 分析架构
- 修改代码
- 补测试
- 写迁移
- 优化 RAG 管道
- 生成脚本
- 部署验证
- 修复生产问题

只有 root_owner 可以触发 Codex 施工。

非 root_owner：

- 不能提交施工候选任务
- 不能通过群聊触发改代码
- 不能触发生产部署

### 14.1 轻施工

低风险任务：

- 读代码
- 查日志
- 跑测试
- 生成 spec / plan
- 总结系统架构
- 建知识库条目
- 写只读脚本

### 14.2 重施工

高影响任务：

- 改代码
- 改数据库结构
- 改生产配置
- 部署生产
- 执行数据修正
- 删除或迁移历史数据

root_owner 可以直接授权重施工。

每次重施工必须记录：

- root_owner 原始指令
- Hermes 拆解目标
- Codex 改了哪些文件
- 跑了哪些测试
- 是否部署生产
- 回滚方式
- 最终验收结果

## 15. Hermes 主动性

Hermes 默认 L4 主动性。

```text
L1 被动回答：
用户问什么答什么。

L2 主动补证据：
用户问产量，Hermes 主动查钉钉、数据中枢、MES/WMS。

L3 主动发现风险：
Hermes 主动发现电耗异常、入库不同步、产量异常。

L4 主动发起低风险动作：
自动归档文件、生成待核对清单、生成日报草稿、建议长期规则。

L5 root_owner 授权后主动重施工：
调用 Codex 改系统、修链路、部署生产、执行高影响动作。
```

默认：L4。

L5：只能由 root_owner 授权。

## 16. 模型层和降级运行

短期先继续使用 Codex token 作为临时模型能力来源。

这是过渡方案，不是长期架构。

后续应迁移到稳定的服务端 LLM Provider。

### 16.1 Codex token 失效时

当出现：

```text
Codex token refresh failed with status 401
```

Hermes 不能直接把英文错误发给用户。

降级策略：

```text
1. 继续执行可用的数据查询
2. 继续读取数据中枢、MES/WMS、钉钉证据、RAG
3. 暂停复杂推理、长文生成和 Codex 施工
4. 用中文提醒 root_owner
```

示例：

```text
模型服务暂不可用，我已记录 trace_id。
当前仍可执行只读数据查询，但复杂分析和 Codex 施工暂时不可用。
```

如果能查到确定性事实，应先报事实：

```text
我现在模型服务未登录，但已查到今日包装产量 239.55 吨，全厂入库 228.60 吨。
复杂分析需要模型恢复后继续。
```

## 17. Hermes Soul.md

Hermes 需要独立的 `Soul.md`。

`Soul.md` 定义 Hermes 的人格、价值观、行为习惯和工厂判断习惯。

人格方向：

```text
有趣
轻松
诙谐
主动
好奇
不死板
```

但业务边界必须严肃：

- 不拿生产安全开玩笑
- 不拿数据准确性开玩笑
- 不拿权限开玩笑
- 不拿成本和经营风险开玩笑
- 不用幽默掩盖不确定性

Soul.md 至少包含：

```text
1. 性格
2. 工作方式
3. 工厂判断习惯
4. 风险边界
5. 与 root_owner 的互动方式
```

默认表达：

```text
闲聊自然轻松
业务判断专业严肃
```

## 18. 三层长期上下文

Hermes 的长期上下文必须三层分开。

```text
Soul.md：
管人格、价值观、行为习惯、工厂判断习惯。

长期规则：
管 root_owner 授权的业务规则、数据优先级、分发策略、施工权限。

RAG 知识库：
管工业知识、现场工艺、字段解释、历史案例、输出口径。
```

禁止混存。

否则会出现：

- 改说话风格误改数据优先级
- 加工艺知识误影响权限规则
- 删除历史案例误删人格设定

## 22. 成功标准

一期完成时，至少满足：

1. Hermes 支持自然语言任务指令，不依赖固定命令。
2. Hermes 支持 root_owner 自然语言管理长期规则。
3. 长期规则保存原文和结构化规则。
4. 钉钉证据按群、专项责任人、内容类型、时间范围四条件采样。
5. 专项责任人钉钉证据优先级高于数据中枢和 MES/WMS。
6. 数据冲突时，高优先级来源可被采用，但冲突必须透明展示。
7. RAG 分层建设，支持六类知识单元和路由检索。
8. RAG 不保存每日动态事实数字。
9. Hermes 直接使用 LangChain / LangGraph。
10. LangGraph checkpoint 存入数据中枢 PostgreSQL。
11. Codex token 失效时，Hermes 可以降级运行。
12. Codex 施工层只允许 root_owner 调用。
13. Hermes 默认 L4 主动性，root_owner 可授权 L5。
14. `Soul.md`、长期规则、RAG 知识库三层分开。
15. 日报生成、异常分析、经营问答三个场景都能通过验收。

## 24. 小白版总结

这次不是让 Hermes 多会几个命令。

这次是让 Hermes 从：

```text
你问一个数，它答一个数
```

升级成：

```text
你说一句业务目标，
它知道该查哪些系统，
知道哪些人发的钉钉文件更可信，
知道铝加工工艺怎么影响产量、能耗和质量，
知道数据冲突时怎么说明，
知道什么时候该学习成规则，
知道什么时候该叫 Codex 去改系统，
还能用轻松自然的方式跟你交流。
```

但底线是：

```text
可以聪明，可以主动，可以有趣。
不能瞎编，不能偷改，不能乱读，不能无痕施工。
```
