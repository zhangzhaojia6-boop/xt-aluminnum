# 鑫泰铝业 数据中枢：前端体验与页面保留审计

日期：2026-06-11

状态：只读审计版，供后续页面合并、删除、重构和测试使用。

## 1. 本轮看了什么

本轮从三个角度看前端：

1. 路由和导航：哪些页面有入口，哪些页面只是隐藏入口或历史跳转。
2. 页面代码：核心页面从哪里取数，是否混用 MES、填报、算法、能耗。
3. 线上体验：用管理员登录后实际打开核心管理端页面，观察页面内容、加载状态、接口状态和用户可理解性。

## 4. 接口对照证据

接口只读对照显示：

1. `/api/v1/aggregation/live?business_date=2026-06-11` 返回 `factory_total.packaging_output=177.61`，`daily_output=177.61`，`finished_inbound_output=0`，`business_day_start=07:30`。
2. 同接口返回 `input=106490.53`、`output=1323.07`、`scrap=105145.3`、`yield_rate=1.24`，说明运行时投料/废料/成品率仍有异常值，需要隔离。
3. 同接口返回 `mes_sync_status.adapter=sqlserver`，`status=fresh`，说明外部 MES 直连同步已在运行。
4. `/api/v1/energy/summary?business_date=2026-06-11` 返回 6 条能耗记录，前三条都有电/气，但 `output_weight=0`，`energy_per_ton=null`。
5. `/api/v1/factory-command/destinations?business_date=2026-06-11` 返回 `tons=330735.5`、`coil_count=1373`，单位必须复核。
6. `/api/v1/mes/supplement-readiness?limit=100` 返回 `machine_match_rate=0.8333`，`generic_terminal_count=64`，`unmatched_count=6`，未匹配集中在 `精整新19辊（WAN）`。

## 5. 本轮发现的问题

### 阻塞

1. 实时页短等待时会出现“全是 0 但仍加载中”的状态，用户容易把“还没加载完”当成“真实为 0”。
2. 能源中心有能耗但产量分母为 0，页面把“单吨峰值”显示成 0，容易让人误以为吨耗真的为 0。
3. 合同页履约率 100% 与延期 269 项并存，业务解释不成立，不能作为经营决策依据。
4. 库存去向 `tons=330735.5` 数值过大，单位如果错会严重误导。

### 高风险

1. MES 机台匹配率 83.33%，还不能直接支撑“按 MES 自动归机列”。
2. 实时页使用 SSE，自动化测试如果等待 `networkidle` 会误判超时。
3. 今日页和生产页依赖快照接口，接口慢或切页时请求被取消，会留下“同步中/暂无可信数据”状态。
4. 填报明细页同时展示人工明细和 MES 对照异常，如果继续扩展，容易变成“什么都塞进去”的页面。

### 体验问题

1. `0`、`—`、`暂无可信数据`、`同步中`、`待同步` 的含义还不统一。
2. 导航名称已收敛，但隐藏页面很多，用户不知道哪些是正式页面。
3. 车间看板默认进入铸锭分厂，管理员视角下可能误以为只看到了一个车间。
4. 实时大屏已经有科技感，但信息优先级仍偏“数据多”，还不够“先处理什么”。
5. 考勤页明确是预留，却还在主导航中，会分散用户注意力。

### 可合并或隐藏

| 页面 | 建议 | 原因 |
| --- | --- | --- |
| `/manage/attendance` | 从核心导航移到系统预留区 | 当前等待钉钉接入，非日常生产核心 |
| `/manage/inventory` | 并入库存去向或卷级线索页 | 当前为空壳，独立价值弱 |
| `/manage/contracts` | 暂不放核心导航，先修公式 | 指标互相冲突 |
| `/manage/reports` | 并入昨日报表历史归档 | 与今日/日报重复 |
| `/manage/factory/destinations` | 并入实时大屏或卷级线索页 | 有价值，但缺主导航和单位口径 |

## 6. 推荐前端调整顺序

### 第一批：状态语言

先统一 5 种状态：

1. 真实为 0。
2. 数据未同步。
3. 数据加载中。
4. 数据异常被隔离。
5. 当前账号无权限。

验收：同一个状态在实时页、日报页、能源页、车间看板显示同一种文案。

### 第二批：页面收敛

保留核心入口：

1. 实时调度墙。
2. 昨日报表。
3. 生产分析。
4. 各车间看板。
5. 填报明细。
6. 能源中心。
7. 异常处理。
8. 系统设置。
9. 账号权限。
10. 主数据与规则。

隐藏或合并：

1. 考勤预留。
2. 库存出入中心。
3. 合同与订单中心。
4. 报表中心。

### 第三批：新增卷级线索页

新增页面不应该叫“填报明细”，建议叫“卷级线索”。

它只解决一件事：搜随行卡/批号，看这卷料从 MES 到填报到异常的完整链路。

核心模块：

1. 卷基本信息：随行卡、批号、客户、合金、规格。
2. 当前工艺：车间、工序、设备名、是否匹配机列。
3. 流转时间线：上道工序、本工序、下道工序。
4. MES 主账：MES 重量、MES 设备、MES 操作员、MES 时间。
5. 人工补录：主操补了什么、什么时候补、谁补。
6. 异常：未匹配机列、缺下机重量、重量不一致。

### 第四批：实时生产流转大屏

实时大屏应该从“展示很多数据”变成“指挥现场动作”：

1. 顶部只放 6 个主指标：MES 包装产量、内勤入库填报、过站下机、总能耗、缺报、异常。
2. 中间放车间/机列流转矩阵。
3. 右侧放优先处理队列。
4. 底部放系统状态：MES 同步、实时连接、能耗链路、AI 只读。
5. 数字跳动只用于真实新值，不用于未知值。

## 7. 三视角评审

### CEO 视角

评分：9.7/10。

判断：方向是对的。最重要的是让老板每天一眼知道“产量、能耗、异常、缺报、MES 是否可信”。合同页和库存页现在不适合作为核心决策入口，因为指标还不可信。

### 工程视角

评分：9.6/10。

判断：当前前端已经有统一 API 模块和 Stitch 风格底座，但仍要补字段契约测试、状态语言测试、SSE 页面加载测试。实时页自动化测试不能用 `networkidle`。

### 设计视角

评分：9.6/10。

判断：主视觉已经比较统一，但用户最缺的是“这是什么状态、我现在该做什么”。下一轮前端重构应优先做状态语言和优先处理队列，而不是继续加装饰效果。

## 8. 结论

下一阶段可以继续推进，但顺序必须是：

1. 先修状态语言和字段契约。
2. 再确认合同、库存、考勤是否合并或隐藏。
3. 再新增卷级线索页。
4. 最后重构实时生产流转大屏。

不要先做大规模视觉重构。否则页面会更漂亮，但用户还是不知道哪些数字可信。
