# 鑫泰铝业 数据中枢：页面与接口覆盖矩阵

日期：2026-06-11

状态：只读审计版，供后续删减、合并、重构、测试使用。

## 1. 这份清单解决什么问题

系统现在不是“没有页面”，而是“页面、旧入口、隐藏详情页、接口太多”。如果直接删页面或接口，很容易误删仍在业务里用的东西；如果完全不整理，用户又会觉得后台复杂、慢、乱。

这份矩阵先做三件事：

1. 分清哪些页面是核心业务入口。
2. 分清哪些页面是详情页、隐藏页、旧入口或暂未接入页。
3. 分清每个页面依赖哪些接口，方便后续写自动测试。

## 2. 审计证据来源

- 前端路由：`frontend/src/router/index.js`。
- 管理端导航：`frontend/src/config/manage-navigation.js`。
- 管理端页面：`frontend/src/views/**`。
- 前端 API 调用：`frontend/src/api/**`、页面内 `api.get/post/patch/delete`。
- 后端路由：`backend/app/routers/**`。
- 浏览器只读抽查：线上 `https://xtmijd.com` 管理端 23 个页面。

## 4. 页面分类规则

| 分类 | 含义 | 处理原则 |
| --- | --- | --- |
| 核心页 | 用户每天会看、会决策、会填报的页面 | 必须保留，必须有自动测试 |
| 管理页 | 配置账号、规则、主数据的页面 | 保留，但要限制权限和删除风险 |
| 详情页 | 从列表点进去看的页面 | 可以无导航，但必须有来源入口 |
| 隐藏页 | 有路由但不在主导航 | 必须说明为什么隐藏 |
| 已停用入口 | 旧上传、旧模板、旧导入等 | 保留重定向或灰度删除 |
| 可合并页 | 页面存在但业务价值弱或重复 | 先隐藏，再观察，再删除 |

## 10. CEO 视角判断

最重要的不是“把所有页面都留下”，而是让管理者每天只看三类东西：

1. 今天/昨日到底生产了多少。
2. 哪些卷、机列、车间需要处理。
3. 哪些数据不可信，为什么不可信。

所以 CEO 视角建议：

- 保留并打磨：实时调度墙、昨日报表、生产分析、车间看板、填报明细、能源、异常、账号、规则、设置。
- 合并或隐藏：报表中心、库存出入、考勤预留、合同中心、治理中心。
- 新增核心：卷级线索页、终端绑定页。

评分：9.7/10。

扣分原因：真实机台二维码和车间主任账号还未完整复测。

## 11. 工程视角判断

当前最大工程风险是接口面太宽、页面状态太散。一个字段可能同时影响实时大屏、日报、填报明细和车间看板。

工程建议：

- 给 `realtime`、`mes`、`factory_command`、`energy` 四类接口先写契约测试。
- 把直接 `api.get/post` 的页面逐步收敛到 `frontend/src/api/**`。
- 建页面冒烟清单：核心页每日测，详情页按入口测，旧入口只测跳转。
- 删除页面前先查路由、导航、API、按钮入口、二维码入口、历史外链。

评分：9.6/10。

扣分原因：还没有落地自动化覆盖矩阵脚本，只是人工审计文档。

## 12. 设计视角判断

用户不怕页面少，怕页面多但每个都不知道有什么用。

设计建议：

- 左侧导航继续保持少而清楚，不要把所有隐藏页塞进去。
- 空页面必须写清楚是“暂无业务数据”“暂未接入”“没有权限”还是“接口失败”。
- 详情页不要独立漂着，必须从列表或异常卡片进入。
- 卷级线索页要成为“查一卷料”的主入口，不要混在填报明细里。
- 实时大屏要像生产指挥墙，不是普通报表页放大版。

评分：9.6/10。

扣分原因：仍缺每个页面的空状态、异常状态、加载状态截图级验收。

## 13. 下一步建议

第一批落地任务不要大改 UI，先做 5 个“小而硬”的动作：

1. 给 `/manage/live`、`/manage/today`、`/manage/energy`、`/manage/fill-details` 建字段断言测试。
2. 给 `/entry`、`/entry/fill`、`/entry/coil` 用真实二维码或机台账号做浏览器回归。
3. 给合同页和库存页做“是否应保留/合并”的业务确认。
4. 给 `/shift/detail/:id` 查 404 噪声来源。
5. 建终端绑定页计划，把 `PC/WAN/一体机` 映射到机列和工艺。
