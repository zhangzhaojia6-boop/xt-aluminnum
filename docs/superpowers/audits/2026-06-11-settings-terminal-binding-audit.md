# 设置、主数据、MES 终端绑定审计

日期：2026-06-11

范围：只读检查 `/manage/admin/settings`、`/manage/alias`、`/manage/admin/users`、`/manage/master`，以及后端主数据、别名映射、MES 机列匹配服务。

## 1. 结论

当前系统已经有主数据、别名映射、用户管理、机列二维码和 MES 补录就绪检查，但还没有真正可落地的“MES 终端绑定规则”。

最关键的问题是：MES 设备名为 `PC`、`电脑`、`一体机` 时，后端会直接把它们判定为通用终端，并跳过设备别名匹配。因此，仅靠现有“别名映射”页面无法解决 PC 对应机列的问题。

需要新增专门的“MES 终端绑定”能力，绑定维度至少包括：

1. 终端名。
2. MES 车间。
3. MES 工艺。
4. 目标机列。
5. 生效时间。
6. 匹配原因。
7. 启用状态。

## 4. 代码证据

### 通用终端会跳过别名匹配

文件：`backend/app/services/mes_machine_match_service.py`

当前规则：

1. `GENERIC_MES_DEVICE_NAMES = {'PC', '电脑', '一体机'}`。
2. `resolve_mes_machine_binding()` 开头先判断是否通用终端。
3. 如果是通用终端，直接返回 `source='generic_mes_terminal'`。
4. 这一步发生在别名匹配之前。

这意味着：即使在别名映射里新增 `PC -> 某机列`，当前代码也不会使用这个别名。

### 当前别名表字段太简单

文件：`backend/app/models/master.py`

`master_code_aliases` 只有：

| 字段 | 作用 |
| --- | --- |
| entity_type | 实体类型 |
| canonical_code | 标准编码 |
| alias_code | 别名编码 |
| alias_name | 别名名称 |
| source_type | 来源 |
| is_active | 是否启用 |

它缺少：

1. MES 车间。
2. MES 工艺。
3. 终端名。
4. 目标机列 ID。
5. 生效时间。
6. 失效时间。
7. 置信度。
8. 匹配原因。
9. 审核人。

结论：别名映射适合“名称标准化”，不适合“PC 终端绑定机列”。

### MES 就绪只看摘要，不给操作入口

文件：`frontend/src/views/manage/admin/SystemSettingsPage.vue`

设置页读取 `fetchMesSupplementReadiness({ limit: 100 })`，只展示：

1. 机台匹配率。
2. 下机重量覆盖率。
3. 冷轧道次覆盖率。
4. 09:30窗口数量。

它没有展示：

1. 通用终端数量。
2. 未匹配设备清单。
3. 待绑定建议。
4. 一键进入绑定页面。

## 5. 根因

### 根因 1：PC 是终端名，不是机列名

MES 记录里的 `PC` 不能说明是哪台机。它可能只代表某台一体机或电脑终端。

如果直接把 `PC` 绑定到某台机，会出现两个风险：

1. 同名 PC 在不同车间串线。
2. 电脑换位置后，历史数据被错误归属。

### 根因 2：现有别名映射不能表达上下文

机列绑定不是简单的“别名 A 等于标准编码 B”。

它需要上下文：

1. 哪个车间。
2. 哪道工艺。
3. 哪个时间段。
4. 这台终端是否跨线使用。

### 根因 3：就绪状态过于乐观

当前 `generic_terminal_count=64` 不拉低 `machine_match_rate`，所以页面显示“可试跑”。

这对“补录可用”是合理的，因为 PC 不阻断人工补录；但对“自动归属机列”是不够的，因为 PC 仍然不知道具体机列。

## 6. 建议方案

### 第一阶段：只读展示待绑定终端

先不让用户改数据，只新增只读视图。

新增页面或设置页模块：

| 模块 | 内容 |
| --- | --- |
| 通用终端 | PC、电脑、一体机数量 |
| 未匹配设备 | WAN、未知设备等清单 |
| 最近记录 | 卷号、车间、工艺、重量、时间 |
| 建议动作 | 绑定终端 / 忽略 / 保持待归属 |

验收：

1. 设置页能看到 64 条通用终端。
2. 设置页能看到 6 条未匹配 `精整新19辊（WAN）`。
3. 不修改任何生产数据。

### 第二阶段：新增终端绑定表

建议新增表：`mes_terminal_machine_bindings`。

建议字段：

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| terminal_name | PC/WAN/一体机名 |
| mes_workshop_name | MES 车间 |
| mes_process_name | MES 工艺 |
| equipment_id | 数据中枢机列 |
| confidence | high/medium/low |
| reason | 绑定原因 |
| effective_from | 生效时间 |
| effective_to | 失效时间 |
| is_active | 是否启用 |
| created_by | 创建人 |
| updated_by | 更新人 |

验收：

1. 同一个 `PC` 可以在不同 MES 车间绑定不同机列。
2. 同一个 `PC` 可以按工艺区分。
3. 停用绑定不影响历史记录。
4. 所有绑定可审计。

### 第三阶段：匹配算法接入终端绑定

新的匹配顺序建议：

1. 明确设备名匹配。
2. 设备别名匹配。
3. `terminal_name + mes_workshop_name + mes_process_name` 终端绑定匹配。
4. 工艺推断匹配。
5. 仍无法匹配则进入待归属。

注意：不要把 `PC` 从通用终端名单里简单删掉。应该让它先走“上下文绑定”，没有绑定时仍作为通用终端或待归属。

### 第四阶段：绑定结果进入卷级线索和实时大屏

绑定完成后：

1. 卷级线索页显示这卷为什么归到这台机。
2. 实时大屏机列矩阵可按绑定后的机列显示。
3. 填报端可用 MES 数据辅助带出，但字段仍可编辑。

## 7. CEO 视角

评分：9.7/10。

判断：终端绑定是把 MES 真值变成可用管理数据的关键。如果不解决，实时大屏会看起来漂亮，但机列级数据不可信。

扣分点：还需要现场确认每个 PC 是否固定对应一台机，还是会随人员/工序变化。

## 8. 工程视角

评分：9.8/10。

判断：不能复用简单别名表硬做 PC 绑定，必须新增结构化表和审计链路。先只读展示，再允许绑定，是低风险路径。

扣分点：需要补数据库迁移、契约测试、回放测试、权限测试。

## 9. 设计视角

评分：9.6/10。

判断：设置页现在只显示百分比，不告诉用户下一步怎么处理。应改成“待处理清单 + 建议绑定 + 风险说明”，让小白也知道哪里没对齐。

扣分点：页面不要堆字段，要用“待处理终端、未匹配设备、已绑定规则”三栏组织。

## 10. 下一步门禁

进入实现前必须先补测试：

1. `PC` 有上下文绑定时能匹配到机列。
2. `PC` 没有上下文绑定时不能乱归属。
3. 同名 `PC` 在不同车间不会串线。
4. `精整新19辊（WAN）` 未绑定时进入未匹配清单。
5. 绑定规则停用后不再生效。
6. 设置页能显示通用终端和未匹配设备，而不是只显示百分比。
