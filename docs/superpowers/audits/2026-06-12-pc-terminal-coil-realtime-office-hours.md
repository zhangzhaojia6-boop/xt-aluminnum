# 鑫泰铝业 数据中枢：PC 终端、卷级线索、物联网能耗与实时大屏 Office Hours

日期：2026-06-12

状态：只读规划备忘，不修改代码，不修改生产数据。

## 1. 现场真实痛点

现场现在最卡的不是“有没有数据”，而是“数据能不能自动归到正确机列”。包装工序里很多外部生产系统记录的设备名是 `PC`，这通常代表一体机或电脑终端，不代表真实机列。如果系统直接把 `PC` 当机列，会把卷、产量、废料、能耗归错地方。

对用户来说，最理想的体验是：

1. 一体机录入后，数据中枢自动知道这卷料属于哪个车间、哪台机、哪个工艺。
2. 手机填报只补外部系统没有的字段，不再重复填随行卡、合金、规格、重量。
3. 调度页像生产现场大屏一样实时跳动，能看到卷在工序间流转。
4. 能耗从物联网库读取，人工填报只做对照和兜底。

## 3. 核心决策

### 3.1 PC 不是机列，PC 是终端

`PC` 只能说明“这条记录来自某台电脑/一体机”。系统必须通过绑定表判断：

```text
PC/终端编码 + MES 车间 + MES 工艺 + 生效时间 -> 数据中枢真实机列
```

不要让算法无证据猜机列。猜错一次，后面产量、废料、能耗、异常都会错。

### 3.2 已有 `mes_terminal_bindings`，不要新增重复表

旧计划里曾写过新增 `mes_terminal_machine_bindings`。结合当前代码，应该取消这个方向，统一使用现有 `mes_terminal_bindings`，只补齐它的使用链路和审核页面。

这样做的好处是：

1. 少一套表，少一套接口。
2. 管理端只维护一个入口。
3. 历史绑定、测试、页面都能继续复用。

### 3.3 MES 做卷级主事实，填报做补录和异常审核

外部生产系统已有的内容，例如随行卡、批号、客户、合金、规格、工艺路线、当前工艺、上机量、下机量，应作为前端主要展示来源。

手机填报只处理两类内容：

1. 外部生产系统没有设计的字段。
2. 外部生产系统与现场不一致时的异常说明和审核。

### 3.4 废料自动计算，不让现场重复填

推荐主公式：

```text
自动废料 = MES 上机量 - MES 下机量
```

保护规则：

1. 上机量或下机量缺失，不计算。
2. 下机量大于上机量，不显示负废料，进入异常。
3. 废料率超过阈值，不进主汇总，先待审核。
4. 人工废料只做对照，不覆盖 MES 原始值。

### 3.5 能耗接物联网独立库，但必须后端只读同步

不要让前端直接连物联网数据库。正确链路是：

```text
物联网独立数据库 -> 后端只读同步 -> 本地能耗影子表 -> 能耗接口 -> 管理端和大屏
```

这样外部库断开时，数据中枢不会崩；前端也不会暴露数据库账号密码。

## 4. 最窄可落地版本

第一版不要追求“全部自动化”，先做最稳的一刀：

1. 管理端列出所有 `device_name=PC/电脑/一体机` 的待绑定记录。
2. 管理员把 `PC + 车间 + 工艺` 绑定到真实机列。
3. 卷级线索页显示每卷的机列归属来源：直接匹配、别名、终端绑定、待归属。
4. 废料按 MES 上机/下机自动算。
5. 实时大屏只展示可信归属；不可信的单独显示“待绑定”，不混入机列产量。

## 5. 不建议做的事

1. 不建议再建一张新的终端绑定表。
2. 不建议把 `PC` 直接当机列。
3. 不建议让前端直连物联网库。
4. 不建议让手机端继续重复录入 MES 已有字段。
5. 不建议把异常废料直接算进全厂主指标。

进入工程计划时，优先做“待绑定 PC 清单 + 匹配链路测试”，再做前端卷级线索和实时大屏视觉强化。只要 PC 归属没稳，大屏做得再漂亮也会显示错数字。
