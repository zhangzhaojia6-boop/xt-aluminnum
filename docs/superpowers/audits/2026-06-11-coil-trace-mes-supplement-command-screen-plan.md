# 卷级线索、MES 辅助补录与实时生产流转大屏专项方案

日期：2026-06-11

范围：机列匹配、MES PC 终端绑定、废料自动计算、物联网能耗独立库、卷级线索页面、实时生产流转大屏。

## 1. 结论

当前系统已经有 MES 卷数据、MES 工序数据、按卷补录、扫码兜底、实时调度墙和 SSE 实时流，但还没有把这些能力合成一个稳定闭环。

最关键的问题是：MES 里很多包装或工序记录的设备名是 `PC`、`电脑`、`一体机`、`WAN` 这类终端名，不是具体机列名。现有代码会把 `PC` 直接判定成“通用终端”，不会继续走设备别名或机列推断。因此，现在不能完全靠 MES 自动知道是哪台机。

正确方案不是让系统硬猜，而是新增一层“终端绑定规则”：同一个 `PC` 必须结合 MES 车间、MES 工艺、生效时间，绑定到数据中枢里的真实机列。

## 2. 现有链路

### 2.1 MES 主数据

已有模型：

| 表 | 作用 |
| --- | --- |
| `mes_coil_snapshots` | 卷级快照，含随行卡、批号、客户、合金、规格、当前/下道工序 |
| `mes_workshop_process_records` | 工序过站记录，含车间、工艺、设备名、上机量、下机量、时间 |
| `mes_stock_records` | 包装入库/库存记录 |
| `coil_flow_events` | 卷流转事件 |

说明：这些表可以支撑“卷级线索页”和“生产流转大屏”，但还需要补机列绑定和状态解释。

### 2.2 手机补录端

已有页面：`frontend/src/views/mobile/CoilEntryWorkbench.vue`。

已有能力：

1. 显示 `MES 待补录`。
2. 点击 MES 卡片可带出随行卡、合金、规格、上机量、下机量、下机时间。
3. 字段可人工修改，不锁死。
4. 找不到卷时可扫码随行卡兜底。
5. 提交时自动计算废料：`scrap_weight = input_weight - output_weight`。

短板：

1. 待补录列表只显示已能匹配到当前机台的 MES 记录。
2. `PC` 终端记录因为匹配不到机列，可能不会出现在对应机台用户面前。
3. 废料自动计算缺少异常阈值保护，不能把负数、极大值直接当真实废料。

### 2.3 管理端卷级能力

已有接口：

1. `GET /api/v1/factory-command/coils`
2. `GET /api/v1/factory-command/coils/{coil_key}/flow`

已有字段：

1. 随行卡。
2. 批号。
3. 物料编码。
4. 当前车间/工艺。
5. 下道车间/工艺。
6. 目的地。

短板：

1. 管理端没有独立 `/manage/coils` 卷级线索页面。
2. 现有卷列表字段偏薄，缺少客户、合金、规格、重量、废料、能耗、补录状态、异常状态。
3. 卷流向接口有时间线雏形，但还没把 MES 过站、人工补录、异常审核合到一个用户能看懂的视图。

### 2.4 实时调度墙

已有页面：`frontend/src/views/manage/live/LiveDashboardPage.vue`。

已有能力：

1. 读取实时聚合接口。
2. 读取填报明细。
3. SSE 实时事件流。
4. 30 秒快照兜底。
5. 机列矩阵。
6. 事件栏。

短板：

1. 缺少卷级实时事件，比如“某卷下机、某卷待补录、某卷机列待归属”。
2. 数字动画应只用于真实新值，不能把缺失值动画成 0。
3. 需要从“数据墙”升级成“生产流转墙”，展示卷在工艺路线上的移动。

## 3. 关键根因

### 根因 1：PC 是终端，不是机列

代码里 `resolve_mes_machine_binding()` 遇到 `PC` 会直接返回 `generic_mes_terminal`。这代表系统主动承认：`PC` 本身不能说明是哪台机。

这一步发生在别名匹配之前，所以只配普通设备别名无法解决问题。

### 根因 2：机列绑定需要上下文

同名 `PC` 可能出现在不同车间。真正能判断机列的是上下文：

1. MES 车间。
2. MES 工艺。
3. 终端名。
4. 现场机列。
5. 生效时间。

所以需要新表，不应复用普通别名表。

### 根因 3：MES 可以做主事实，但填报仍要保留补录和审核

MES 可以作为产量、卷流转、包装入库的主事实来源；手机填报应逐步变成：

1. MES 没有的字段补录。
2. MES 异常时确认。
3. 现场质量/异常说明。
4. 人工纠偏记录。

不能马上把后工序填报端完全删掉，因为 PC 机列归属、物联网能耗、异常审核还未完全闭环。

## 4. 推荐方案

### 阶段 1：PC/终端绑定只读审计

目标：先让管理员看到哪些 MES 记录无法归属机列。

新增或增强设置页模块：

| 区域 | 内容 |
| --- | --- |
| 通用终端 | PC、电脑、一体机、WAN 的数量 |
| 待绑定记录 | 车间、工艺、终端名、卷号、时间、重量 |
| 建议机列 | 如果同车间同工艺只有一台候选机列，显示候选但不自动采用 |
| 风险提示 | 跨机列、跨车间、同名终端时标记高风险 |

验收：

1. 能看到每个 `PC/WAN` 终端对应的 MES 车间和工艺。
2. 不修改任何历史数据。
3. 不自动把 PC 归到某台机。

### 阶段 2：新增 MES 终端绑定表

建议表名：`mes_terminal_machine_bindings`。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `terminal_name` | PC、电脑、一体机、WAN 等终端名 |
| `mes_workshop_name` | MES 原始车间 |
| `mes_process_name` | MES 原始工艺 |
| `equipment_id` | 数据中枢机列 |
| `process_code` | 本系统工艺码，可空 |
| `confidence` | high / medium / low |
| `reason` | 绑定原因 |
| `effective_from` | 生效时间 |
| `effective_to` | 失效时间 |
| `is_active` | 是否启用 |
| `created_by` | 创建人 |

匹配顺序：

1. MES 设备名直接等于机列编码或名称。
2. 设备别名匹配。
3. 终端绑定规则匹配。
4. 同车间同工艺唯一机列推断。
5. 待归属。

验收：

1. `PC + 车间 + 工艺` 可以稳定归到机列。
2. 没有绑定规则时不误归属。
3. 每条匹配结果都返回匹配来源和置信度。

### 阶段 3：卷级线索页

新增页面：`/manage/coils`。

页面目标：让管理者输入随行卡或批号，就能知道这卷料在哪里、走过哪些工序、是否缺补录、是否异常。

核心模块：

| 模块 | 内容 |
| --- | --- |
| 搜索区 | 随行卡、批号、客户、合金、规格、车间、工艺 |
| 卷级列表 | 当前车间、当前工艺、机列、重量、状态、更新时间 |
| 卷详情抽屉 | MES 过站、人工补录、异常审核、能耗参考 |
| 时间线 | 上工序、当前工序、下工序、包装入库 |
| 差异卡 | MES 值、人工填报值、自动计算值 |

字段建议：

1. MES 上机量。
2. MES 下机量。
3. 自动废料。
4. 人工废料。
5. 废料差异。
6. MES 当前工艺。
7. 当前机列。
8. 补录状态。
9. 异常状态。
10. 数据来源。

验收：

1. 能按随行卡查到卷。
2. 能看到 MES 数据和人工补录数据的差异。
3. 能看出机列是直接匹配、终端绑定、工艺推断还是待归属。

### 阶段 4：废料自动计算安全化

原则：废料可自动算，但不能无脑算。

计算：

```text
自动废料 = MES 上机量 - MES 下机量
```

保护规则：

1. 上机量或下机量缺失时，不计算。
2. 下机量大于上机量时，标记异常，不显示负废料为真实值。
3. 废料率超过工艺阈值时，进入异常审核。
4. 单位必须统一为 kg 或吨，前端显示时再格式化。
5. 人工填报废料保留为对照，不覆盖 MES 自动值。

验收：

1. 正常值显示自动废料。
2. 异常值显示“待核”，不污染总废料。
3. 原始 MES 值仍可追溯。

### 阶段 5：物联网能耗独立库接入

原则：前端不直连物联网库，业务库不直接写外部库。

推荐链路：

```text
物联网数据库（只读） -> 后端同步任务 -> 本地能耗影子表 -> energy_service -> 管理端/日报/大屏
```

建议新增：

1. `iot_energy_adapter`：只读连接物联网库。
2. `iot_energy_snapshots`：本地影子表。
3. `iot_energy_sync_runs`：同步日志。
4. `energy_service` 增加来源优先级：物联网系统值、车间电工填报值、全厂总电工填报值、历史导入值。
5. 页面同时显示“系统采集”和“人工填报”。

验收：

1. 物联网库不可用时，页面不报错，显示采集延迟。
2. 人工填报仍保留。
3. 吨耗分母缺失时不显示 0。

### 阶段 6：实时动态生产流转大屏

目标：从“看数字”升级成“看生产流转”。

页面结构：

| 区域 | 内容 |
| --- | --- |
| 顶部跑马指标 | 全厂包装入库、过站下机、在制卷、吨电耗、异常、待补录 |
| 中部流转图 | 铸轧/热轧/冷轧/退火/精整/包装入库 |
| 机列矩阵 | 每台机当前状态、今日卷数、吨数、待补录、异常 |
| 卷级事件流 | 新卷下机、补录完成、终端待绑定、能耗更新 |
| 底部系统状态 | MES、物联网、填报、日报、AI |

动画规则：

1. 真实数字变化时 1 秒滚动。
2. 缺失值不滚动成 0。
3. 不做重型光效。
4. SSE 正常时只更新变化卡片。
5. SSE 断开时 30 秒快照兜底。

验收：

1. 有数据时实时跳动。
2. 没数据时显示 `待同步`、`无分母`、`待绑定`，不显示假 0。
3. 页面在普通办公电脑上不卡顿。

## 6. 测试计划

### 单元测试

1. `PC + 车间 + 工艺` 命中终端绑定。
2. 同名 PC 在不同车间不会串线。
3. 没有绑定时保持待归属。
4. 废料正常计算。
5. 负废料和异常废料进入异常审核。

### 接口测试

1. `/api/v1/mes/supplement-readiness` 返回通用终端和未匹配设备清单。
2. `/api/v1/factory-command/coils` 返回卷级扩展字段。
3. `/api/v1/factory-command/coils/{coil_key}/flow` 返回时间线。
4. `/api/v1/energy/summary` 返回物联网值和人工值对照。
5. `/api/v1/realtime/events/stream` 能推送卷级和能耗事件。

### 浏览器测试

1. `/manage/admin/settings` 能看到待绑定终端。
2. `/manage/coils` 能搜索随行卡。
3. `/entry/coil/...` 能看到 MES 待补录和可编辑字段。
4. `/manage/live` 数字变化时轻量动画，不假 0。
5. `/manage/energy` 能区分系统采集和人工填报。

## 7. 风险与回滚

| 风险 | 影响 | 回滚 |
| --- | --- | --- |
| PC 绑定错机列 | 产量归属错误 | 停用绑定规则，回到待归属 |
| 物联网库连接慢 | 页面变慢 | 同步任务降频，页面只读本地影子表 |
| 废料阈值太严 | 异常过多 | 调整阈值配置，不改原始数据 |
| 实时事件过多 | 页面卡顿 | 限流，只推摘要事件 |
| 卷级页面过复杂 | 用户看不懂 | 先只做搜索、列表、详情三块 |

## 9. 推荐执行顺序

1. 先做终端绑定只读审计，不改归属。
2. 再做终端绑定表和匹配测试。
3. 再增强手机 MES 待补录，让 PC 记录能进入“待确认”而不是消失。
4. 再新增卷级线索页。
5. 再接物联网能耗影子表。
6. 最后重构实时生产流转大屏。

这条顺序最稳，因为它先解决数据可信度，再优化用户体验，最后做视觉和实时动效。
