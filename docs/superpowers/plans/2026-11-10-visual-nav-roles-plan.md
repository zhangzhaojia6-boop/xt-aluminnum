在不拖慢系统的前提下，让管理端更丰富（图片、动画、3D），把右上角藏着的功能放进左侧主导航，把用户和角色放到一个页面统一管理，并让张兆嘉能在异常页写当日异常说明，Hermes 和日报都读得到。

## 工作流

### W1 异常说明（张兆嘉写）

**评审后改过：不新建表。** `anomaly_explanation_daily` 的合同（`metric_contracts.py:417`）只认钉钉、`root_owner_correction`、`verified_owner_daily` 三类来源；原计划的「数据中枢投影」不在其中，写了也只会是候选。系统已有「负责人确认补录」表 `DailyFactCorrection`（`models/reports.py:82`），日报事实生成时由 `_apply_root_owner_corrections`（`daily_fact_bundle.py:761`）读入，来源就是 `root_owner_correction`，正好被这个字段认可。

- 存储：每次保存写一行 `DailyFactCorrection`：`field_name=anomaly_explanation_daily`、`value_payload={"value": 正文}`、`actor_user_id`、`reason="异常说明"`、`trace_id`；同一天旧的那行改为 `superseded`。正文 1 到 2000 字。每次保存另写 `record_audit`。
- 谁能写：后端配置 `ANOMALY_NOTE_AUTHOR_USER_IDS`，默认只有 983（张兆嘉）；配置支持多人，以后加代写人只改配置。不按角色放开。
- 接口：`GET /api/v1/daily-anomaly-notes/{date}`（review 权限可读）、`PUT` 同路径（只有指定作者，其他人 403）。
- 生效：保存后对当天日报事实做一次刷新，让 Hermes 不用等到第二天 08:05。
- 页面：异常页顶部「当日异常说明」。作者看到编辑框和保存，其他人看到正文、修改人和时间；当天没写时，其他人看到「今天还没有异常说明」。
- Hermes：#150 的固定回答改为只在当天确实没写时说「张兆嘉今天还没有写异常说明」。
- 文档：`docs/hermes/fact-source-map.md:22` 把这个字段标为「已证实」，但当时没有任何写入代码。这次一并改成真实来源。
- 测试：用真实合同校验函数跑一遍，确认写入后这个字段是「已确认」，不是候选。

### W2 主导航整合

- 左栏分组：主线（总览、实时、生产、卷材、异常、3D 工厂）、业务（车间看板、填报明细、能耗、考勤、物资采购）、配置（主数据、别名映射、系统设置、规则）、权限（用户与角色、治理、通讯治理、通讯通道）、工具（归档报表、知识库资料、输出 skill 对齐、QR 打印）。
- 除「主线」外的分组默认折叠，展开状态记在本地。按现有 `canAccess` 过滤，空分组不显示。
- 去掉齿轮按钮和 `SettingsDrawer`；搜索仍能搜到全部入口。AI 助手和操作员端留在顶栏。
- 窄屏沿用现有 `COMPACT` 规则，不把配置类塞进手机导航。

### W3 用户与角色统一页

- `/manage/admin/users` 改名「用户与角色」，两个标签：账号（现有表格）、角色。
- **评审后改过：不新增第三套角色定义。** 「能进的页面」由前端从真实路由的 `meta.access` 加上 `auth.js` 的判断规则推算，和用户实际能进的页面同源；另加测试，任何角色的推算结果和真实路由守卫不一致就失败，防止这一列说假话。
- 后端只读接口 `GET /api/v1/roles` 只返回角色代码和账号数。角色中文名合并成一份（现在 `UserManagement.vue:229` 和 `utils/display.js` 各有一份），前端统一引用。
- 角色标签页：每个角色一行，账号数、可进页面、数据范围（全厂 / 本车间 / 本班组）。点账号数跳到账号标签并按角色筛选。
- 账号标签增加「长期未登录」筛选（`last_login` 超过 30 天或为空），方便清理。

### W4 视觉：图片、动画、3D

**性能预算（硬性）**

| 项目 | 上限 |
|---|---|
| 非 3D 页面首屏 JS 增量 | 0（3D 代码只在 3D 页按需加载） |
| 3D 代码分块 | gzip 后 ≤ 180KB，单独 chunk，不进 PWA 预缓存 |
| 单张图片 | WebP，≤ 150KB；全部图片合计 ≤ 1.5MB |
| 3D 页帧率 | 普通办公电脑 ≥ 50fps；隐藏标签页时停止渲染 |
| 动画 | 只用 transform 和 opacity；`prefers-reduced-motion` 时关闭 |

**图片**

- 允许联网下载。来源限 Unsplash、Pexels 这类可商用免署名图库，或厂内自拍照片；每张记录来源链接和许可证到 `frontend/public/media/CREDITS.md`。
- 下载后转 WebP，放 `frontend/public/media/`，同源提供，不外链。
- 用途：登录页一张铝卷或轧机主图；空状态插图；车间识别小图（13 个车间，没有合适图片的用工序图标代替）。数字页不放装饰照片。
- PWA 运行时图片缓存加上限：最多 60 张、30 天。

**动画**

- 统一一套入场和数值滚动动效，复用现有 `AnimatedMetricValue`。
- 页面切换淡入，列表按批次错开出现，时长 ≤ 300ms。

**3D 产线（实时页）**

- 实时页「生产流转」旁加「2D / 3D」切换，默认 2D。
- 3D 用 three.js 画 6 个工序节点和连线，节点高度或亮度来自现有 `processFlowItems` 的真实吨数；没有数据的工序画成灰色并标「—」，不画 0。
- 渲染按需进行：数据变化或拖动视角时才重绘；标签页隐藏时停止。
- 检测不到 WebGL、`failIfMajorPerformanceCaveat` 失败、或开启减少动态效果时，切换按钮不显示，只用 2D。

**3D 工厂总览（新页 `/manage/factory-3d`）**

- 13 个车间按工序顺序排成示意布局（不是真实厂区位置），页面角落标明「示意布局」。
- 每个车间一个体块，颜色表示当天有无产出、高度表示当天吨数，点击进入该车间看板。
- 数据来自现有 `/dashboard/daily-production`（`workshop_output`），不新增接口。
- 以后如果提供厂区平面图，再换成真实位置。
