# 鑫泰铝业 数据中枢：前端颗粒度对齐 + MES 主数据映射最终可执行计划

日期：2026-06-12

状态：READY_FOR_IMPLEMENTATION

适用范围：管理端、调度大屏、车间主任看板、填报端、移动端历史页。

执行方式：TDD 分阶段实现，先测试，后最小实现，再浏览器验收，再五视角 review。

## 1. 最终目标

把 `鑫泰铝业 数据中枢` 的前端从“能看数据的后台”推进为“清晰、大气、全中文、可实时判断生产状态的工业数据中枢”。

本计划有四个硬目标：

1. 前端视觉颗粒度必须对齐 image2 和 Stitch 目标稿，不满足就重新 image2 + Stitch 出参考图和目标前端稿。
2. 前端各功能模块默认以 MES 数据库抓取后落到本系统的 MES 投影数据为主数据。
3. 人工填报数据保留为补录、对照、异常审核和 MES 缺失时兜底，不再和 MES 主数据混成一个口径。
4. 当前活跃车间只认十二个：铸锭、铸二、铸三、热轧、精整、拉矫、园区剪切、新厂在线、园区在线、冷轧1650、冷轧1850、冷轧2050。

## 2. 关键判断

### CEO 视角

管理层最需要的是一眼判断“全厂现在是否正常”。所以页面要围绕生产流转、产量、在制卷、能耗、异常、缺报、数据同步状态组织，而不是堆很多表。

目标评分：9.7 / 10。

### 工程师视角

前端不能直接连外部 MES 数据库。正确链路是后端只读抓取 MES SQL Server，落到本系统 `mes_*` 投影表，再由管理端接口提供给前端。这样页面快、权限可控、外部数据库异常时也不会直接拖垮前端。

目标评分：9.7 / 10。

### 设计师视角

视觉要工业蓝、深色仪表、强数字、细网格、低噪声动效。页面必须大气整洁，不能像普通后台模板，也不能像 AI 生成的炫光大屏。

目标评分：9.7 / 10。

### 安全审查视角

外部 MES 数据库账号、业务数据、用户权限不能暴露到前端。车间主任只看本车间，手机填报端不暴露管理端能力。

目标评分：9.7 / 10。

### 真实用户视角

现场人员要少点、少滚动、少输入；管理人员要一眼看懂哪里异常；车间主任要只看到自己车间的问题和缺报。

目标评分：9.7 / 10。

## 3. 数据主口径

本轮明确三类数据边界：

| 数据类型 | 主用途 | 前端展示规则 |
| --- | --- | --- |
| MES 数据库抓取数据 | 产量、包装、卷级线索、在制卷、工艺路线、当前工序、设备/PC 对应工艺 | 作为管理端主数据，显示为 `MES 数据库` |
| 人工填报数据 | 补录、异常说明、内勤补充字段、MES 没覆盖字段 | 显示为 `人工填报`，作为对照和兜底 |
| 系统算法数据 | 成品率、废料、吨耗、汇总指标、异常判断 | 显示为 `系统计算`，必须能追溯公式和来源 |

禁止事项：

1. 禁止把 MES、人工填报、系统计算混成一个无来源数字。
2. 禁止为了页面好看使用假数字。
3. 禁止前端直接访问外部 MES SQL Server。
4. 禁止在没有证据时把人工填报数值覆盖为 MES 主口径，或把 MES 主口径覆盖为人工数值。

## 4. 十二个活跃车间标准

活跃车间固定为：

```text
铸锭
铸二
铸三
热轧
精整
拉矫
园区剪切
新厂在线
园区在线
冷轧1650
冷轧1850
冷轧2050
```

执行规则：

1. 所有管理端页面、筛选项、车间矩阵、车间主任看板都必须使用这十二个标准名称。
2. 旧名称只允许作为别名归一化，例如 `2050冷轧车间` 归为 `冷轧2050`。
3. 已取消车间不得出现在产量概览、机列矩阵、缺报统计、看板筛选中。
4. 如果 MES 记录里只有 PC 或设备名，必须通过 PC/设备/工艺映射表归到十二车间之一。
5. 如果无法匹配车间，进入“未匹配线索”模块，不得硬塞到错误车间。

## 5. 生产生态流转设计

生产流转不死写成单一路线，而是优先使用 MES 工艺路线和当前工序生成。

默认兜底顺序：

```text
铸锭 -> 铸二 / 铸三 / 热轧 -> 冷轧1650 / 冷轧1850 / 冷轧2050 -> 新厂在线 / 园区在线 -> 拉矫 / 精整 / 园区剪切 -> 包装入库
```

页面表达：

1. `/manage/live` 用“实时流转墙”展示全厂生产生态。
2. `/manage/today` 用“昨日经营流转”展示业务日结果。
3. `/manage/production` 用“分析复盘流转”展示趋势、排行、来源对照。
4. `/manage/workshop-dashboard` 用“本车间局部流转”展示车间主任关注的信息。
5. `/manage/coils` 或卷级页面展示每卷的随行卡、客户、合金、规格、工艺路线、当前工序、当前车间、重量变化。

## 6. 视觉总原则

设计读取：

```text
这是一个工业生产数据中枢，不是营销页，也不是普通后台。
视觉应接近横屏工业指挥舱：深色工业蓝、数据栅格、强数字、清晰层级、轻量动效、全中文表达。
```

设计参数：

| 项目 | 标准 |
| --- | --- |
| 主色 | 工业蓝 |
| 背景 | 深色仪表底，弱纹理，低噪声 |
| 字体 | 中文清晰优先，数字可使用更强机械感字形 |
| 卡片 | 少阴影，多细线、栅格、分区 |
| 动效 | 只用于实时数字、状态变化、流转节点 |
| 语言 | 全中文，不出现无意义英文装饰 |
| 光效 | 禁止大面积重光效，避免拖慢页面 |
| 密度 | 管理端高密度但不拥挤，手机端低密度易操作 |

如果浏览器截图与 image2/Stitch 目标稿差距明显，不能只靠小修 CSS 凑合，必须回到 image2 + Stitch 重新出参考稿。

## 8. 分阶段执行计划

### Phase 0：保护现场

目标：保证已有改动不丢，后续每一步可回滚。

任务：

1. 查看当前分支、未提交文件、未跟踪文件。
2. 新建或确认独立功能分支。
3. 记录当前计划文件、当前前端改动范围、当前测试状态。
4. 不修改生产数据库，不在线上提交测试数据。

验收：

1. 有清楚的分支和改动清单。
2. 能说明哪些文件是本轮前端视觉相关改动。
3. 没有破坏已有业务代码。

### Phase 1：只读理解数据链路

目标：确认 MES 数据、人工填报、系统算法分别从哪里来。

任务：

1. 读取 SQL Server 只读适配器和 MES 同步服务。
2. 确认 MES 数据是否落入本地 `mes_*` 投影表。
3. 梳理 `/manage/live`、`/manage/today`、`/manage/production` 的真实接口来源。
4. 梳理人工填报表、能耗表、日报汇总表、异常表与前端页面的关系。
5. 梳理十二车间归一化和别名映射。

验收：

1. 每个核心页面能说明主数据来自 MES、人工填报还是算法。
2. 能确认前端不直接连外部 MES 数据库。
3. 能确认十二车间标准是否已被前端工具层覆盖。

### Phase 2：字段映射冻结

目标：先把数据口径锁住，再改视觉。

任务：

1. 建立页面字段映射表。
2. 建立接口字段映射表。
3. 建立十二车间字段归一化表。
4. 建立 MES 主数据与人工填报对照表。
5. 建立空值、未同步、未匹配、不适用的显示规则。

验收：

1. 每个核心数字都有来源标识。
2. 每个页面都能区分 `MES 数据库`、`人工填报`、`系统计算`。
3. 未匹配 PC、未匹配机列、未匹配车间不再静默进入错误模块。

### Phase 3：测试先行

目标：先让测试证明当前系统哪里不满足新要求。

任务：

1. 写十二车间标准测试。
2. 写 MES 主数据来源显示测试。
3. 写人工填报与 MES 对照测试。
4. 写全中文标签测试，禁止关键页面出现无意义英文装饰。
5. 写手机端长文本不溢出测试。
6. 写车间主任只能看本车间测试。

验收：

1. 新测试先红灯，能说明当前缺口。
2. 红灯原因是业务或视觉要求未满足，不是测试写错。
3. 不允许先改页面再补测试。

### Phase 4：image2 + Stitch 设计稿冻结

目标：先让目标图足够好，再进入代码。

任务：

1. 用 image2 重新生成工业蓝数据中枢目标图。
2. 用 Stitch 生成核心页面设计稿。
3. 每个设计稿必须标注真实数据区、空状态、加载状态、错误状态、权限状态。
4. 所有可见标题、按钮、表头、状态都使用中文。
5. 对比目标图和现有页面，列出差距清单。

验收：

1. `/manage/live` 达到调度大屏颗粒度。
2. `/manage/today` 达到日报总览颗粒度。
3. `/manage/production` 达到生产分析颗粒度。
4. 如果设计评分低于 9.7，重新 image2 + Stitch，不进入实现。

### Phase 5：视觉地基实现

目标：先统一底层视觉语言，不急着改页面业务。

任务：

1. 统一工业蓝 token、背景、边框、状态色、数字样式。
2. 统一卡片、表格、指标、筛选栏、状态条、事件流样式。
3. 保留轻量数字跳动和状态动效。
4. 移除或避免会拖慢页面的大面积光效。
5. 保证页面仍可读取真实接口。

验收：

1. `npm run test` 通过。
2. `npm run build` 通过。
3. 核心页面能打开，无白屏。
4. 没有新增重型依赖。

### Phase 6：三大核心页面实现

目标：先把用户最常看的页面做到可交付。

任务：

1. `/manage/live` 做成实时动态生产流转大屏。
2. `/manage/today` 同时显示 MES 主数据、人工填报对照、系统计算。
3. `/manage/production` 强化趋势、排行、来源对照、异常波动。
4. 全厂产量、包装产量、在制卷、能耗、缺报、异常都要有清晰来源。
5. 没数据时显示 0、空状态或未同步，不允许空白。

验收：

1. 三个页面浏览器打开无阻塞错误。
2. 控制台无新增错误。
3. 关键数字可追溯来源。
4. 页面视觉评分不低于 9.7。

### Phase 7：二级业务页面实现

目标：让查明细、查能耗、查异常、查卷级线索也统一。

任务：

1. `/manage/workshop-dashboard` 做成本车间生产看板。
2. `/manage/coils` 做成卷级线索页。
3. `/manage/fill-details` 做成人工填报审计台，不把 MES 原始记录混入填报明细。
4. `/manage/energy` 做成能耗仪表盘。
5. `/manage/alerts` 显示具体异常原因和处理状态。

验收：

1. 车间主任只看到本车间。
2. 卷级线索能看到随行卡、客户、合金、规格、工艺、当前工序。
3. 填报明细能查人物、时间、机列、字段、内容。
4. 异常页面能看到具体异常，不只是空提示。

### Phase 8：配置和手机端实现

目标：让后台配置清楚，现场使用顺手。

任务：

1. `/manage/admin/settings` 增加十二车间、别名、机列、PC/工艺映射的清晰入口。
2. `/manage/admin/users` 清理视觉展示上的重复角色口径，但不直接硬删生产账号。
3. `/entry`、`/entry/fill`、`/entry/history` 优化为手机现场模式。
4. 手机端 MES 参考值可带出，但字段不锁死，人工仍可修改。
5. 历史填报按整日查看。

验收：

1. 360px 宽度无横向溢出。
2. 按钮和输入框适合手指点击。
3. 主操、电工、内勤、车间主任流程可打开。
4. 配置页不会误导用户创建旧车间或重复角色。

### Phase 9：业务口径复核

目标：确认视觉优化没有改坏业务。

任务：

1. 复核产量、包装产量、全厂入库产量、成品率、废料、吨耗、能耗、合同量、在制卷。
2. 复核业务日、班次、日报、调度页、MES 同步的时间口径。
3. 复核 MES 数据与人工填报数据是否正确并列。
4. 复核十二车间是否覆盖所有核心页面。
5. 复核权限是否误显或误隐藏。

验收：

1. 无字段错接。
2. 无算法口径混用。
3. 无旧车间残留在核心页面。
4. 无权限越界。

目标：用测试和浏览器证据证明可以交付。

验收：

1. `npm run test` 通过。

## 11. 失败处理规则

| 失败情况 | 处理 |
| --- | --- |
| 页面不好看或和目标图差距明显 | 重新 image2 + Stitch，不靠零散 CSS 硬凑 |
| 页面好看但字段错 | 回到 Phase 2 和 Phase 3，先修映射测试 |
| MES 数据同步不通 | 页面显示未同步状态，不能伪造成正常 |
| 某车间无法匹配 | 进入未匹配线索，不得硬归属 |
| 手机端溢出 | 不进入下一阶段，先修 360px 布局 |
| 测试失败 | 不提交，不同步云端 |
| 线上验证失败 | 回滚前端构建，保留问题证据 |

## 12. 回滚方案

本计划默认不改生产数据库、不改后端核心算法，所以回滚以代码和构建产物为主。

回滚顺序：

1. 如果只是单页视觉问题，回退该页面改动。
2. 如果通用样式影响全站，回退视觉 token 和公共样式。
3. 如果字段映射错误，回退页面映射层并保留失败测试。
4. 如果线上阻塞，回滚到上一版前端构建产物。

回滚后必须验证：

```text
/manage/live
/manage/today
/manage/production
/entry
```
