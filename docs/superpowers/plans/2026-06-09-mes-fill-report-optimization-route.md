# 外部 MES 数据源与填报端字段搭配优化路线

日期：2026-06-09

## 一句话结论

最省事、最稳的路线是：外部 MES 数据源负责提供“已经发生的生产事实”，本机数据中枢负责做“口径加工、缺口提醒、人工修正和日报定稿”。

填报端不要再让人重复填写外部 MES 已经有的卷号、客户、合金、规格、当前工序、下道工序、入库重量、工序开始结束时间等字段。填报人员只补三类东西：外部 MES 没有的异常原因、能耗/气耗/成本类数据、以及外部 MES 与现场口径不一致时的修正说明。

## 哪些字段重复，应由外部 MES 自动带出

这些字段本机填报端不应再要求人工重复录入，默认自动带出并锁定；现场确实不一致时，只允许走“修正原因”：

| 填报端/本机字段 | 外部 MES 推荐来源 | 处理方式 |
| --- | --- | --- |
| 随行卡号、卷号 | `MES_Product.MaterialCode`，必要时关联 `Id`/`PID` | 扫码或搜索后自动识别 |
| 批号 | `MES_Product.PBatchNumber` / `BatchNumber` | 自动带出 |
| 合同号 | `MES_Product.ContractCode`，入库用 `WMS_InStockDetail.ContractCode` | 自动带出 |
| 客户 | `MES_Product.CustomerSimple` / `Customer` | 自动带出，优先级需业务确认 |
| 合金 | `MES_Product.Alloy` | 自动带出 |
| 规格 | `MES_Product.Specification`、`SpecThickness`、`SpecWidth`、`SpecLength` | 自动带出 |
| 当前车间/当前工序 | `MES_Product.CurrentWorkShop`、`CurrentProcess` | 自动带出，用于看板和缺报定位 |
| 下道车间/下道工序 | `MES_Product.NextWorkShop`、`NextProcess` | 自动带出，用于提醒 |
| 工艺路线 | `MES_Product.ProcessRoute` | 自动带出 |
| 机台/设备 | `MES_ProductProcessRecord.DeviceName`，辅以 `MES_Device` | 自动匹配本机机列 |
| 操作人员 | `MES_ProductProcessRecord.Worker` | 自动带出，班组归属仍需本机排班校验 |
| 上机/下机时间 | `MES_ProductProcessRecord.BeginDatetime`、`EndDatetime` | 自动计算 |
| 投入/产出重量 | `MES_ProductProcessRecord.BeginWeight`、`EndWeight` | 自动计算，注意 kg/吨单位 |
| 成品入库重量 | `WMS_InStockDetail.NetWeight` | 自动汇总，按 kg 转吨 |
| 在制分布 | `MES_Product.CurrentWorkShop + CurrentProcess + FeedingWeight` | 自动汇总 |

## 哪些字段仍需要本机填报或其他系统

这些字段本次在外部 MES 数据源里没有稳定来源，短期还不能取消人工或外部导入：

| 字段 | 原因 | 建议 |
| --- | --- | --- |
| 换辊、待料、换刀、故障等停机原因 | 工序记录里有 `Memo`，但不能稳定覆盖所有停机原因 | 填报端只保留“异常/停机原因与分钟数” |
| 电度、气量、吨电耗、吨气耗 | 外部 MES 表里没有明显 `kWh`、电、气字段 | 继续接能源 Excel/能源系统/专项补录 |
| 电费、气费、成本单价 | 属于财务/能源价格口径，不在外部 MES | 由本机成本配置或专项录入生成 |
| 回收车间产量、大修磨辊 | 不在本次核心 MES 表里 | 保留专项日报字段 |
| 班次归属 | 外部 MES 有时间和人员，但没有完整本机班次规则 | 本机按 7:30 业务日和班次规则归属 |
| 外加工标记 | 入库/合同字段可能有线索，但需要业务确认 | 先保留本机标记，后续对账后自动化 |
| 合同接单、总余合同量 | 外部有合同相关表，但还没完成口径验证 | 先用本机合同投影，后续接 `MES_Contract*` 对账 |

## 推荐的系统搭配

不要让填报端直接访问 SQL Server。推荐链路：

1. 外部 MES 数据源只读同步。
2. 写入本机 `mes_*` 投影表。
3. 再加工成本机“日汇总事实表”：入库、工序、在制、机列、合同、成品率。
4. 填报端读取本机数据，展示自动带出字段。
5. 填报人员只处理缺口、异常和修正。
6. 质量闸门检查缺报、差异、能耗缺失、单位异常。
7. 7:40 生成并推送固定日报文字。

这样做的好处是：外部 MES 网络抖动时，本机还有缓存；外部字段变动时，只改同步和映射层；填报端和日报模板不被外部库直接绑死。

## 7:40 日报自动化流程

建议每天按这个节奏跑：

| 时间 | 动作 | 目标 |
| --- | --- | --- |
| 06:50 | 同步外部 MES 卷材、工序、入库、在制、设备数据 | 提前把外部数据拉到本机 |
| 07:10 | 生成机列/车间预汇总 | 让缺口尽早暴露 |
| 07:20 | 生成缺报清单和异常清单 | 只催真正缺的内容 |
| 07:25 | 车间主任查看缺报 Excel/看板 | 明确谁缺、缺哪个班、缺哪个机台、缺哪个卷号 |
| 07:30 | 冻结上一个生产业务日 | 统一口径，不混自然日 |
| 07:35 | 生成全厂日报指标和车间日报指标 | 汇总产量、在制、入库、工序、能耗、合同、成品率 |
| 07:38 | 跑质量闸门 | 有缺口就列明，不把缺数当 0 |
| 07:40 | 生成老板日报和车间日报文本 | 推送定稿或带缺口的待确认稿 |

核心原则：7:40 必须先出“可用稿”。如果少数人工字段没补齐，系统不能整篇停摆，而是把缺口单独列出，让负责人补；可以自动取的生产事实先正常进入日报。

## 老板日报模板的数据来源

| 模板内容 | 推荐来源 |
| --- | --- |
| 全厂总产量日合计、月累计、比昨日升降 | `WMS_InStockDetail.NetWeight / 1000`，按本机 7:30 业务日汇总；月累计累加 |
| 外加工吨数 | 先保留本机标记，后续从合同/部门/客户规则对账 |
| 各车间日产量、月累计产量 | 外部工序记录 + 本机日报专项表；口径逐项确认 |
| 1650/1850/2050 道次 | `MES_ProductProcessRecord` 按机台、班次、人员计数 |
| 在制料 | `MES_Product` 中未入库、未出库且有当前车间/工序的卷材汇总 |
| 电量、气量、吨电耗、吨气耗 | 本机能源导入/专项补录 |
| 入库成品、寄存 | `WMS_InStockDetail` + 本机寄存规则 |
| 合同接单、总余合同量 | 本机合同投影，后续接 `MES_Contract*` 对账 |
| 成品率 | 入库净重 / 投料或工序投入，先和现有人工日报对账后固化 |
| 成本核算 | 能源费用 + 产量，来自本机成本/能源配置 |

## 车间日报模板的数据来源

以 1650/1850/2050 为例：

| 模板内容 | 推荐来源 |
| --- | --- |
| 白班/小夜/大夜人员 | `MES_ProductProcessRecord.Worker` + 本机排班表 |
| 轧了多少道 | `MES_ProductProcessRecord` 按机台、班次计数 |
| 用时多少分钟 | `BeginDatetime` 到 `EndDatetime` 汇总，需处理跨班和重叠 |
| 平均几分钟一道 | 用时 / 道次 |
| 换辊、待料、换刀 | 填报端异常/停机原因 |
| 日轧总道次 | 三班道次相加 |
| 本月单日最高 | 本机月度机列日汇总取最大 |
| 成品、中退、开坯 | 按工序/状态/下道工序规则从工序记录和卷材状态分类 |
| 日合计电度、月累计电度 | 本机能源导入 |
| 日电耗、月电耗 | 电度 / 对应成品吨数 |

## 填报端改造方向

1. 扫码/输入随行卡后，自动带出卷号、客户、合金、规格、当前工序、下道工序、机台建议。
2. 自动字段默认只读，旁边显示来源是“外部 MES 数据源”。
3. 人工只填：停机原因、停机分钟、异常说明、能耗补充、现场修正原因。
4. 缺报列表从“谁没填表”升级为“哪个车间、哪个班次、哪个机台、哪个卷号缺了哪一项”。
5. 对“外部 MES 抓到了，但本机机列没填”的数据，自动进入缺报 Excel 和车间看板。
6. 班组长没有及时填时，系统先使用外部 MES 自动值生成预稿，同时标记“待人工确认”。

## 实施阶段

### 阶段 1：字段口径固化

- 固化 `SQL Server 字段 -> 本机 mes_* 投影 -> 日报指标` 映射。
- 明确 kg/吨换算，特别是 `WMS_InStockDetail.NetWeight`。
- 外部 SQL 查询避免中文等值过滤，中文部门和工序映射放到本机。
- 对 `1650冷轧（WAN）` 出现在 `2050车间` 这类情况做机台映射校验。

验收：
- 近 7 个已完成业务日，入库吨数与人工日报差异在可解释范围内。
- 随行卡、合金、规格、当前工序自动带出准确率不低于 99%。

### 阶段 2：本机日汇总事实表

- 从 `mes_stock_records` 或外部入库明细生成“包装入库日汇总”。
- 从 `mes_workshop_process_records` 生成“机列/班次/人员/道次/重量/用时日汇总”。
- 从 `mes_coil_snapshots` 生成“在制料日快照”。

验收：
- 老板日报需要的产量、月累计、在制、道次能由本机自动生成。
- 外部同步失败时，日报显示“使用缓存/数据滞后”，不能把缺失当 0。

### 阶段 3：填报端瘦身

- 把重复字段改成自动带出。
- 只保留外部 MES 没有的异常、能耗、修正、成本专项。
- 缺报 Excel 细化到车间、班次、机台、人员、时间、卷号、缺字段。

验收：
- 填报人员每天主要处理异常，不再重复录卷材基础信息。
- 车间主任能一眼看出“谁缺、缺什么、影响哪段日报”。

### 阶段 4：日报模板生成器

- 新增老板日报长文本模板。
- 新增 1650/1850/2050 等车间日报模板。
- 模板只从本机汇总表取数，不直接查外部 SQL Server。

验收：
- 每天 07:40 自动生成你给出的那种完整文字结构。
- 缺字段时保留模板结构，并在质量闸门里列出缺口，不静默填 0。

### 阶段 5：影子运行和切换

- 连续 7 个业务日同时保留人工日报和自动日报。
- 每天对比总产量、车间产量、入库、道次、在制、能耗、成品率。
- 对账稳定后，把自动日报设为主用，人工改为复核和补异常。

验收：
- 7 个业务日内无 P0/P1 数据事故。
- 总产量、入库、重点车间道次差异都能解释。
- 07:40 能稳定出稿。

## QA 验收清单

- SQL Server 只读账号不能写入、删除、建表、改表。
- 密码不进入代码、文档、日志和提交记录。
- 所有 SQL Server 查询只允许白名单 `SELECT`。
- 业务日统一按 7:30 切分，不混自然日。
- kg/吨字段必须有自动单位检查，超大值要报警。
- 中文部门名不直接作为 SQL Server 硬过滤条件。
- 外部同步失败时显示缓存状态，不返回假 0。
- 缺报 Excel 必须包含车间、班次、机台、缺报人员、缺报时间、对应卷号、缺失字段、外部 MES 是否已有数据。
- 车间日报的道次、人员、用时、重量至少抽样 7 天人工核对。
- 老板日报最终推送前必须经过质量闸门。

## 当前最推荐的下一步

先做“字段自动带出 + 缺口清单”，再做完整日报模板。

原因很简单：只要填报端先少填、缺口先准，7:40 日报的数据底座就会稳定；否则直接做漂亮长模板，最后还是会被缺报、口径不一致和能耗缺失卡住。
