# 阶段七施工报告：指定人员补产量与发布日报

## 目标

阶段七解决两个动作的安全闭环：

- 指定人员可以发起“补产量”请求，但不直接修改 MES 原始数据，也不直接改核心产量表。
- 指定人员可以发布日报，但必须先生成预览、再二次确认、再执行发布。

## 本阶段改动

- 新增 `agent_designated_operation_service`，作为阶段七的唯一入口。
- 补产量执行后只写入 `agent_events` 的人工纠偏事件，状态为 `pending_manual_apply`。
- 日报发布复用现有钉钉日报发送服务。
- 日报发布前记录正文哈希；如果确认后日报正文被改动，发布会被拒绝。
- 通讯治理概览补充 `actual_write` 和 `execution_status`，方便确认操作是否真实执行。
- 管理端通讯治理页显示“未执行、等待执行、演练完成、真实执行”等执行状态。

## 安全边界

- 不修改 MES 原始表。
- 不直接改核心产量表。
- 不绕过二次确认。
- 不允许非白名单人员发起、确认、执行。
- 日报正文预览后发生变化时，不允许继续发布。

## 五视角评分

- CEO 视角：9.8。补产量和发日报进入可控流程，不再靠口头确认。
- 工程师视角：9.8。新增独立服务，复用原审批能力，改动边界清楚。
- 设计师视角：9.7。管理端增加执行状态，信息更明确，没有扩大页面复杂度。
- 安全视角：9.8。白名单、预览、二次确认、哈希校验、留痕齐全。
- 真实用户视角：9.8。指定人员可以做事，但每一步都能追溯，降低误操作风险。

## 结论

阶段七已达到进入回归测试的标准。当前实现是安全优先版本：补产量先进入人工纠偏队列，不直接改变生产主数据；日报发布可以真实执行，但必须通过预览和确认。
