# Production Readiness Closed Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将鑫泰铝业数据中枢和 NousResearch Hermes 从“基础服务可运行”推进到“真实事实、日报、智能体、恢复和发布门禁全部可重复通过”。

**Architecture:** 保持两个独立系统边界：数据中枢负责事实、填报、投影、日报、任务和审计；Hermes 负责钉钉接入、推理、工具和统一回复调度。所有阶段通过一个结构化生产就绪门禁汇总，但每个阶段拥有独立的小计划、测试、生产证据和回滚点。

**Tech Stack:** Python、FastAPI、SQLAlchemy、PostgreSQL、SQL Server 只读适配器、Vue、Node test runner、Playwright、NousResearch Hermes、钉钉 Stream、systemd、Nginx、GitHub Actions。

---

## 每阶段固定闭环

每个阶段必须严格执行以下顺序：

- [ ] 读取当前分支、HEAD、未提交改动、相关历史计划和生产状态。
- [ ] 归档阶段开始时的真实失败证据，不用旧报告代替当前事实。
- [ ] 在最高可用接缝编写能够复现问题的失败测试或失败门禁。
- [ ] 运行失败测试，确认失败原因与阶段目标一致。
- [ ] 完成能够通过该测试的最小修改，不增加无关页面、服务或抽象。
- [ ] 运行阶段聚焦测试、相邻回归测试、语法检查和构建。
- [ ] 在生产或等价真实环境执行阶段验收，并保存机器可读与小白可读产物。
- [ ] 由独立评审者执行规格符合性评审，发现问题后修复并重新评审。
- [ ] 规格通过后由另一独立评审者执行代码质量评审，发现问题后修复并重新评审。
- [ ] 验证回滚步骤、幂等性和失败恢复，不以“理论上可回滚”代替演练。
- [ ] 更新阶段报告和本计划状态，只记录真实执行过的证据。
- [ ] 创建单一职责提交，推送分支并保持主分支可恢复。
- [ ] 阶段门禁全部通过后才进入下一阶段。

### Phase 1: 安全前置与真实钉钉证据入库

**Blocked by:** Phase 0

- [x] 执行仓库、Git 历史、构建包和普通日志密钥扫描，并在任何生产配置变更前建立可恢复数据库备份。
- [x] 验证真实文本、模糊文本、图片、Excel 和 PDF 事件。
- [x] 验证 receipt、chat inbox、multimodal evidence、文件文本、哈希和 trace。
- [x] 验证重放幂等、未知表达保留和断线重试。
- [x] 验证企业内部应用授权范围内的消息不会被硬群 allowlist 或硬识别规则拒收。

**Exit gate:** 新凭据生效且旧凭据失效，密钥扫描无未处置泄露，生产变更前备份可读取；至少 10 条文本和 5 个文件全部持久化并可追溯；重复事件不重复入库；企业内部应用授权范围内不存在硬群或硬关键词丢弃；消息必须先持久化和建立 trace，再决定是否提取事实或回复。

### Phase 2: 事实优先级与字段口径合同

**Blocked by:** Phase 1

- [x] 固化 127 个日报字段的单位、业务时间、来源和字段级容差。
- [x] 固化标准生产 07:50、铸二/铸三/热轧 10:00、责任人每日一录 09:30 和 10:00 迟报截止的现行时间合同。
- [x] 固化分母规则：只有明确 N/A 字段可以扣除；答案钥匙未写且未声明 N/A 的字段必须标为 `reference_absent` 并阻塞门禁。
- [x] 同时输出答案钥匙已出现字段匹配率和 127 字段规范覆盖率。
- [x] 固化钉钉、授权纠错、MES/WMS、扫码补录、投影、历史和 RAG 的合同。
- [x] 建立合同测试和文档一致性检查。

**Exit gate:** 每个字段都有唯一口径；每天的分母变化均能逐字段解释；实时数字不能由 RAG、历史答案或答案钥匙生成；任何绝对容差不超过 20。

**Evidence:** [Phase 2 事实合同生产闭环报告](../reports/2026-07-18-phase2-fact-contract-closure.md)，合并 [PR #50](https://github.com/zhangzhaojia6-boop/xt-aluminnum/pull/50)，首次生产部署 [#29636674363](https://github.com/zhangzhaojia6-boop/xt-aluminnum/actions/runs/29636674363)，真实回滚 [#29637081280](https://github.com/zhangzhaojia6-boop/xt-aluminnum/actions/runs/29637081280)，重新部署 [#29637188407](https://github.com/zhangzhaojia6-boop/xt-aluminnum/actions/runs/29637188407)，最终只读状态 [#29637297416](https://github.com/zhangzhaojia6-boop/xt-aluminnum/actions/runs/29637297416)。三日业务匹配率仍低于 90%，按计划保留给 Phase 3/4，不把合同闭环写成业务对齐完成。

## 失败处理规则

- 阶段真实环境门禁失败时，状态保持 in progress，不用单元测试通过覆盖失败事实。
- 外部凭据、真实钉钉消息或七个自然业务日属于外部时钟，不伪造完成状态。
- 可继续完成不依赖外部时钟的自动化、修复、评审和准备工作，但最终阶段状态保持未通过。
- 同一阻塞连续出现三次且无法继续推进时，记录精确阻塞证据和所需最小外部动作。

## 提交规则

- 每个阶段至少一个独立提交，提交只包含该阶段直接需要的改动。
- 每个阶段完成后推送功能分支并保存 GitHub Actions 或生产验收链接。
- 所有阶段完成后再进行最终分支评审、合并和生产同步。
