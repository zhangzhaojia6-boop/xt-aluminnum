# 物资采购管理后台方案

日期：2026-11-08

状态：已自审，执行中

依据：《物资采购管理办法》第十六、十八、十九、二十条，《物资采购全流程线上化实施方案》第一、七节。

## 1. 要解决什么

办单页面已经有了，但管理的人还缺东西：

| 谁 | 要做什么 | 依据 | 现在 |
|---|---|---|---|
| 分管领导、总经理 | 看进度、看花了多少钱、看卡在哪 | 方案「采购进度全部实时可见」 | 只有环节条形图和总数 |
| 企管 | 每月抽查，紧急采购单独台账 | 办法第十六、二十条 | 台账不能筛选，不能导出 |
| 财务 | 查单据和付款 | 方案「审批全部留痕可查」 | 只能逐张点开 |
| 采购科负责人 | 维护合格供应商和黑名单 | 办法第十九条 | 没有 |
| 管理员 | 指派办理人，知道开放前还缺谁 | 方案第八节 | 只能指派，看不出缺口 |
| 采购科负责人、管理员 | 作废走错的单子 | 留痕要求 | 只有草稿能撤销 |

## 2. 范围

页面都放在 `/procurement` 下，用同一个外壳：

| 页面 | 路径 | 内容 |
|---|---|---|
| 总览 | `/procurement/board` | 在办、超时、紧急、本月付款；各环节在办；各环节平均耗时；本月按类别金额；供应商前 10；超时清单；疑似拆单；紧急超期未补 |
| 台账 | `/procurement/ledger` | 按状态、环节、类别、紧急、超时、供应商、关键字、日期筛选；分页；合计金额；导出 CSV；紧急台账用同一页预设筛选 |
| 单据详情 | `/procurement/:id` | 沿用现有页面，补作废入口 |
| 供应商 | `/procurement/suppliers` | 名单、合格或黑名单状态、报价次数、中标次数、累计金额；新增和修改 |
| 办理人 | `/procurement/staff` | 各岗位人员，缺人提醒，指派和移除 |

后端新增 `procurement_suppliers` 表（迁移 0059），新增台账、导出、供应商、作废接口。开关关闭时管理员仍能进后台配办理人和供应商，其他人照旧 404。

### 不放进 `/manage` 的原因

采购专用账号进不了管理端，也调不了管理端的其他接口，而财务、采购科都用这种账号。放在采购区，所有人同一个入口，手机和电脑都能用。管理端抽屉的入口继续跳转过来。

### 不做

每日推送清单和超时催办（要真实外发）、智能助手、合同模板、供应商资质附件和评分表、库存系统对接、多物料明细。

## 3. 规则

- **能看全部：** 管理员、企管、财务部、总经理、分管领导、采购科负责人、采购经办人、法务。
- **收紧：** 门岗、仓库、质检、设备部、会计只能看当前归自己办的单和办过的单，加上提报人和本车间主任。这是对现有规则的收紧。
- **供应商：** 采购科负责人和管理员能改。选定黑名单供应商不能提交比价，也不能申请豁免。名称去空格、不分大小写比对。第一次报价自动入库，状态为待评价，只有黑名单才拦。
- **作废：** 采购科负责人和管理员能作废，必须写理由，写入办理记录。已进入付款入账的不能作废。
- **导出：** 能看全部的人才能导出。单元格以 `= + - @` 开头的要转义，防止表格软件当公式执行。
- **留痕：** 改供应商、指派写审计日志。

## 4. 验收

- 权限矩阵有测试：门岗看不到别人的单和台账，企管能看全部但不能办。
- 台账筛选、分页、合计、导出有测试，公式转义有测试。
- 黑名单拦截、作废规则有测试。
- 真实后端：管理员配岗位、采购科拉黑、企管筛选和导出，浏览器走通。
- 桌面和手机截图过目，无横向溢出。

## 6. 自审发现

写方案时查到并已写进上面：

1. 现有 `can_view_all` 让所有岗位都能看全部台账和金额。已改为白名单，同时 `can_view` 要放行当前办理人和办过的人，否则门岗打不开自己要办的单。
2. CSV 导出存在公式注入风险，供应商名是自由文本。
3. 黑名单若靠完全相等比对，加个空格就能绕过。先做规范化比对；错别字绕不过去，留给采购科负责人审比价时把关。
4. 超时是算出来的，不能在数据库筛选。台账按筛选条件取全量后在内存判断再分页。当前规模（每年几千单）可以接受，单量大了要存字段。
5. 平均耗时用办理记录相邻时间相减，退回重办会多算，标题就叫「平均耗时」，不当考核依据。
